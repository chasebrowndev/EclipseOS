# T-00 — Apotheosis Master (Draft v0.2)

## 1. Goals
1. A terminal that is **correct** (conformance measured, not claimed), **fast** (named
   budgets against measured peers, T-23), and **safe against its own input** (T-18).
2. **The union of the best control surfaces** of existing terminals — everything a user
   can do in kitty, wezterm, foot, ghostty, alacritty, contour, rio, iTerm2, Windows
   Terminal, Konsole or tmux has a declarative equivalent here — without an embedded
   scripting language.
3. **Images and video as first-class content**: kitty graphics, sixel, and native media
   placements with audio.
4. **Seamless on EclipseOS**: Abyss theme, real glass, semantic publishing, sensitivity,
   every setting in the master settings GUI. Complete and unprivileged on any other
   Wayland compositor.
5. **One language**: our source is Rust; configuration is KDL (§3).

## 2. Non-goals
X11, macOS, Windows. An embedded scripting runtime (Lua, Python, WASM; ADR 0122). A
plugin ABI. Cloud accounts, telemetry, AI features. An in-process ssh implementation.
A web or mobile client. Tearing presentation by default. Bitmap-font-only rendering
paths beyond what the font stack gives for free.

## 3. Rules

### 3.1 Language rule (ADR 0110)
- Every source file we write is Rust, except the data assets of §3.3.
- No C-family source (C, C++, Objective-C, or assembly driven through a C compiler) is
  compiled by our build, in our crates or in any dependency's build script; no code is
  emitted by bindgen at build time. FFI bindings we need are generated by a dev-only
  xtask and committed.
- The system linker driver is not "C compiled by our build".
- **Two standing exceptions.** (1) (ADR 0118) `nasm` assembles `rav1d`'s x86-64 routines
  inside the media helper crate when the `av1-asm` feature is on (packaging only). `nasm`
  is a `makedepends`; nothing of it is needed at run time. (2) The non-shipping workspace
  `apotheosis/fuzz/` may build libfuzzer-sys's C++ runtime in a build script and uses a
  dated nightly pinned in its own `rust-toolchain.toml`; it is never a dependency of a
  shipping crate and `lang-rule.sh` skips it entirely (T-18 §11, ADR 0110).
- Enforcement is mechanical (T-24 §3), not by review.

### 3.2 System libraries (allow-list)
A shipped binary may link or load only (objects the Vulkan loader or libva load on behalf of
the installed driver, and their dependencies, count as "the installed driver"):

| Library | Used by | How |
|---|---|---|
| glibc, libgcc_s (Rust runtime baseline) | all | linked |
| `libwayland-client` | `apotheosis` | linked (required by Vulkan WSI) |
| Vulkan loader and the installed driver | `apotheosis` | loaded at run time |
| `libxkbcommon` | `apotheosis` | only under the `xkbcommon` cargo feature (off by default; the default keyboard backend is pure Rust, ADR 0125) |
| `libva`, `libva-drm` | `apoth-media-helper` | loaded at run time (`libloading`, never a `DT_NEEDED` entry) when hardware decode is used |

Audio uses no library: a pure-Rust client speaks the PulseAudio native protocol to the
`pipewire-pulse` socket. Adding a library to this table needs an ADR.

### 3.3 Data assets
The only non-Rust, non-KDL *source* we author: shell-integration snippets for bash, zsh
and fish (each ≤ 8 KiB, embedded with `include_str!`, reviewed like code), WGSL shaders,
and terminfo text generated from the Rust table. Test fixtures and Markdown are not
source.

### 3.4 Prior art (ADR 0112)
We study *how* other terminals solve a problem and write our own solution.
- Allowed: reading prior-art source and documentation to understand an approach, a data
  structure, a protocol behaviour or an edge case; citing it in `PRIOR-ART.md`.
- Not allowed: copying, translating or line-by-line paraphrasing functions, tables or
  tests; keeping foreign source open while writing the corresponding code.
- **Procedure**: implementing agents do not open prior-art source. They ask the
  `apoth-prior-art` agent a question; it answers in prose (approach, invariants, edge
  cases, pitfalls — no code, no identifiers beyond public protocol names) and appends
  the lookup to `docs/internal/apotheosis/PRIOR-ART.md` (date, question, sources read,
  licence of each). The implementer writes from that description and this volume.
- Protocols are implemented from their **published specifications**; where the only
  reference is GPL source (kitty), the specification text and black-box behaviour are the
  inputs, and that project's source is not consulted for the crate in question
  (T-15 §1 names the graphics crate explicitly).
- Generated Unicode tables come from the Unicode Character Database files, not from
  another project's tables.

### 3.5 Licences
System crates AGPL-3.0-only; vocabulary and protocol crates Apache-2.0 (the crate map
marks each). Every source file carries its SPDX header. Dependencies must pass
`cargo deny` under T-24 §4.

### 3.6 Root invariants carried over
From the repository root, unchanged in force here: human input is never logged by
content; `password`-role values are never delivered, logged or stored; app-declared
sensitivity only raises; policy is fail-closed (an unreachable policy service is a
deny, T-12 §4); specs and code disagreeing is a bug in one of them.
Apotheosis is **not TCB**. The TCB-adjacent changes it causes elsewhere (policy data,
P-04 credential signal) are separate, owner-reviewed PRs.

### 3.7 Settings rule
Every option exists in exactly one schema table (T-10 §1) and is editable in
ec-settings, by `apoth config`, and by hand. A PR that adds an option without its GUI
control fails the coverage test.

### 4.2 Threads
| Thread | Owns | Never does |
|---|---|---|
| main (calloop) | Wayland connection, input encoding, **every PTY write** (keys, paste, replies) through the per-pane outbound queue, UI model, `Session`, dispatcher, config, control socket | block on GPU, disk, D-Bus or a PTY write; take a pane's term lock on the input path |
| io, one per pane | PTY read, `apoth-vt` + `apoth-term` mutation under the pane's term lock, publishing the pane's `InputModes` mirror, producing replies into the pane's reply queue | touch Wayland or wgpu; write the PTY; decode images |
| render, one per window | snapshot dirty rows (short lock), build and submit frames, atlas uploads | parse; hold the term lock while building |
| workers (2–3) | glyph raster, image decode, compression, search, D-Bus calls, file I/O | own state; results return by channel |
| a11y adapter | AT-SPI transport (only when activated) | read grids directly |
| publisher, per pane on Abyss | `ec-term-pub` | — |

One process per instance; many windows (ADR 0120). The media helper is a separate
sandboxed process per playing placement (T-16 §4).

Input path rule: **main never takes a term lock on the input path.** Key, mouse and paste
encoders read only the pane's lock-free `InputModes` mirror (T-03 §2): an `AtomicU64`
mode bitfield (DECCKM, DECKPAM, mode 1036, bracketed paste, mouse-tracking and encoding
modes, focus reporting) plus the active kitty keyboard flags word, stored by the io thread
with `Release` ordering immediately after each mode-changing sequence and loaded by main
with `Acquire`.

Single PTY writer: main is the only thread that writes a pane's PTY master, which is
`O_NONBLOCK`. Each pane has one bounded FIFO outbound queue of *units* (a reply, a key's
bytes, a whole paste including its bracket wrapper); a unit is written completely before
the next unit starts, so a reply or key never lands inside another unit. Main writes on
the event when the queue is empty and otherwise drains on `POLLOUT`. The io thread pushes
replies into the pane's reply queue (T-18 §5) and pings main; main moves them into the
outbound queue in arrival order. Queue bound: 1 MiB plus the paste in flight; overflow
drops the new unit and counts it (counter only, never content).

### 4.3 Data flow
Key → main: bind lookup → (Action) or encoder (reading `InputModes`) → outbound queue →
`write(pty)` immediately when the queue is empty.
PTY bytes → io: parse → grid mutation → dirty rows + events. Wakeups are edge-triggered
and coalesced (T-07 §1): render is notified only on the pane's clean→dirty transition
(atomic flag, one notify); events go to a fixed-capacity per-pane event slot (latest-wins
for title, cwd and progress; a bell counter; a bounded queue for marks and notifications
that drops and counts on overflow) and main is pinged at most once per drain. Title and
notification bytes use per-pane buffers preallocated at their T-18 §5 caps.
Render: on wake or frame deadline, snapshot → build → submit → present; frame pacing by the scheduler (T-07 §2), never by blocking in `present`. Presenter: the wgpu
surface only (ADR 0119).

# T-01 — VT Parser (Draft v0.2)

Crate: `apoth-vt` (Apache-2.0, no dependencies beyond `memchr` and `simdutf8`). Not TCB.
Implements matrix rows VTCORE-11..13, -54..-60, UNICODE-01, PERFORMANCE-10..13, -77..-80,
GRAPHICS-39..40.

## 1. Scope

`apoth-vt` turns a byte stream into a stream of typed actions. It knows the *syntax* of
ECMA-48 / DEC control functions and nothing about their meaning: no grid, no modes, no
clock, no allocation after construction. Everything semantic is T-03.

We own this parser (ADR 0111). `vte`'s `Perform` has no APC/SOS/PM delivery and only
per-byte DCS `put`; the kitty graphics protocol is APC and sixel is a multi-megabyte DCS.
`vte` is a dev-dependency differential oracle only (§6).

## 2. State machine

### 2.1 States
The Williams DEC-compatible machine: `Ground`, `Escape`, `EscapeIntermediate`, `CsiEntry`,
`CsiParam`, `CsiIntermediate`, `CsiIgnore`, `DcsEntry`, `DcsParam`, `DcsIntermediate`,
`DcsPassthrough`, `DcsIgnore`, `OscString`, `ApcString`, `PmString`, `SosString`. The
`[state][byte-class] → (action, next state)` table is generated by `const` evaluation and
is the single source of transitions; a unit test renders it and diffs it against a
checked-in text table so any transition change is a reviewed diff.

### 2.2 Character encoding
- Input is UTF-8, always. There is no 8-bit or Latin-1 mode.
- Bytes 0x80–0x9F are never C1 controls. Only the 7-bit `ESC Fe` forms introduce
  sequences. A UTF-8-encoded U+0080..U+009F is data, passed to T-03, which discards it.
  `S8C1T`/`DECSCL` 8-bit requests are parsed and ignored by T-03; replies are always 7-bit.
  (Resolves VTCORE-13 against VTCORE-60: the optional 8-bit mode is not built.)
- Malformed UTF-8 yields U+FFFD by the maximal-subpart rule (Unicode §3.9, Table 3-7).
  The scalar decoder and the bulk fast path must agree byte for byte (§6, fuzz parity).
- A partial code point at the end of a chunk is carried (≤ 3 bytes) to the next call.
- `CAN`, `SUB` abort any sequence; `ESC` inside a sequence restarts it; C0 controls inside
  CSI/ESC execute immediately, as on a VT.

### 2.3 Parameters
- Up to 64 parameters per CSI/DCS, each `u32`, saturating. Excess parameters set an
  `overflow` flag on the dispatched action; the first 64 are still delivered.
- A 64-bit `colon` bitset records, per parameter, whether the separator *after* it was
  `:`; sub-parameter grouping is T-03's job. Empty parameters are distinguishable from 0.
- Up to 4 intermediate bytes and one private marker (`<=>?`); more ⇒ `CsiIgnore`.

## 3. Output interface

```
pub trait Sink {
    fn print_run(&mut self, text: &str);            // ≥1 printable scalar, no C0/DEL
    fn execute(&mut self, c0: u8);
    fn esc(&mut self, inter: &[u8], fin: u8);
    fn csi(&mut self, p: &Params, inter: &[u8], private: u8, fin: u8);
    fn string_start(&mut self, kind: StrKind, head: &StrHead) -> StrRoute;
    fn string_put(&mut self, chunk: &[u8]);
    fn string_end(&mut self, end: StrEnd);          // St | Bel | Aborted | OverCap | Rejected
}
```
`Parser::advance(&mut self, bytes: &[u8], sink: &mut impl Sink)` is the only entry point.
It is monomorphised over the sink: no dynamic dispatch per byte (PERFORMANCE-84 rejected).

### 3.1 Streaming strings
OSC, DCS, APC, PM and SOS are streamed; the parser buffers nothing beyond the 32-byte head.
- `string_start` receives the kind and a *head*, buffered by the parser in a fixed
  `[u8; 32]` before the call so the route can be chosen from it:
  | Kind | Head |
  |---|---|
  | OSC | numeric command, plus the selector bytes after its `;` up to the next `;`, `=` or `:` (≤ 32 bytes total); e.g. `1337` + `File`, `9` + `4` |
  | DCS | private marker (`<=>?` or 0), parameters, intermediates, final byte |
  | APC | first byte |

  A string that terminates or is aborted before the head is complete calls `string_start`
  with the partial head, then `string_end`. A head longer than 32 bytes is truncated; the
  sink routes on the truncated head (unknown ⇒ cap 0).
- The sink answers with a `StrRoute { cap: u32 }`: the maximum payload bytes it will accept.
  `cap = 0` routes the string to a zero-memory skip state (unknown protocols, PM, SOS).
- Payload arrives as `string_put` slices that borrow from the input; the terminator scan
  is vectorised. When `cap` is exceeded the parser calls `string_end(StrEnd::OverCap)`, skips to the
  terminator and returns to `Ground`. A string is terminated by `ST` (`ESC \`), and for
  OSC also by `BEL`; the terminator used (`StrEnd::St` or `StrEnd::Bel`) is reported in `string_end` so replies can mirror
  it (VTCORE-26).
- The head is a copy for routing only. Payload `string_put` slices carry everything after
  the OSC command's `;` (DCS: after the final byte; APC: from the first byte), selector
  bytes included, and count against `cap`; when the head spanned a chunk boundary the
  first `string_put` borrows from the parser's head buffer instead of the input.
- Caps are owned by T-03/T-15/T-18, not here. The parser enforces whatever it is given.

### 3.2 Ground fast path
In `Ground`, scan for the next byte < 0x20 or 0x7F with a SWAR/`memchr`-class scan,
validate the run with `simdutf8`, and emit one `print_run` for it. `LF`, `CR`, `TAB`, `BS`
are executed inline without leaving the scan loop. Throughput budget: T-23 `THR-ASCII`.

## 4. Limits (all compile-time constants, listed in one module)
64 params · u32 saturating · 4 intermediates · 32-byte string head · 3-byte UTF-8 carry · no heap. A hostile
stream can make the parser consume input; it cannot make it allocate, recurse or panic.

## 5. Determinism
`advance` is a pure function of (parser state, bytes). Splitting any input at any byte
boundary yields the identical action stream. T-21's mirror mode depends on this.

## 6. Test Plan
- Table snapshot test (§2.1). Transition unit tests per state.
- **Chunk-invariance property test** (VTCORE-55): for random and corpus inputs, every split
  point produces the same recorded actions.
- **Fuzz** (`cargo-fuzz`, target `vt_advance`): no panic, no allocation (counting
  allocator), bounded time per byte. 10 CPU-minutes per PR touching the crate; nightly 1 h.
- **Fast/slow parity fuzz**: bulk path vs a byte-at-a-time reference decoder.
- **Differential** against `vte` on 7-bit streams without APC/SOS/PM (VTCORE-56); the
  divergence list is a reviewed file.
- Bench: `THR-ASCII`, `THR-DENSE`, `THR-CSI` corpora (T-23).

# T-02 — Grid & Scrollback (Draft v0.2)

Crate: `apoth-grid` (AGPL-3.0-only; deps: `apoth-unicode`, `lz4_flex`). Not TCB.
Implements VTCORE-02..08, SCROLLBACKSEARCH-01..04, -21..-26, UNICODE-07, PERFORMANCE-36,
SHELLINTEGRATION-03..04.

## 1. Model

A `Screen` is an ordered list of **pages**. The last rows of the list are the *active
area* (`rows × cols`); everything before is *history*. The primary screen has history; the
alternate screen is a single fixed page set with none.

Resolves VTCORE-06 (ring) against SCROLLBACKSEARCH-01 (pages): pages win. A full-screen
scroll appends a row to the tail page (or opens a new page) and moves the active-area pin;
no cell is copied. Region scrolls inside the active area rotate row handles within a page
and copy only across a page seam.

### 1.1 Page
A page is one contiguous, zeroed, demand-paged allocation from a pool (standard size
512 KiB; oversize pages allowed for very wide grids). It contains, at fixed offsets:
row headers, cells, a style table, a grapheme arena, a hyperlink table and a string arena.
**Every internal reference is a page-local offset or index, never a pointer**, so a page
can be moved, compressed, serialised or sent to another process as bytes.

### 1.2 Cell (8 bytes)
```
bits  0..20  code point, or arena index when tag = Cluster
bits 21..22  tag: Empty | Scalar | Cluster | BgOnly
bits 23..24  wide: Narrow | Wide | SpacerTail | SpacerHead
bit  25      protected (DECSCA)
bit  26      hyperlink present
bits 27..28  semantic: Output | Input | Prompt
bit  29      multicell member (OSC 66; geometry in the row's multicell list)
bits 30..31  reserved
bits 32..47  style id (0 = default)
bits 48..63  BgOnly: packed colour; otherwise reserved for kitty placeholder decode cache
```
`BgOnly` cells carry a palette or RGB background without touching the style table
(VTCORE-03). The multicell bit is reserved now so OSC 66 (T-04 §5) does not need a cell
format change.

### 1.3 Row header
Offset of the row's cells, flags (`wrapped`, `wrap_continuation`, `has_cluster`,
`has_style`, `has_link`, `has_multicell`, `prompt_start`, `dirty`), an occupancy
high-water column, a `u32` block id (T-14) and a `u64` change sequence number (T-21,
§5). The sequence number is taken from one per-screen monotonic counter on every mutation
of the row's content, style or flags (other than `dirty`); it never decreases, including
across reflow, which assigns fresh numbers to every row it rewrites.
Flags may be false-positive, never false-negative; erase and reset take fast paths on
unflagged rows.

### 1.4 Interning
- **Styles**: per-page, ref-counted, open-addressed; ids are item indices. A full table
  triggers page capacity growth (copy into a larger page), never style loss.
- **Clusters**: page-local arena in 4-code-point chunks, 64 code points max per cluster.
- **Hyperlinks**: per-page table of `(id, uri)` with ref-counts; URI ≤ 2083 bytes,
  id ≤ 250 bytes. (Replaces the global bitmap GC of VTCORE-29: page lifetime is the GC.)

## 2. Pins
A pin is `(page serial, row, col)`. Viewport top, cursor, saved cursors, selection ends,
search matches, prompt/block marks, image placements and bookmarks are *tracked pins*
registered with the screen. Every operation that moves rows (reflow, page split,
eviction, compression) updates tracked pins; a pin whose row is evicted becomes
`Garbage` and its owner is notified. No component stores raw row indices across calls.

## 3. Operations
- Print (bulk `print_run` into contiguous cells by width class), all erase/insert/delete
  forms, region scroll, tab stops, wide-char seam repair in O(1) (VTCORE-08).
- **Reflow** on column change (primary screen only): logical lines (soft-wrapped runs) are
  re-wrapped; pins, block ids, semantic bits, hyperlinks and placements are carried. Rows
  the shell will redraw (the live prompt, from the T-14 block state) are not re-wrapped
  (SHELLINTEGRATION-10). Per-profile `scrollback.reflow #false` truncates.
  - *Synchronous part*: the active area and the viewport (plus the logical lines that
    cross into them) are reflowed by the io thread under the term lock before the resize
    is acknowledged; budget T-23 `RESIZE`.
  - *Lazy part*: every history page carries a `wrap_width` tag. Pages whose tag differs
    from the current width are re-wrapped in slices of ≤ 1 page or 200 µs by the io thread
    when it is otherwise idle, releasing the term lock between slices (T-07 §1), or on
    demand when read. Logical lines that span a page seam are converted together.
  - Tracked pins in an unconverted page stay in that page's coordinates (page serial,
    row, col at its tagged width) and are rewritten when the page is converted.
  - Search, selection extraction, the logical-line iterator, the a11y text model, scroll
    to a row index and serialisation convert a page before reading it. Row counts above an
    unconverted page are estimates until it is converted; the scrollbar may move by the
    difference.
  - A further resize retargets unconverted pages: each is re-wrapped once, from its tagged
    width directly to the newest width; pages already converted re-enter the lazy set.
- **Interactive resize** (PERFORMANCE-23): while the toplevel is being dragged the grid is
  cheaply truncated/padded; the real reflow and the `TIOCSWINSZ` happen after 25 ms idle or
  on the final configure.
- Selection geometry: cell, word, line, block, semantic-zone selections as pin pairs with
  left/right cell sides (NAVIGATION-12). Text extraction joins wrapped rows, trims per
  config, and yields clusters.
- Logical-line iterator with a byte-offset → pin map, for search and hints (T-14).

## 4. Scrollback limits
- Two limits, whichever hits first: `scrollback.bytes` (default 64 MiB logical per pane)
  and `scrollback.lines` (default unlimited). Eviction drops whole head pages, and is
  block-atomic where a T-14 block boundary is within one page of the cut.
- **Cold-page compression**: complete history pages outside the viewport are LZ4-block
  compressed on a worker, bounded to 4 pages per batch; decompression is transparent on
  access. A batch is armed only by an event (a page leaving the viewport or completing)
  as a one-shot timer 2 s after the pane's last output; with no output there is nothing
  new to compress and no timer exists (T-23 `IDLE`).
- **Disk spill** (opt-in, R2): pages beyond the memory budget go to an unlinked 0600 file
  under `$XDG_STATE_HOME/apotheosis/`, LZ4 then AEAD (`chacha20poly1305 =0.10`, RustCrypto, pure Rust, Apache-2.0 OR MIT, already used by ec-brokerd) with a per-process random key held
  only in memory (key handling per T-18 §9). Never enabled by default (ADR 0121).

## 5. Snapshots
Two APIs; each consumer of grid changes uses exactly one and owns its own change state.

| API | Consumer | Change tracking |
|---|---|---|
| `snapshot_dirty(&mut FrameSnapshot) -> Damage` | renderer only (the window showing the pane) | the row `dirty` flag and the screen's pending-scroll record; cleared by this call |
| `snapshot_since(&mut RowSnapshot, seen: &mut SeenSet) -> Changes` | a11y (T-20 §4), semantic publisher (T-17 §4), mux tee (T-21), control-socket `read-content` (T-12) | the row change sequence number (§1.3); never reads or clears `dirty` |

- `Damage` is `None | CursorOnly | Rows(set) | Scroll { top, bottom, left, right, delta,
  rows } | Full`. `Scroll` reports a full-screen or region scroll that happened since the
  last snapshot as a row shift of `delta` within the region, and `rows` lists only the
  newly exposed or otherwise changed rows, which are the only rows copied. Several scrolls
  of one region accumulate into one delta; a scroll of a different region, a delta ≥ the
  region height, a reflow, an alternate-screen switch or a palette change yields `Full`.
- `snapshot_since` copies the visible rows whose sequence number is greater than the
  consumer's `seen` entry for that row position, then updates `seen`. `SeenSet` is
  allocated by the consumer at the screen size and is reset to "nothing seen" on resize,
  screen switch or reflow, which makes the next call a full copy.
- Both copy styles resolved, hold the term lock only for the copy, and allocate nothing
  when the snapshot buffer already has capacity. A pane is drawn by exactly one window at a
  time (T-13); moving it to another window makes that window's first snapshot `Full`.

## 6. Test Plan
- Property tests: reflow round-trip (narrow then widen restores text and pins); random
  operation sequences against a naive `Vec<Vec<Cell>>` model; pins never dangle.
- Lazy reflow: resize during a partially converted history (including a second resize
  before conversion finishes) yields the same text and pins as an eager reflow.
- Consumer independence: randomised traffic with the renderer, a11y and publisher
  snapshotting in random interleavings; every consumer's view equals the grid after each
  of its snapshots. `Scroll` damage replayed on the previous frame equals `Full`.
- Compression round-trip; eviction honours both limits; block-atomic cut.
- Memory budgets `MEM-PANE`, `MEM-LINE` (T-23). Miri on the page allocator tests.

## 7. Open Decisions
- Standard page size (512 KiB proposed) is fixed by the M3 bench, not by this text.

# T-03 — Terminal Semantics (Draft v0.2)

Crates: `apoth-term` (AGPL-3.0-only; deps: `apoth-vt`, `apoth-grid`, `apoth-unicode`,
`apoth-terminfo`, hooks into `apoth-image`). Not TCB.

## 1. Contract
`Term::feed(&mut self, bytes: &[u8], now: Instant) -> Wake` applies bytes to the screens
and appends to two queues: `replies` (bytes for the PTY) and `events` (typed, T-11 §3).
`Term` performs no I/O and reads no clock. `Term::next_deadline()` exposes the earliest
timer it needs (sync-output timeout, blink phase is not here). Same bytes + same `now`
sequence ⇒ same state (T-21).

## 2. The mode table
One source file, `modes.rs`, lists every ANSI and DEC private mode: number, name, default,
`Settable | ReadOnlySet | ReadOnlyReset | Unrecognised`, and owner. DECRQM answers, DECSET
handling, XTSAVE/XTRESTORE and the generated docs all derive from it (VTCORE-19, -20).
A mode's DECRQM state may depend on config (2027, T-04 §2); the table entry then names
the config key and the state per value. A test queries every mode by DECRQM and compares
with the table.

`modes.rs` also marks which modes feed the input path (DECCKM, DECKPAM, 1036, 2004, mouse tracking and encoding modes 9/1000–1006/1015/1016, 1004 focus). After any sequence that changes one of them, or the kitty keyboard flag stack (push, pop, set), `Term` stores the pane's `InputModes` mirror (`AtomicU64` bitfield + active kitty flags word, `Release`) before the next byte is parsed; T-00 §4.2. A test asserts that every input-path mode in the table has a mirror bit.

Sixel modes in the table (all answer DECRQM): `?80` DECSDM, default reset, sixel scrolling (set = scrolling disabled, xterm ≥ 369 polarity; semantics T-15 §2); `?1070` private sixel colour registers, default set (T-15 §2); `?8452` sixel cursor right, default reset (T-15 §2).

the decisions and deviations.

# T-04 — Unicode (Draft v0.2)

Crate: `apoth-unicode` (Apache-2.0, no deps); policy lives in `apoth-term`.
Implements UNICODE-01..09, -17, -19, -20, FONTS-07.

## 1. Tables
An `xtask` generates, from UCD files checked into `apotheosis/data/ucd/` (no build-time
download), one three-stage table giving per code point: width (0/1/2), grapheme-break
class, `Emoji_Presentation`, `Extended_Pictographic`, and East-Asian-Ambiguous. A second
generated table is the UAX #29 transition function. Unicode version is the latest at each
release; `unicode.version` (R2) selects older width behaviour by overlay.

## 2. Grapheme clustering
Clustering is always on in the grid: a cluster occupies one cell (or two if wide) and is
stored per T-02 §1.4. Mode 2027 (grapheme cluster widths) reflects the width method in
force (§3) and is settable when that is not `unicode`:

| `unicode.width-method` | DECRQM 2027 | `CSI ? 2027 h` | `CSI ? 2027 l` |
|---|---|---|---|
| `unicode` (default) | 3 (permanently set) | no effect | no effect |
| `wcswidth` | 2 (reset), or 1 after `h` | pane uses `unicode` widths until `l`, RIS or a config reload that changes the method | back to `wcswidth` |

The switch applies to cells printed after it; stored widths are never recomputed. A cluster never extends across a cursor
movement: a combining mark that arrives after any cursor-moving control starts a new cell
(UNICODE-03).

## 3. Width
`unicode.width-method`: `unicode` (default: width of the cluster from the table; VS16 on
an emoji-capable base widens to 2, VS15 narrows to 1) or `wcswidth` (legacy per-scalar
sum, for applications that disagree). `unicode.ambiguous-width` `narrow` (default) or
`wide`. `font.cell-width-override` ranges (FONTS-07) force PUA/icon ranges to 1 or 2 so
application and terminal agree. Width decisions are made once, at print time, and stored
in the cell; the renderer never recomputes width.

## 4. Bidirectional text
R1: no reordering; text is laid out in logical order, as in kitty, alacritty and ghostty.
R2 (UNICODE-14..16, should): the terminal-wg BiDi model with `unicode-bidi`, implicit mode
default, per-row logical↔visual maps. The cell and row formats need no change for it.
Shaping of joining scripts within a run is R1 (T-06).

## 5. Text sizing (OSC 66)
R2 (UNICODE-08, raised from the matrix's "must" tier to R2 because no R1 gate depends on
it and it touches grid, renderer and selection). Full kitty protocol: scale 1–7, width
0–7, fractional `n/d`, alignment. A sized run is a *multicell block* recorded in the row's
multicell list; member cells carry the multicell bit; any erase or overwrite intersecting
a block removes the whole block. Payload cap 4096 bytes. Width-only (`w=`) is honoured
even when scaling is disabled.

## 6. Test Plan
- Mode 2027: DECRQM under both methods; `h`/`l` under `wcswidth` change the column after
  printing a ZWJ sequence (CPR), and are inert under `unicode`.
- Generated-table tests against `GraphemeBreakTest.txt`, `EastAsianWidth.txt`,
  `emoji-test.txt`; `unicode-segmentation` as dev-dependency oracle.

# T-05 — Input (Draft v0.2)

Crates: `apoth-input` (Apache-2.0, pure encoders), keyboard state in `apoth-wl`.
Implements INPUT-01..09, -12, -13, -16..-19, -22..-24, -26..-28, -30, -34..-37, -39, -40,
-48, -58..-78.

## 1. Keyboard state
- **XKB backend** (ADR 0125): trait `KeyboardBackend`. The default and shipped
  implementation, from M7, is `kbvm` (pure Rust): parse the `wl_keyboard.keymap` text,
  build a stateless lookup table keyed by (group, effective mods, keycode), update
  components from `wl_keyboard.modifiers`. `libxkbcommon` is the cargo feature
  `xkbcommon`, off in release builds; it is the differential oracle (§8) and an escape
  hatch for source builds (`APOTHEOSIS_XKB=system` selects it when compiled in).
- Virtual modifiers (Super, Hyper, Meta, NumLock, CapsLock) are resolved by *name* from
  the keymap, never by fixed bit index (INPUT-68).
- Compose: XCompose search order per INPUT-72; the table is built lazily on the first
  dead key or Compose press, off the main thread (PERFORMANCE-87).
- Key repeat is client-side from `wl_keyboard.repeat_info`, cancelled on release, on focus
  loss and on any other repeating key; `keyboard.repeat-rate` / `keyboard.repeat-delay` override.
- On `wl_keyboard.leave`, all held keys are released (release events emitted under kitty
  flag 2) and repeat stops.

## 2. Key encoding (`apoth-input`)
Pure function `encode_key(&KeyEvent, InputModes, &mut [u8; 64]) -> usize`, where `InputModes` is a `Copy` value loaded from the pane's lock-free mirror (T-00 §4.2). No allocation. The mouse encoders (§5) and paste wrapping (§6) take the same `InputModes` value; no encoder caller holds a term lock.
- **Legacy**: xterm/VT220 forms, DECCKM, DECKPAM/DECNKM, DECBKM, `CSI 1;m X`, `CSI n;m ~`,
  Alt as ESC prefix (mode 1036 default set), Shift+Tab `CSI Z`, Ctrl mapping with the
  non-Latin fallback of INPUT-70.
- **Kitty keyboard protocol**, complete: flags 1, 2, 4, 8, 16; push/pop/query stack of 8
  per screen (main and alternate separately); functional-key PUA table; alternate keys
  from the Shift-only and empty-mask lookups (INPUT-65, -66); base-layout key from a static
  evdev→US table (INPUT-67); associated text; event types. State is per pane and is never
  downgraded by the mux (INPUT-48).
- **modifyOtherKeys** levels 1–2 and `formatOtherKeys` (R2; raised to R1 if the tmux
  compatibility fixtures in T-03 require it).
- Not built: HP/SCO/Sun function keys, Win32 input mode, always-on fixterms.

## 3. Bindings
Bindings are matched before encoding. Full model in T-11; input-side rules: bind lookup applies only to real seat key events; `input.send-keys` bypasses it (T-11 §3, T-12 §2).
- A trigger is a chord or a `>`-separated sequence of chords. `phys:` matches the key
  position, default matches the keysym after layout.
- Key tables (modes) form a stack; activation options: `one-shot`, `timeout`, `until-unknown`,
  `replace`. A visible indicator shows the active table and any pending sequence.
  Sequence timeout default 1000 ms (`keyboard.sequence-timeout`, 0 = none).
- Per-binding flags: `unconsumed` (also forward), `performable` (consume only if the
  action can run), `global` (R2).
- A key consumed by a binding emits nothing to the PTY, including its release event.

## 4. IME (text-input-v3)
Enable on focus; send cursor rectangle in surface coordinates on every cursor move;
`content_type` terminal. Apply `preedit_string`, `commit_string`,
`delete_surrounding_text` atomically on `done`. Preedit is drawn inline at the cursor by
the renderer with underline and the active segment highlighted; it is never written to the
grid or the PTY. Committed text goes through `encode_text` (kitty flag 16 aware).

## 5. Mouse
- Reporting: 1000/1002/1003 with SGR 1006 and SGR-Pixels 1016; X10 `CSI M` default
  encoding for 1000 without 1006. Not built: 1005, 1015, 9 (INPUT-20 → never; no surviving
  application requires them).
- **Shift always overrides** application mouse capture for local selection; the override
  modifier set is `mouse.selection-override`.
- Mouse bindings use the same Action vocabulary, keyed by button, click count, modifiers
  and target (`grid`, `link`, `tab`, `divider`, `scrollbar`).
- Alternate scroll 1007 (INPUT-24), default set (`mouse.alternate-scroll-mode #true`;
  `less` depends on it): active only on the alternate screen while no mouse-reporting
  mode (1000/1002/1003) is set; otherwise the wheel is reported as a button. Each notch
  sends `mouse.scroll-lines` (default 3) Up/Down key presses in the current DECCKM form
  (`SS3 A` or `CSI A`), through the same encoder as a key (kitty flags apply).
- Button codes, identical in X10 and SGR encodings: wheel up/down/left/right 64/65/66/67;
  buttons 8–11 are 128–131. In X10 `CSI M` encoding an event whose column or row
  exceeds 223 is not sent (SGR 1006 has no limit).
- Selection gesture state machine is a pure function (click count ≤ 3 within interval and
  distance, drag, autoscroll at edges, extend with Shift-click). Word boundaries from
  `selection.word-chars`; smart-selection regex rules tried first on double-click (R2).
- Copy hygiene: trailing spaces trimmed, soft-wrapped rows joined, `selection.copy-on-select`
  `none|primary|clipboard|both` (default `primary`).
- Pointer shape via `wp_cursor_shape_v1`, `wl_cursor` theme fallback. OSC 22 stack is R2.

## 6. Paste
- Sanitising, bracketing, newline handling, the paste guard and every `paste.*` key are
  defined once, in T-18 §4. This crate provides the pure encoder
  `encode_paste(&[u8], InputModes, out)` that implements T-18 §4 and is tested against
  its table; it defines no keys and no policy of its own.
- Paste and key bytes are appended to a per-pane write queue on the main thread; write
  readiness is armed only while the queue is non-empty; writes take priority over reads.

## 7. Invariant
Key, paste, IME and clipboard *content* is never logged at any level, never placed in an
event payload that reaches the journal, and never included in crash reports. Debug logging
of input records event kinds and byte counts only.

# T-06 — Fonts & Text (Draft v0.2)

Crate: `apoth-font` (AGPL-3.0-only; deps: `fontconfig-parser`, `skrifa`, `harfrust`,
`swash`, `zeno`). Implements FONTS-01..06, -09..-12, -15..-18,
-20, -24, RENDERING-14, -17, -21..-23, PERFORMANCE-18, -21, -22.

## 1. Stack
- **Discovery**: our own directory scan. Directories come from `fontconfig-parser`
  (`<dir>`, `<include>` and the XDG defaults; no libfontconfig, no FreeType); each face's
  `name`, `OS/2`, `fvar` and `cmap` are read through `read-fonts` once and stored in the
  on-disk index of §4. `fontdb` is not used: it parses with `ttf-parser`, a second parser
  of untrusted font files. JetBrains Mono and Instrument Sans from `assets/fonts/` are
  embedded and are the terminal fallback of every chain.
- **Parsing, outlines, hinting, colour**: `skrifa`/`read-fonts`. One parser family:
  `ttf-parser`, `rustybuzz`, `fontdb` and `cosmic-text` must not appear in `cargo tree`.
- **Shaping**: `harfrust`.
- **Rasterisation** (§7): `swash`'s scaler (`ScaleContext`, which draws skrifa outlines
  with skrifa hinting and rasterises with `zeno`) for grayscale outline masks and for
  bitmap emoji (CBDT/sbix). COLRv0/v1 is painted by our own painter on skrifa's
  `ColorPainter`: each clip and glyph path is rasterised to a coverage mask with `zeno`;
  solid, linear, radial and sweep fills and the COLRv1 composite modes are our code, on
  premultiplied RGBA8. OT-SVG is not supported.
- **One `read-fonts`**: `harfrust`, `skrifa` and `swash` are pinned to versions that
  resolve a single `read-fonts` (and a single `skrifa`), so one `FontRef` serves shaping
  and rasterisation; cargo-deny `bans` rejects duplicate versions of either (T-24 §3).

## 2. Configuration surface
Key paths: `font.<style>.family`, `font.<style>.instance`, `font.<style>.axes`, `font.<style>.features` (OpenType feature list, `+ss01 -calt`) for style in `regular|bold|italic|bold-italic`; `font.size`; `font.fallback` (ordered families); `font.map` (Ty `CodepointRanges` → family; binds code-point ranges to a family ahead of fallback, symbol maps); `font.cell-width-override` (Ty `CodepointRanges`); `font.synthetic` (set of `bold|italic`, default both) for the synthetic bold/italic toggle when a style is missing. `font.ligatures` `on|off|not-under-cursor`
(default `not-under-cursor`).

## 3. Metrics
Cell width = round(advance of the primary face), cell height = round(ascent + descent +
line gap), the gap split evenly; baseline derived from the cell bottom. Every derived
metric (underline position and thickness, strikethrough, cursor thickness) has a minimum
of 1 px and a KDL adjustment (`font.adjust-*`, px or %). All grid metrics are integers in
physical pixels at the surface's current scale and are recomputed on scale change.

## 4. Fallback
A per-face coverage index (sorted code-point ranges) is cached on disk under
`$XDG_CACHE_HOME/apotheosis/`, keyed by path+mtime+size, so fallback is a binary search
without opening fonts. For a cluster, choose one face covering *all* its code points
(ZWJ, keycap, VS sequences). Order: style's families → `font.map` → fallback list →
system coverage index (script-aware) → embedded fonts → a procedural "tofu with hex"
glyph. Emoji presentation selects colour faces first.

## 5. Shaping
- Runs never cross rows; a run breaks on face, style, script, and at the cursor cell when
  the ligature policy says so.
- **Simple-text fast path**: a run of code points that the face maps 1:1 with no enabled
  feature affecting them skips the shaper: one glyph per cell at the cell advance.
- **Shape cache**: key = hash(text, face, features, size); position-independent (relative
  cluster indices) so the same word at another column hits. Fixed-size N-way associative
  table, no allocation on hit.
- Shaped clusters are mapped back to cells; a ligature glyph spanning *n* cells is
  rasterised once and drawn as *n* cell-wide slices so each cell keeps its own colours.

## 6. Built-in glyphs
Box drawing U+2500–257F, block elements, shades, quadrants, sextants, octants, braille,
Powerline U+E0B0–E0BF and the Symbols for Legacy Computing ranges are drawn by our code at
the exact cell size and never taken from a font (`font.builtin-glyphs #true`). Lines meet
cell edges exactly at every scale; diagonals and arcs are antialiased analytically. This
module is original work specified from the Unicode charts.

## 7. Rasterisation
Grayscale coverage masks from the swash scaler (§1); hinting `none|light|full` (default `light`); grid glyphs at
integer origins; glass-interface text at 4 horizontal sub-pixel bins. LCD sub-pixel AA is
not built: surfaces are translucent and fractionally scaled (RENDERING-20's opt-in is
declined). `font.thicken` adjusts stem weight. Blending is T-07 §4.

## 8. Diagnostics
`apoth fonts list|resolve <text>` prints the resolved chain, the face chosen per cluster,
the rule that matched, features and metrics.

## 9. Test Plan
- Bitmap goldens for every built-in glyph at 6 cell sizes (exact match; our code only).
- Shaping snapshot tests on the embedded fonts (glyph ids and positions).
- Fallback tests with a fixture font directory. Coverage-index cache invalidation test.
- Fuzz: `font_load` (discovery index read) and `font_raster` (outline and COLRv1 paint) on
  arbitrary bytes through our skrifa/swash wrappers (no panic, bounded time).
- COLRv1 goldens for each paint type and composite mode on a test font (our painter).

## 10. Open Decisions
None.

# T-07 — Renderer & Frame Scheduling (Draft v0.2)

Crate: `apoth-render` (AGPL-3.0-only). Implements
RENDERING-01..07, -09, -17..-19, -24..-26, -30, -55, -57, -59..-64, -68, -70, -71,
PERFORMANCE-01..09, -14, -17, -26, -34, -35, -67, -76.

wgpu is pinned in the Apotheosis workspace `Cargo.lock` (T-24 §1), independent of the
EclipseOS shell's wgpu: `wgpu = { version = "=30.0.2", default-features = false,
features = ["std", "vulkan", "wgsl"] }`. Every wgpu fact this section relies on was
verified on 30.x (Appendix A). A bump is its own change with the Appendix A rows
re-verified. The build must not enable `gles`, `webgl` or `angle` (ADR 0110's Vulkan-only
premise; checked in T-24 §3).

## 1. Threads and ownership
| Thread | Owns | Blocks on |
|---|---|---|
| main | calloop: Wayland connection, input, bindings, every PTY write (keys, paste, replies) via the per-pane O_NONBLOCK outbound queue, T-00 §4.2, glass state, config, control socket, timers | epoll |
| io (per pane) | PTY reads, `Term::feed`; replies into the reply queue (never writes the PTY), lazy reflow slices (T-02 §3) | `read` |
| render (per window) | wgpu surface and its per-frame Wayland requests (§3.1), scene build, the window's atlases, present | condvar; under `Fifo` only, swapchain acquire (§3) |
| workers (2–3) | glyph raster misses beyond the inline budget (§4), image decode, page compression, search over history | queue |

`Term` is behind a fair mutex. Every lock taker and its bound:

| Taker | API | Hold |
|---|---|---|
| io | `Term::feed` | slices of ≤ 64 KiB or 1 ms; yields at the slice end whenever any other taker is waiting |
| render | `snapshot_dirty` (T-02 §5) | one snapshot |
| a11y adapter (T-20 §4), publisher (T-17 §4), mux tee (T-21) | `snapshot_since` (T-02 §5) | one snapshot |
| main, control-socket `read-content` / `get-text` (T-12) | `snapshot_since` or one logical-line batch | one snapshot |
| worker, search (T-14 §6) | active area by `snapshot_since`; history one page per hold | one snapshot or one page |

"One snapshot" is ≤ 100 µs for a full-screen copy at 300×80, the same bound as T-23 §3
rule 2; M11 measures it. If the bound is exceeded, the fallback is double-buffered rows
(the io thread writes a back row set; the snapshot swaps it in O(1)). No taker
other than io holds the lock while doing anything but copying. (Resolves PERFORMANCE-64
"everything on calloop" against PERFORMANCE-07: parse is off the main loop; the
grid-ownership question is settled as "io thread owns mutation, consumers copy".)

Wakeups are edge-triggered: the io thread sets the pane's dirty flag atomically and notifies the render condvar only on its clean→dirty transition; render clears it when it snapshots. Events (title, cwd, progress latest-wins; bell count; marks and notifications in a bounded queue that drops and counts on overflow) go to a fixed-capacity per-pane slot with buffers preallocated at their T-18 §5 caps; main is pinged at most once until it drains the slot (T-00 §4.3).

## 2. Frame scheduling
This section is the only normative scheduler; T-23 §3 rule 3 refers here.

- **Event-driven**: zero periodic wakeups. Every timer is one-shot and is armed only by
  an event (PTY output, input, focus, configure, file change, presentation feedback).
  Cursor blink and glass animation timers exist only while blinking or animating
  (`IDLE-BLINK`); with a static screen, no blink and no animation the process has no
  armed timer (T-23 `IDLE`). Main-loop timers live in one timer queue.
- **Frame gate**: one `wl_surface.frame` callback in flight per surface, state `Idle →
  Requested → Received`. A frame is rendered when the window is dirty **and** (no
  callback is pending **or** the callback has fired). Never request a callback without
  committing. Under the `Fifo` fallback this gate is off (§3).
- **Output coalescing**: the first dirtying read arms an upper timer (half the measured
  refresh interval, clamped to ≤ 8 ms; 8 ms until feedback has been received); each
  further read re-arms a lower timer (0.5 ms). Render on whichever fires first.
- **Echo bypass** (PERFORMANCE-05): output that arrives within `render.echo-window`
  (default 30 ms; value fixed by the latency probe at M17) of a local key event skips
  both coalescing timers. It does not skip the frame gate.
- Under flood, intermediate states are dropped: parse everything available, render the
  latest state once per gate opening.
- Mode 2026 holds presentation per T-03 §4.
- Occluded or suspended surfaces (`xdg_toplevel.suspended`, callbacks stopped, wgpu
  `Occluded`) stop rendering entirely.
- **Pacing ladder**, in order; each step is used when available, else the next:
  1. Frame callbacks gate rendering (above).
  2. `wp_presentation` feedback on every commit supplies the measured refresh interval
     for the coalescing timers and the end stamps of the latency probe (T-23).
  3. Present mode `Mailbox`: we never block in present or acquire.
  4. Present mode `Fifo`: the WSI paces (it may use `wp_fifo_v1` and
     `wp_commit_timer_v1` itself); our frame gate is disabled and the render thread
     blocks in `get_current_texture` (§3).
  5. Explicit present timing (`VK_EXT_present_timing`) once wgpu exposes it: M38,
     conditional on that upstream API (ADR 0119 "Revisit when").

  Apotheosis never creates a `wp_fifo_v1` or `wp_commit_timer_v1` object on a
  WSI-owned surface (a second object on a surface is a protocol error, fatal per T-09
  §2); T-09 §3 lists those globals as informational only.

## 3. Presentation
- wgpu `Surface` on the Vulkan backend. Present mode `Mailbox` when offered, else `Fifo`;
  `Immediate` is never requested. `desired_maximum_frame_latency = 1`. Under `Mailbox`
  the render thread never blocks in acquire or present. Under `Fifo` it may block in
  `get_current_texture`; this is the only blocking GPU wait in the process, it is on the
  render thread, and main never waits for it. `apoth doctor` reports the mode in use.
- Alpha: choose `PreMultiplied` from the surface capabilities; all colour written to the
  surface, including the clear colour, is premultiplied; blend `One, OneMinusSrcAlpha`. If
  no alpha mode is offered (reported on some proprietary drivers), fall back to opaque and
  surface that in `apoth doctor`.
- Adapter selection: prefer the adapter the compositor renders on; never pick a software
  adapter when a hardware one offers an alpha-capable surface.
- Opaque region: empty when translucent; full when alpha is 1 or fullscreen.
- Fractional scale: `wp_fractional_scale_v1` + `wp_viewport`, `buffer_scale` 1, buffer
  size chosen so the viewport maps pixels 1:1 (viewport source unset, destination = the
  window's logical size); integer `preferred_buffer_scale` fallback.
- Surface errors: `Outdated`/`Suboptimal` → reconfigure; `Lost` → recreate surface;
  device lost → rebuild device, pipelines and atlases from CPU state (PERFORMANCE-76).
- **Damage to the compositor** (ADR 0119): wgpu's surface path exposes neither buffer age
  nor damage rectangles, so each presented frame is full-surface damage to the compositor.
  We do not build our own swapchain (GRAPHICS-37/38 rejected: unsupported wgpu-hal
  internals). Mitigations: zero frames when idle, the retained grid texture with scroll
  shifts (§4), and an upstream request for incremental present. `IDLE` and `PWR-SCROLL`
  budgets (T-23) are the acceptance criteria, not the mechanism.

### 3.1 Commit ownership
The WSI commits the window's main `wl_surface` inside `SurfaceTexture::present()` on the
render thread. Therefore:
- After the hand-off at the end of startup (§5), main never commits that surface.
- The render thread owns a dedicated `wl_event_queue` (proxy wrappers) for that
  surface's `wl_callback` (frame) and `wp_presentation_feedback` objects and dispatches
  it itself. Main's queue never receives those events.
- Surface state that must land in a given frame's commit — `xdg_surface.ack_configure`
  for the size being drawn, window geometry, opaque region, input region, the blur
  region (T-09 §5) — is computed by main and handed to the render thread through one
  per-window double-buffered slot. Immediately before `present()` the render thread sends,
  in order: the slot's pending requests, `wl_surface.frame` (when the gate is on),
  `wp_presentation.feedback`; then calls `present()`. A configure is acknowledged only by
  the frame whose swapchain matches its size.
- Subsurfaces created by main (T-08, T-09) are committed by main; their state that must be
  synchronised with the main surface uses `wl_subsurface.set_sync` and is applied by the
  main surface's commit above.
- Latency end events: `LAT-ECHO` ends at the return of `present()` (a tracing span on the
  render thread); `LAT-PHOTON` ends at `wp_presentation_feedback.presented`.

## 4. Scene
Passes per frame, back to front:
1. Window fill (translucent base for glass).
2. Images with z < 0 (T-15).
3. **Grid, retained**: the grid is rendered into an offscreen texture that is updated only
   for damaged rows, then composited. The texture and the background texture below are
   row rings with a row-offset uniform: `Scroll` damage (T-02 §5) over the full grid
   advances the offset; a region scroll copies the region's rows through a scratch texture
   (`copy_texture_to_texture`, never overlapping in place). Per-row instance ranges move
   with their rows. Only the rows listed in the damage are redrawn. Within it:
   a. backgrounds — one full-grid quad sampling a `cols × rows` RGBA8 texture; selection,
      search highlight, inverse and dim are folded in on the CPU before upload;
   b. glyphs — one instance per glyph (grid position, pixel offset, atlas rect, colour,
      flags), persistent per-row instance ranges rebuilt only for damaged rows;
   c. decorations — underline styles, strikethrough, overline as procedural rects/sprites
      with integer period arithmetic so patterns join across cells.
4. Images with z ≥ 0, media placements.
5. Cursor (block, beam, underline, hollow when unfocused); glyph under a block cursor is
   recoloured; optional smooth cursor motion, default off.
6. IME preedit.
7. Glass interface draw list (T-08): rounded rects (SDF), images, text.
8. Overlays.

**Atlases** are per window, owned by that window's render thread; no lock is taken on an
atlas hit. R8 mask and RGBA colour, skyline-packed pages, LRU by the window's own frame
counter; an entry may be evicted only when its last-use frame is older than every frame
still in flight on that window. Rasterised glyph bitmaps are kept in one process-wide
CPU glyph cache of immutable `Arc` entries (sharded map; a shard lock is held only for
lookup or insert, never across a raster or a scene build), so a second window uploads
from it instead of rasterising. Built-in glyphs are cached per (cell size, code point).

**Atlas misses**: a glyph needed by the frame and missing from the window's atlas is
taken from the CPU glyph cache, else rasterised inline on the render thread, up to
1 ms or 16 glyphs per frame, into a preallocated scratch buffer. Glyphs of the rows that
answer a key event within `render.echo-window` are always rasterised inline, whatever the
budget. Remaining misses go to the workers; until a result lands the cell is drawn without
its glyph and the row stays in the renderer's own pending set, redrawn in the next frame
after the result arrives. Shape-cache misses (T-06 §5) are shaped on the render thread
into a reused arena; no per-run allocation.

Text blending: `render.text-blending` `linear-corrected` (default), `linear`, `native`.
Minimum-contrast recolouring is defined once, in T-20 §6 (`colors.minimum-contrast`); the
renderer applies it per cell on the CPU side of pass 3.

## 5. Startup
Adapter and device creation run concurrently with PTY spawn and font resolution. No buffer
is attached before wgpu is ready (T-09 §7): the first commit is the first wgpu frame, so the
compositor maps the window with real content. A second window in a running
process reuses device, queue, pipelines, fonts and the CPU glyph cache, and builds its
own atlases from that cache (`START-WARM`).

## 6. Test Plan
- **Scene snapshot tests** (primary gate, no GPU): `FrameSnapshot → instance lists`
  compared to stored text.
- **Damage mirror test** (PERFORMANCE-30): randomised editor-shaped traffic, including

# T-08 — Glass Interface (Draft v0.2)

Crates: `apoth-ui` (AGPL-3.0-only; GPU-free, emits a draw list) and the glass pipeline in
`apoth-render`. Visual source of truth: `docs/STYLE.md`. Implements UI-01, -05, -06, -08,
-12, -18, -27, -45, -46, -48, -49, -52 (R1 musts); UI-03, -04, -09, -10, -13, -14, -16,
-21..-23, -26, -31..-35, -44, -50, -53, -54 (should); UI-11 (R2).

## 1. Principles
1. **Everything the terminal draws around the grid is glass**: translucent layers over the
   compositor's blur, rounded corners, a crisp rim, soft depth. Dark by default, gold accent.
2. Focus and selection are a **brighter fill plus a crisp rim**, never a halo. `apoth-ui`
   has no blur, glow, bloom or gradient primitive, so a surface cannot violate this.
3. Every interactive element has hover, pressed, focused (keyboard) and disabled states.
4. The interface is drawn by our renderer in the same surface as the grid (UI-46); it is
   not a layer-shell client and not a second toolkit.
5. Tokens (radii, spacing, alphas, durations, type scale) come from the shared pure token
   crate extracted from `shell/crates/ec-ui/src/tokens.rs` (milestone X2), colours from
   `ec_theme::derive` (T-17 §2). No literal colour or radius appears in `apoth-ui`.

## 2. Toolkit model
- **Immediate-mode with retained state**: each frame the UI model is walked to produce a
  layout tree and a draw list (`RoundedRect{rect, radii, fill, rim}`, `Text{run, pos,
  colour}`, `Icon`, `Clip`, `Shadow{rect, radii, spread, alpha}`); per-widget state
  (hover, focus, animation progress, text-edit state) is keyed by stable ids.
- UI input marks a UI-only dirty flag; a UI-only frame re-uses the previous grid texture
  when the compositor's buffer age allows, so typing in the palette never rebuilds cells.
- Widgets (closed set, R1): label, button, icon button, toggle, text field (single line,
  IME-capable, selection, clipboard), list (virtualised, keyboard navigable), scroll area,
  tab strip, split handle, tooltip, toast, bar (search / consent / error), modal sheet,
  menu, progress, badge. R2: slider, picker grid.
- Text in the interface uses the same shaping and atlas path as the grid (T-06) with the
  UI font (`interface.font` `system|<family>`, default `system`: the portal's UI font,
  else the terminal font).
- Animation: one spring and one ease helper (UI-04), time-composable so irregular frame
  intervals stay correct. `interface.motion` `system|full|reduced|none`, default `system`:
  `reduced` while the portal's reduce-motion setting is on, else `full`. An animating surface requests frames; a
  settled one requests none (T-07 idle rule).

## 3. Glass pipeline
- Window background: `window.opacity` `auto|<0..1>` (default `auto`: 0.82 while a blur
  capability is present, else 1.0; re-evaluated when the capability changes) applies to
  default-background cells; `window.alpha-mode`
  `default|matching|all` decides whether explicitly coloured cells are also translucent.
- Blur is requested from the compositor (T-09 §5), updated double-buffered with the frame
  that changes it. **On Abyss** the blur region is exactly one box covering the window
  geometry, so the compositor draws its own backdrop, rim, bezel and window shadow
  (COMP-06 §1 `ext_background_effect` row, COMP-02 C-14/C-15); the client lays only the
  tint (`docs/STYLE.md` §Colour). Off Abyss the region is the union of the window's glass
  rects. Without a blur capability the fallback is a raised tint alpha
  (`window.blur-fallback` `tint|opaque`), logged once.
- Interface layers sit above the grid: each is a rounded rect with fill alpha from the
  token table and a 1 px hairline rim. While blur is on, layers carry **no** drop shadow
  and no top-edge highlight (STYLE.md: cards inside a window are fill + hairline only;
  the compositor's rim lights the edge). The inner top highlight and the analytic
  rounded-rect shadow (no blur pass) are drawn only in the blur-off fallback and, for the
  window shadow, only for CSD off Abyss (T-09 §4).
- Text over glass meets a minimum contrast of 4.5:1 against the *worst-case* backdrop
  assumed by the token table; `ec_theme::validate` is run on every derived palette.

## 5. Hit-testing and focus

# T-09 — Wayland Client (Draft v0.2)

Crate: `apoth-wl` (AGPL-3.0-only). Implements INTEGRATION-09..11, -13, -53, -58, -61,
-64, -65, -67, UI-45, -48, -49, -52; INTEGRATION-29, -55, -59, -63, -68 (should).

## 1. Stack
`wayland-client` on the system `libwayland-client` backend (required by the Vulkan WSI,
which needs a real `wl_display*`), `wayland-protocols`, and `calloop`. A thin first-party
layer binds the globals with our own `Dispatch` impls on one state struct;
`smithay-client-toolkit` is used with `default-features = false` (no `xkbcommon`; no
`calloop` feature unless needed) for shm pool and output tracking only, not as the
application frame. Keyboard handling is first-party over `wl_keyboard`, feeding the
`XkbBackend` (T-05 §1). No winit. Feature unification is asserted in CI (`cargo tree`
check that exactly one wayland backend is active, and that the `xkbcommon` crate is
absent unless the `xkbcommon` cargo feature is on — T-00 §3.2).

## 2. Event loop
The display fd is a calloop source using the prepare-read / read / dispatch-pending
protocol; the loop flushes before sleeping, handles `EAGAIN` by waiting for `POLLOUT`,
and on `EPIPE` reads once more so the protocol error is surfaced. Protocol errors are
fatal for the connection and logged with interface and code. Main reads `CLOCK_MONOTONIC` when the display fd becomes readable, before dispatch, and attaches it to every input event of that dispatch (T-23 §1).

Each optional global is bound opportunistically; a capability table is kept per window and
exposed by the `wayland-info` Action and IPC (AUTOMATION-38).

## 4. Windows
- Configure handling: size is authoritative; resize snaps the grid to whole cells with the
  remainder as padding (`window.resize-by-cells` only hints min/inc where the compositor
  honours it). States `tiled_*`, `maximized`, `fullscreen` drop shadow and corner radius;
  `suspended` stops rendering entirely.
- CSD (only when `configure(mode)` is client-side): single surface. Off Abyss, window
  geometry excludes a client-drawn shadow margin; on Abyss no shadow margin is drawn
  (the compositor draws the window shadow, COMP-02 C-14; T-08 §3); the input region is
  geometry plus a resize margin; edge hit-tests call `xdg_toplevel.resize`, title drag
  `move`, right-click `show_window_menu`. CSD creation failures are retried on the next
  configure.
- App id `org.eclipseos.Apotheosis` (overridable by `--app-id` and profile; on Abyss an override must start with `org.eclipseos.Apotheosis`, otherwise it is ignored with a diagnostic and the default is used — T-17 §7); title from
  the window template.
- Multi-output: a window uses the scale of the output with the largest overlap as
  reported by `preferred_fractional_scale` / `preferred_buffer_scale`.

## 5. Blur
Bind `ext_background_effect_manager_v1`, track its `capabilities` (blur bit), create one
effect object per surface, and set the blur region, committed with the frame that draws
it. On Abyss the region is one box covering the window geometry (T-08 §3) and only
`ext_background_effect_v1` is used. Off Abyss the region is the glass rects and the
ladder is ext effect → `org_kde_kwin_blur` → tint/opaque. Capabilities can change at
runtime; the ladder is re-evaluated. No private Eclipse protocol is used (ADR 0109).

## 6. Seat
- Keyboard: keymap fd → the XKB backend (T-05); repeat is timed by us from
  `repeat_info`; enter/leave drive focus events (mode 1004) and modifier state reset.
- Pointer: enter serials kept for cursor setting; axis events use `axis_value120` where
  present, accumulated to lines with a configurable multiplier; `axis_stop` ends kinetic
  accumulation. Touch: tap = click, drag = scroll, long-press = context menu (R2).
- Multi-seat: state (focus, IME, selection ownership) is per seat.
- Clipboard and primary: offer `text/plain;charset=utf-8`, `text/plain`, `UTF8_STRING`;
  receive preferring UTF-8, plus `text/uri-list` for file drops (paths are shell-quoted
  and pasted through the paste guard). Transfers are non-blocking pipe sources on the
  loop with a size cap and timeout. DnD of text and files into a pane is R1; drag out is R2.

## 7. GPU surface
`raw-window-handle` handles are built from the backend's display and surface pointers;
the Vulkan WSI attaches buffers to our `wl_surface`. We never attach a buffer ourselves
to that surface. Device loss triggers renderer rebuild (T-07 §3); no adapter ⇒ the
software adapter if installed and `render.allow-software`, else a clear error naming the
missing Vulkan driver.

## 8. Test Plan
Headless-Abyss gates: window appears with correct app id and size; fractional scale
1.0/1.25/1.5/2.0 screenshots are pixel-crisp (cell-grid alignment test pattern);
clipboard round-trip with a test client; IME round-trip with a scripted input-method
client; blur capability removal at runtime; output hot-unplug while mapped; resize storm
(1000 configures) without leak. A protocol-absence matrix runs the client against a
minimal test compositor with each optional global withheld in turn.

## 9. Open Decisions
- Whether to drop sctk entirely once the first-party layer covers seats and outputs.

# T-10 — Configuration (Draft v0.2)

Crates: `apoth-config` (AGPL-3.0-only; no wgpu, no wayland), shared `ec-config-schema`
(Apache-2.0, extracted from `abyss/crates/ec-abyss-config`; ADR 0113). Implements
CONFIG-01, -02, -05, -07..-09, -11, -12, -14, -16..-18, -21, -24, -25, -28, -30..-34, -38,
-41 (must); CONFIG-03, -06, -10, -19, -20, -23, -26, -27, -29, -35..-37, -43..-47 (should).

## 1. One schema table
Every option is one row of `apoth_config::schema::TABLE`: path, `Ty`, default,
constraints, scope (`global|window|tab|pane`), `profilable` (bool), reload class,
override class (§1.1), doc text. Presentation (label, page, widget, group, search
keywords, release tier) is a paired `apoth_config::meta::META` table, one row per `TABLE`
key in the same order, with the "every key has metadata" test — ADR 0107 Option 2, per
product. From the two tables are generated: the KDL parser and validator, `apoth config`
subcommands, the ec-settings Terminal pages, the option reference in `docs/`, and the
coverage test that fails when a key has no GUI control.
**A key that is not in the table does not exist**; there is no stringly-typed side door.

What moves to `ec-config-schema` (ADR 0113, milestone X1), and nothing else:
- `Ty` with its constraints. Existing variants are kept (`Color` is reused; no `Colour`
  is added). New variants: `Font`, `FontFeatures`, `KeyChord`, `Duration`, `Path`,
  `Palette16`, `Action`, `Regex`, `Template`, `Bytes`, `Argv` (argv array with the T-11 §2
  typed placeholders), `CodepointRanges`, `Match` (T-11 §7 grammar), `StringSet`,
  `Map { key: Ty, value: Ty }`, `ThemeRef` (one scheme or a `light=… dark=…` pair). Each
  new variant names its ec-settings widget in the same change.
- A generic `Reload` `Live|NewPane|NewWindow|Restart`; Abyss maps its `Live` → `Live`
  and `NeedsRestart` → `Restart` and uses no other variant.
- The default type `Dv` gains `Computed { id, doc }`: a named function of the runtime
  environment (blur capability, portal settings, compositor), shown in the GUI as
  "Automatic (currently X)"; reset restores `Computed`, and `config diff` compares
  against it, not against its current value.
`Owner` and scope stay per-product types (`ec-abyss-config` keeps `Owner {Abyss, Policy}`;
`apoth-config` has no `Owner`). X1 updates every exhaustive match on `Ty`/`Reload` —
today `shell/crates/ec-settings/src/search.rs`, `shell/crates/ec-settings/tests/coverage.rs`,
`abyss/crates/ec-abyss/src/ipc/config_rpc.rs`, `abyss/crates/ec-abyss-config/src/tests.rs`
and `abyss/crates/ec-abyss-config/tests/config_doc.rs` — in the same PR.

### 1.1 Override class
Every row has an override class; a row without one fails the table test, and the
validator treats an unknown class as `grant` (fail-closed).

| Class | Runtime override (`config.set`, layer 8) | Persist over the socket (`config.persist`) | Keys |
|---|---|---|---|
| `appearance` | socket class `appearance` (T-12 §4) | `config-write` | colours, theme, fonts, opacity, padding, cursor style, tab/scrollbar/interface look |
| `behaviour` | socket class `config-write` | `config-write` | scrollback size, mouse, selection, bell switches other than `bell.command`, notifications filters |
| `security` | **refused** | `config-write`; the consent sheet shows the KDL diff | everything under `security`, `clipboard`, `paste`, `links`, `rule`, `binds`, `mouse-binds`, `key-table`, `macro`, `profile`, `domain`, `layout`, `menu`, `shell`, `include`; `graphics.file-transmission`, `media.allow-paths`; every key whose `Ty` is `Argv`, `Action`, `Match` or `Map` |
| `grant` | **refused** | **refused** — no socket method or Action writes it; only a hand edit or ec-settings | every key under `socket` (`socket.grants`, `socket.key-stream`, `socket.interpreters`; T-12 §4) |

The same column decides automatic profile application (T-11 §6).

## 2. Files and layers
Resolution order, later wins:
1. built-in defaults (the table);
2. `/etc/eclipse/apotheosis.kdl` (OS defaults, owned by the package);
3. third-party fragments `/usr/share/apotheosis/fragments/*.kdl` (profiles, themes,
   actions only; cannot set global options) — R2;
4. `~/.config/eclipse/apotheosis.kdl` and its `include`s (relative, glob, optional `?`;
   depth cap 8; cycle detection; each error attributed to its file);
5. `~/.config/eclipse/apotheosis.d/profiles/*.kdl` (per-file error isolation) — R2;
6. matched profile(s) (T-11 §6);
7. launch overrides (`-o key=value`, flags), re-applied on every reload;
8. runtime overrides (`config.set` Action / socket, scoped to window, tab or pane;
   transient, never written to disk; `config.reset` clears). Only `appearance` and
   `behaviour` keys accept a runtime override (§1.1); a `security` or `grant` key is
   refused with a diagnostic naming the class.
Every value is optional per layer; `apoth config show --origin` prints the winning layer
per key. Off EclipseOS the paths are `$XDG_CONFIG_HOME/apotheosis/apotheosis.kdl` and
`/etc/apotheosis/apotheosis.kdl`; the Eclipse paths are tried first when they exist.

## 3. Shape of the file
Top-level nodes: `version`, `font`, `colors`, `theme`, `unicode`, `window`, `interface`,
`tabs`, `panes`, `close`, `scrollbar`, `cursor`, `scrollback`, `blocks`, `mouse`, `touch`,
`keyboard`, `selection`, `clipboard`, `paste`, `links`, `open`, `hints`, `shell`,
`shell-integration`, `terminal`, `bell`, `notifications`, `progress`, `graphics`, `media`,
`render`, `security`, `accessibility`, `socket`, `sessions`, `domain`, `quick-terminal`,
`binds`, `mouse-binds`, `key-table`, `macro`, `rule`, `profile`, `layout`, `menu`,
`include`, `when`. `when` is the **config-time** conditional: it takes closed static
predicates (`compositor`, `host`, `scheme`, `on-battery`, `scale`) and wraps any nodes.
Runtime mode conditions on binds are a different option, `mode=` (T-11 §3). The complete
key list is the generated reference; the spec does not duplicate it.

`open` (T-14 §11): `open.placement` enum `float|inline|window`, default `float` (where a
terminal handler shows); `open.handlers` map, default empty, `<type> <handler>
[placement]` per entry, where `<type>` is `type/subtype` or `type/*` (a URL's type is
`x-scheme-handler/<scheme>`) and `<handler>` is `apoth-icat`, `apoth-play`,
`<id>.desktop` or `opener` (`links.open-command`); only the two terminal handlers take a
placement. An entry that does not parse is dropped with a diagnostic. "Remember for
<type>" in the picker writes one entry through the editor (§5). Both keys have GUI rows
(Settings → Security → Links, "Open with").

Security additions: a `security { <class> allow|ask|deny }` child block under `domain` and `profile` (T-18 §3; profile wins over domain; it never loosens a pane that is remote only by process detection); `security.remote-keys` bool, default #false (T-17 §5); and `remote.clients` list (extend-only), default [ssh, mosh-client, telnet, docker, podman, kubectl, tmux, screen] (T-18 §10).

## 4. Load, validate, apply
- Parse into a fresh model; collect **all** diagnostics (file, line, column, key,
  message, suggestion for near-miss keys); apply atomically only if the result is valid.
- Tolerance: a bad entry inside a collection (one bind, one rule, one profile) is dropped
  with a diagnostic and the rest applies; a bad scalar keeps the previous good value.
- On error the glass error bar appears in every window; the last good config stays live.
  First start with a broken file runs on defaults plus the error bar.
- Hot reload: inotify on the *parent directories* of the main file and every include
  (survives editor rename-replace), symlinks canonicalised, 100 ms debounce, poll
  fallback (2 s) only on filesystems where inotify setup fails; this state is reported by `apoth doctor` and is excluded from T-23 `IDLE`. Own writes are suppressed by content hash.
- Each key's reload class says what a change needs; a `restart`-class change shows a
  toast saying so. Target: > 95 % of keys are `live`.

## 5. Editing
- `apoth-config::edit` operates on a lossless KDL document (comments, ordering, unknown
  nodes preserved), changing only the affected nodes; writes are temp + fsync + rename.
- Three editors use it: `apoth config set|unset|add|remove` (edits the file locally, no
  socket), ec-settings, and the in-terminal `config.save-override` Action (T-11 §1).
- **Write target.** A write goes to the main user file at top level, unless (a) the
  control was opened in a scoped context — a profile page writes that profile's node, a
  `when` variant selector writes that `when` block — or (b) the key's winning value
  comes from an `include`d user file, which is edited in place in that file. A value
  whose winning layer is `/etc` or a fragment is never edited there; the write creates a
  top-level user value that overrides it. ec-settings shows a value that exists only
  under a `when` block with a predicate chip and edits it in place; any scalar control
  can add a `when` override for that key using the closed predicate set.
- ec-settings links `apoth-config` and edits the file directly; there is no Abyss
  round-trip for terminal settings (ADR 0113). Each control shows its origin layer, an
  overridden marker, and reset; a search box and a changed-only filter cover all keys.
  A live preview terminal is embedded on the appearance pages (R2: until then the
  running windows are the preview, since reload is live).
- Collection editors (binds, mouse binds, key tables, macros, profiles, rules, layouts,
  hints, menus, socket grants, the sequence policy table `security { sequence … }`
  (T-18 §3), `font.map` / `font.cell-width-override` range lists, and theme scheme files
  under `apotheosis.d/themes`) are dedicated pages (milestone M27) built on the same edit
  API.

## 6. Versioning and import
`version 1` node. Migrators are ordered functions over the document model; renamed keys
map through a compatibility table with a deprecation diagnostic. `apoth config migrate`
rewrites the file after showing a diff. Importers (`apoth config import foot|alacritty|kitty
<path>`) are one-shot translators that emit KDL plus a report of untranslatable keys; the
foot importer is R1 because the default switch (T-24) runs it for existing users.

## 7. Themes
`theme` (`ThemeRef`) selects the colour source: `system` (Abyss theme seeds, T-17 §2), a
named scheme, or a `light=… dark=…` pair following the portal colour-scheme. Default
`Computed`: `system` on Abyss, else the stock dark/light pair. Schemes
are KDL files (16 ANSI + fg/bg/cursor/selection + optional 256 overrides) in
`/usr/share/apotheosis/themes` and `~/.config/eclipse/apotheosis.d/themes`. A scheme
change emits the mode-2031 report where enabled (T-03).

## 8. CLI
`apoth config validate|show|get|set|unset|explain|diff|migrate|import|path|edit`:
`validate` exits non-zero with line-numbered diagnostics; `show` prints the effective
merged config (`--origin`, `--changed-only`, `--json`); `explain <key>` prints the doc
row; `diff` compares against defaults. These edit or read the file locally; runtime
overrides are `apoth set`/`reset` (T-12 §5).

## 9. Test Plan
Table-driven round-trip tests for every key (default → KDL → parse → equal); comment
preservation property test (random edits never alter untouched bytes); layer precedence
tests; watcher tests (rename-replace, symlink swap, include change); fuzz target
`config_parse`; ec-settings coverage test extended to every Apotheosis key; importer
fixtures from real foot/alacritty configs; doc generation is checked in CI for drift;
a node-coverage test that every backticked dotted key in this volume and in the annex's
KDL-surface column starts with a §3 node and exists in `TABLE`; an override-class test
that `config.set` and `config.persist` on every `security`/`grant` key are refused as
§1.1 says.

# T-11 — Actions, Binds, Rules, Profiles (Draft v0.2)

Crates: `apoth-action` (Apache-2.0: the vocabulary), dispatcher in `apotheosis`.
Implements AUTOMATION-01..05, -07..-09, -11..-14, -16, -19, -20, -30, -31, -36 (must);
AUTOMATION-06, -10, -15, -17, -18, -24, -25, -34, -35 (should). Extension by embedded
scripting is rejected (AUTOMATION-32; ADR 0122).

## 1. One vocabulary
`enum Action` with typed, parse-validated arguments is the only way anything happens.
Key binds, mouse binds, the palette, menus, rules, macros, layouts, launch flags and the
control socket all construct `Action` values and hand them to one dispatcher on the main
thread. Each variant has a stable string id (`pane.split`, `clipboard.copy`), a title, a
doc line and a capability class (T-12 §4). The registry is generated from the enum; the
palette, the CLI help, the settings bind editor and the reference docs read the registry.
The R1 floor is the ≈100-action set of AUTOMATION-16; the full list is the generated
reference.

Every id is `family.verb` (dotted, kebab-case verb). The families and their capability
classes (T-12 §4) are closed; a variant's class is the family's unless the row names an
exception. A class pair means both are required. Any method or Action whose reply
carries pane text is `read-content` in addition to its listed class.

## 2. Arguments, never shell strings
`launch`, `pipe`, `open`, `coprocess.run`, `config.open` and `capture` with a command
destination take **argv arrays** with typed
placeholders (`{selection}`, `{url}`, `{match}`, `{cwd}`, `{file}`, `{line}`, `{pane-id}`);
a placeholder expands to exactly one argv element and is never re-split or interpreted.
There is no action that passes a string to `sh -c`; a user who wants a shell writes
`argv "sh" "-c" "…"` explicitly, and then placeholders are passed as positional
parameters, not interpolated.

## 3. Key binds
- Grammar: `bind "<mods>+<key>" { <action> … }`; modifiers in any order; key is a keysym
  name (layout-dependent, matched on the produced symbol, then on the unshifted symbol)
  or `physical:<name>` (position-dependent, wins when both match).
- Options: `repeat=#false`, `mode="<mode-condition>"` (`alt-screen`, `app-cursor`,
  `copy-mode`, `searching`, `has-selection`, `kitty-keyboard`, negation with `!`; named
  `mode` so it is not confused with the config-time `when` node, T-10 §3),
  `release=#true`, `global=#true` (R2, portal).
- A matched press consumes the press **and** its release and repeats; the application
  never sees half a chord.
- Bind lookup runs only on real seat key events. Keys synthesized by `input.send-keys`
  are encoded straight to PTY bytes by `apoth-input` and never enter bind lookup, key
  tables or interface focus (T-12 §2).
- **Key tables**: named tables activated by `key-table.push name [one-shot] [timeout]`
  and `key-table.pop`; a leader key is a one-shot table. Multi-key sequences
  (`"ctrl+a>c"`) compile to implicit tables with `keyboard.sequence-timeout`.
- `unbind "<chord>"` removes a default; `binds clear-defaults=#true` starts empty.
- Performable-only binds (AUTOMATION-05 nuance): `bind … performable=#true` passes the
  key through when the action would be a no-op (copy with no selection).
- Mouse binds: `mouse-bind "<mods>+<button|wheel-up|…>" on="press|release|click|double|triple|drag"
  { action }`, with the rule that application mouse reporting wins unless the bypass
  modifier (`mouse.bypass-modifier`, default Shift) is held.

## 4. Macros
`macro "name" { action; action; … }` is an ordered list usable anywhere an action is,
referenced as `macro.run "name"`. Macros may not recurse (checked at load). A macro's
capability class is the union of its members' classes after expansion, computed at load
and checked again at dispatch; a member that is itself conditional on its arguments
(e.g. `pane.split` with a command) contributes its strictest class.

## 5. Rules
```
rule "name" {
    on "command-finished"
    where "status:!0 and duration:>10s and not focused"
    do { notify title="{command}" body="exit {status}" }
}
```
- **Closed event set** (AUTOMATION-13): `bell`, `focus-in/out`, `resize`, `title-changed`,
  `cwd-changed`, `host-changed`, `foreground-changed`, `prompt-start`, `command-started`,
  `command-finished`, `output-idle` (silence), `output-activity`, `pane-opened/closed`,
  `tab-opened/closed`, `window-opened/closed`, `user-var-changed`, `progress-changed`,
  `notification`, `config-reloaded`, `theme-changed`, `media-*`, `startup`, `output-match`
  (R2).
- Rules are evaluated on the main thread, in file order, non-reentrantly: actions run by
  a rule do not synchronously trigger further rules; events they cause are queued, with a
  per-rule rate limit (default 10/s) and a global loop guard.
- **Consent** (SECURITY-24). Every event is *program-triggered* except the trusted set:
  `startup`, `config-reloaded`, `theme-changed`, `focus-in/out`, `resize`,
  `pane-opened/closed`, `tab-opened/closed`, `window-opened/closed` — and those only when
  caused by the user or the user's config, not by an escape sequence or a socket client
  (a socket-caused event is program-triggered). The check is by capability class, not by
  Action name, with macros expanded first: a rule on a program-triggered event may
  dispatch only Actions whose class is `observe`, `layout` or `appearance`. Classes
  `input` and `clipboard` need `allow-input=#true`; `spawn` needs `allow-spawn=#true`;
  `read-content`, `config-write` and `keys` are never allowed (a `notify` template over
  event fields is `layout`). Validated at load; a violation drops the rule with a
  diagnostic carrying the rule's file and line.
- An opted-in rule additionally needs **confirm-once**: its first firing opens a glass
  sheet showing the rule name, trigger and the fully expanded argv or input in a
  bounded monospaced box; the sheet ignores Return and activates only on an explicit
  choice (allow for this instance / allow always / disable rule). The answer is stored
  keyed by a hash of the rule's text; editing the rule asks again.
- Stock rules ship in `/etc/eclipse/apotheosis.kdl`: long-command notification
  (threshold 60 s, only when unfocused; `notify` only, so no opt-in is needed).
- `output-match` (R2): linear-time regex on completed logical lines, off the io thread,
  bounded backlog.

## 6. Profiles
A profile is a named bag of any keys marked `profilable` (window, tab or pane scope,
T-10 §1) plus `shell`, `env`, `cwd`, `binds`. `inherits` gives single inheritance (cycle-checked). A profile is chosen
(a) explicitly (`launch profile=`, palette, default-profile), or (b) automatically by
`match` blocks scored additively (exact host 16, wildcard host 8, job 4, user 2, exact
path 1; ties by file order) and re-evaluated on `cwd-changed`, `host-changed`,
`foreground-changed`. Automatic switching applies only the profile's `appearance`-class keys
(T-10 §1.1) and its `binds` to a live pane (never `shell`/`env` or any `behaviour`,
`security` or `grant` key), restores on un-match, and never overrides a value the
user changed at runtime in that pane.

## 7. Match language
One grammar wherever something is selected (rules `where`, socket targets, profile
matches, `launch --match`): terms `field:pattern` joined by `and`, `or`, `not`,
parentheses. Fields: `id`, `title`, `pid`, `cwd`, `cmdline`, `process`, `host`, `user`,
`profile`, `tab`, `window`, `workspace`, `state` (`focused`, `active`, `zoomed`,
`bell`, `running`), `var:<name>`, `env:<name>`, plus event fields (`status`, `duration`).
Patterns are anchored globs by default, `~regex` for regex, numeric comparisons for
numeric fields. Relative tokens: `self`, `last`, `next`, `prev`, `left|right|up|down`,
`marked`. It is a filter language with no assignment, calls or loops.

## 8. Templates
Tab titles, window titles, badges, status segments and notification text use one small
typed format language: `{var}`, filters (`|basename`, `|truncate:20`, `|default:"…"`),
and `{if cond}…{else}…{end}` over the same fields as §7. No loops, no user functions.
It is specified by a grammar in the generated reference and has a fuzz target.

## 9. Variables
`OSC 1337 ; SetUserVar=name=<base64>` sets a per-pane variable (≤ 64 names × 1 KiB);
`var.set` Action and socket set variables at pane, tab, window or global scope. Variables
are readable in templates and the match language and raise `user-var-changed`.

## 10. Test Plan
Registry completeness test (every variant has a dotted id in a §1 family, title, doc and
capability class, and is reachable from palette and socket; no consent or sheet answer
has an id); bind-bypass test (`input.send-keys` of a bound chord does not fire the bind);
macro class-union test; rule consent tests per class (a `user-var-changed` rule running
a macro that wraps `launch`, `capture` to a command, or `pane.split` with a command is
dropped without `allow-spawn`; confirm-once sheet ignores Return); bind-resolution tests (physical vs symbol, tables,
sequences, consume-release); argv placeholder tests proving no re-splitting; rule engine
tests (ordering, loop guard, consent refusal); profile scoring tests; match-language and
template parser fuzz targets; headless gate driving 20 representative actions by key,
palette and socket and asserting identical effects.

# T-12 — Control Socket & CLI (Draft v0.2)

Crates: `apoth-proto` (Apache-2.0 wire types), server in `apotheosis`, client `apoth`.
Implements AUTOMATION-20..22, -36, -37, INTEGRATION-15, REMOTE-01..03, -05, -06,
SECURITY-21, -23 (must); SECURITY-22, AUTOMATION-23, -38, -39, INTEGRATION-06, -17..-20,
REMOTE-04, PACKAGING-02 (should). Policy: ADR 0116.

## 1. Transport
- Unix stream socket `$XDG_RUNTIME_DIR/apotheosis/<instance>.sock`; directory `0700`,
  socket `0600`; startup refuses a directory not owned by the user or with group/other
  bits. `SO_PEERCRED` uid must equal ours. No TCP, no abstract namespace, no forwarding.
- **Peer identity** is taken once, at `hello`, and bound to the connection: a pidfd from
  `SO_PEERPIDFD`; on kernels without it, `pidfd_open(SO_PEERCRED.pid)` followed by
  re-reading `SO_PEERCRED` and checking the process start time in `/proc/<pid>/stat`
  against a read taken before the pidfd (a mismatch refuses the connection). From the
  pidfd are derived, also once: the executable (`/proc/<pid>/exe`), pane ancestry, and
  agent membership (§4.1); every `/proc` read is followed by a pidfd liveness check, so a
  reused pid cannot answer. Grants are evaluated per request against this identity; a
  connection whose peer pidfd has exited is closed. A connection fd passed to another
  process (`SCM_RIGHTS`) keeps the connecting peer's identity: a cooperating peer is that
  process's deputy, which the terminal cannot detect, and this is why agent
  identification (§4.1) rests on cgroup membership, which an agent cannot leave.
- Framing: newline-delimited JSON, UTF-8, one object per line, ≤ 1 MiB per line.
  Request `{"id":n,"method":"…","params":{…}}`; reply `{"id":n,"ok":…}` or
  `{"id":n,"error":{"code":"…","message":"…"}}`; events `{"event":"…","seq":n,…}` are
  separate lines and never interleave inside a reply.
- Handshake: first message `hello {proto, client, want:[caps]}` → `{proto, version,
  granted:[caps], features:[…]}`. Unknown methods and fields are errors, not ignored.
- The listener and client streams are sources on the main loop; anything slow goes to
  the pool. Per-client output buffers are bounded; a client that stops reading is
  disconnected after the high-water mark (SECURITY-32).
- systemd socket activation (`LISTEN_FDS`) is accepted (R2).
- The R2 server attach socket (T-21 §3) uses the same directory, modes and peer checks; attach requires `read-content` + `input` per pane under §4.

## 2. Methods
`action.run {action, target}` runs **any** registry Action — the socket has no separate
command set to drift — under that Action's class (T-11 §1). Consent and sheet answers
are not registry Actions (T-11 §1) and no method reaches them; `action.run` with such a
name fails as an unknown action. `input.send-keys` encodes straight to PTY bytes with
`apoth-input` and never enters bind lookup, key tables or interface focus, so it cannot
fire a bind or reach any glass surface. Queries: `tree` (windows → tabs → panes with ids, titles, cwd,
foreground process, size, state), `pane.info`, `pane.processes`, `pane.text {extent,
sgr, wrap}`, `pane.blocks` (command records), `config.get`, `config.effective`,
`keyboard.state`, `graphics.list`, `media.list`, `wayland.info`, `render.status`,
`version`. Streams: `subscribe {events:[…], match}` / `unsubscribe`; `pane.watch`
(rendered-row deltas, R2).

Media windows (`apoth icat --ext`, T-16 §1.1), class `layout`, not targeted:
- `media.window-open {cols, rows, title?}` opens a borderless glass window with one grid
  of `cols` × `rows` cells (each 1..500) and returns `{window}`. It has no PTY. It belongs
  to the connection: it closes when the connection closes. At most 8 are open at once.
- `media.window-write {window, data}` feeds base64 `data` (at most 768 KiB of base64 per
  request) to the window's grid. Only the owning connection may write. The grid parses and
  decodes off the main loop. A window more than 64 MiB behind refuses writes.
- `media.window-wait {window}` is answered with `{closed: true}` once the window has
  closed (Escape or `q` in it, the compositor's close, or a render failure).

## 3. Targeting and environment
Targets use the T-11 §7 match language; default target is `self` when the client runs
inside a pane. Each pane exports `APOTHEOSIS_SOCKET`, `APOTHEOSIS_PANE`,
`APOTHEOSIS_WINDOW`, `APOTHEOSIS_VERSION`. Ids are opaque, stable for the life of the
object, and never reused within an instance.

## 4. Capabilities
Every method and Action has a capability class (or a pair, all required); the
Action → class mapping is the T-11 §1 family table, and a macro needs the union of its
members' classes (T-11 §4).

| Class | Covers | Default for a same-uid, non-agent client |
|---|---|---|
| `observe` | tree, info, versions, config read, non-content events; content-bearing fields (pane title, cwd, foreground argv from `pane.processes`, OSC 133 command text in events, `config.effective` values under `env`) are returned as `null` to peers that are (descendants of) agent sessions unless `read-content` is granted for that pane, and to all peers while the pane is in the credential state (T-17 §5) | granted |
| `layout` | navigation, close, move, focus, resize, tabs, windows, workspaces, `layout.*` without argv, notify (T-11 §1) | granted |
| `appearance` | `config.set` of keys whose override class is `appearance` (T-10 §1.1), theme, font size, `config.reload` | granted |
| `spawn` | `launch`, `pipe`, `open`, `config.open`, `capture`/save to a destination, any Action carrying argv (incl. `layout.apply` of an argv-carrying layout) | **granted only to clients whose peer is a descendant of one of our panes** (the user's own shell) and is not a remote client (below); otherwise ask |
| `read-content` | pane text, blocks, watch, selection | ask (consent sheet naming the client executable), unless descendant-of-target-pane reading itself |
| `input` | send-text/bytes/keys, paste, broadcast | ask, unless the target is the client's own pane |
| `clipboard` | read/write clipboard via the terminal | ask |
| `keys` | key-event stream | per-pane opt-in `socket.key-stream` (pane scope, profilable, override class `grant`) in config only; never grantable by prompt; suppressed while the pane is in the credential state and for remote panes unless the profile sets `security { remote-keys #true }` (T-17 §5); never logged |
| `config-write` | `config.persist`, `config.save-override`, `config.set` of `behaviour` keys | ask; a `security` key's sheet shows the KDL diff; `grant` keys are never writable over the socket (T-10 §1.1) |

`socket.grants` (`Map<Path, StringSet>`, override class `grant`) can pre-grant classes by
executable path; it cannot name `keys`, and the validator rejects an entry whose path is
an interpreter (below). Consent answers are cached per (executable path, class) for the
instance lifetime or persistently if the user chooses — except for **interpreters**
(`python*`, `node`, `deno`, `bun`, `perl`, `ruby`, `php`, `lua*`, `sh`, `bash`, `zsh`,
`fish`, `nu`, `dash`, `env`, `busybox`; `socket.interpreters` can only extend it), for which
consent is asked per connection and never cached or pre-granted. A peer whose executable
is on the remote-client list (T-18 §10) never gets descendant-of-pane privileges, so a
user-run `ssh -R` forward of the socket is treated as an ordinary client.

### 4.1 Agent peers
- A peer is an **agent peer** when its cgroup (read via the pidfd from
  `/proc/<pid>/cgroup`, §1) is under `agents.slice/` (VOL1 Threat Model §7, Sandbox
  Baseline: every agent process runs in `agents.slice/agent-<id>.slice`). The test runs
  on every host and does not depend on Abyss detection (T-17 §1): losing the Abyss or
  policy connection never turns it off.
- An agent peer gets nothing by default except `observe`. Descendant-of-pane privileges,
  `socket.grants` pre-grants and cached consent never apply to it. Every other class is
  refused unless the policy service allows the equivalent seat operation for that agent:

  | Class | Asked as (S-01 §2) |
  |---|---|
  | `input` | `seat.text` / `seat.key`, target app id `org.eclipseos.Apotheosis` |
  | `read-content` | `scene.text` |
  | `clipboard` | `clipboard.read` / `clipboard.write` |
  | `spawn` | `launch.shell` (a pane process runs outside the agent's sandbox) |
  | `layout`, `appearance` | `seat.action` |
  | `config-write`, `keys` | never; refused without asking |

- The query is made by asking, not by guessing: it goes to the fixed path
  `/run/user/<uid>/eclipse/policyd.sock`, computed from our uid (never from the
  environment), and the server is accepted only when it authenticates the way abyss
  authenticates policyd (`SO_PEERCRED` uid and membership of the `ec-policyd.service`
  cgroup, ADR 0070 — or the policyd system user once policyd moves there). No reachable
  or authenticated policy service, a timeout, or an unknown answer ⇒ deny. Until COMP-11
  defines this query, every agent-origin request outside `observe` is denied
  (ADR 0116). The socket must never be a way around `check()`.

## 5. CLI
`apoth <group> <verb>`; every group maps to methods above: `apoth ls`, `launch`, `split`,
`focus`, `close`, `send-text`, `send-keys`, `get-text`, `do '<action>; <action>'`
(textual action syntax identical to KDL `do` bodies), `subscribe`, `notify`, `set`/`reset`
(runtime overrides: `config.set`/`config.reset` over the socket, class per the key's
override class), `config …` (T-10 §8: edits or reads the file locally, no socket), `icat` (foreground,
inline by default, `--ext` for a separate window; lifetime rules in T-16 §1.1), `play`, `ssh` (R2), `shell-init`, `terminfo`, `fonts`
(`list`, `explain <char>`), `doctor` (capability and environment report), `completions`.
`--json` everywhere; exit codes: 0 ok, 1 error, 2 usage, 3 denied, 4 no instance.
Inside Apotheosis panes the shell-integration snippets (T-14 §2) define `ap` as a short
alias of `apoth`; nothing is installed system-wide, and no other short names are defined.

launch sends one `launch` request (cwd, env, argv, activation token, overrides) to the
running instance and, with `--wait`, relays the child's exit code.

# T-13 — Mux (Draft v0.2)

Crate: `apoth-mux` (AGPL-3.0-only; pure data + traits). Implements MUX-01, -02, -04, -11..-18,
-22..-24, -28, -30, -41.

## 1. Model
```
Session ── Workspace* ── Window* ── Tab* ──┬─ tiled: split tree of Pane | Stack
                                            └─ floating: ordered list of Float(Pane)
```
All of it is plain data owned by one `Session` value on the main thread; children are
referenced by `u64` ids. A Wayland window is a *view* of a `Window`; nothing in
`apoth-mux` knows about Wayland or wgpu. This separation exists from M22 so that the
daemon (T-21) is a relocation of the `Session`, not a rewrite.

## 2. Domains
`trait Domain { spawn, split, attach, detach, list }` and `trait Pane { feed-side handle,
write, resize, info }`. R1 ships `LocalDomain` only. R2: `UnixDomain` (T-21), `SshDomain`
(T-22), `ExecDomain` — a declarative argv/env *template* that wraps every spawn in the
domain (`docker exec`, `distrobox enter`, `kubectl exec`); no callback (MUX-32). An ExecDomain pane uses the remote column of T-18 §3 unless its domain block overrides it with `security { }`.

## 3. Layout
- Binary split tree; each node has orientation and a fraction; sizes resolve to cells
  with minimum sizes (2×1). Actions (`pane.*`, T-11 §1): `pane.split` (direction, size,
  cwd, profile, command — class `spawn` when `command` is given), `pane.close`,
  `pane.focus` (direction / next / previous / last), `pane.swap`, `pane.move`,
  `pane.rotate`, `pane.resize` (direction, amount), `pane.equalize`, `pane.zoom`
  (toggle), `pane.break-to-tab`, `pane.break-to-window`, `pane.join`.
- **Stacks** (MUX-17): a tree leaf may hold N panes, one expanded and the rest shown as
  one-line headers.
- **Floating layer** (R2, MUX-18..20): per-tab ordered floats with show/hide, pin,
  raise-on-focus, embed/float toggle, placement search.
  - Actions: `pane.float` (cwd, profile, command — class `spawn` when `command` is given)
    opens a float. `pane.toggle-float` floats the focused tile or embeds the focused float.
    `pane.toggle-floats` shows or hides every float of the tab. `pane.toggle-pin` pins a
    float, keeping it shown when the floats are hidden.
  - Placement: a new float is half the tab, centred. If that spot is taken by a shown
    float, it tries the top-left and top-right corners in (2, 1)-cell steps, then staggers
    from the top left.
  - A float takes no room from the tree. It is always framed and draws over the tiles on
    its own glass backing and shadow layer. Floats are hit-tested before the tiles, top
    float first.
- **Layout presets** (MUX-13): `even-h`, `even-v`, `main-h`, `main-v`, `tall`, `grid`,
  `stack` applied over the pane list; `layout.next` cycles. The free tree is the default.
- New panes inherit the focused pane's cwd (OSC 7, else `/proc/<fg>/cwd`).
- Unfocused panes are dimmed by `panes.inactive-dim` (default 0.12).

## 4. Tabs, windows, workspaces
Tabs (`tab.*`): new, close, move, rename, focus by index/relative/MRU, detach to window.
Windows carry a workspace name; `workspace.switch` maps and unmaps windows. Closing asks for
confirmation when a foreground job other than the shell is running
(`close.confirm` `never|if-running|always`). `panes.remain-on-exit` `never|on-failure|always`
keeps a dead pane with its exit status; Enter re-runs.

## 5. Broadcast input
`broadcast.set {mode}` (class `input`), modes `off|tab|window|selected`. A persistent
indicator is drawn on every receiving pane.
- While the **source** pane is in the credential state (T-17 §5), broadcast is
  suspended: keystrokes go only to the source, and the indicator shows "paused". It
  resumes on the next sample that leaves the credential state.
- A **receiver** is excluded while it is in the credential state or its toplevel
  sensitivity is `secret`, in every mode, including `selected` and modes spanning
  windows.
- Broadcast out of a remote pane requires confirmation per broadcast session (T-17 §5).

## 6. Layout files and session save
- Named layouts are KDL (`layout "dev" { tab { split … } }`): tabs, tree, cwd, command
  argv, profile, focus. `layout.apply` (class `spawn` when the layout carries any command
  argv, else `layout`; T-11 §1), `layout.save`.
- R2: periodic session serialisation (default 60 s when dirty) with atomic writes
  (temp, fsync, rename, keep last good). Layout and cwd only by default; pane *contents*
  are never saved unless T-21 §5 is enabled.
- Undo close (R2): closed tab/pane restorable for `close.undo-timeout` (default 5 s); the
  process is kept alive hidden until expiry.

## 7. Test Plan
Tree-operation property tests (sizes sum, minimums hold, focus neighbour is symmetric);
layout KDL round-trip; headless screenshot goldens for 1/2/3/4-pane presets and a stack;
broadcast exclusion test for `secret`; credential-source test: a broadcast group in
`selected` mode spanning two windows, with a fixture that clears `ECHO` (keeps `ICANON`)
in the source, delivers no bytes to any other pane.

## 8. Open Decisions
- tmux control-mode client domain (MUX-33, should): R2 or never, by demand.

# T-14 — Shell Integration & Navigation (Draft v0.2)

Lives in `apoth-term` (marks, blocks), `apoth-grid` (search iterator), `apotheosis`
(overlays). Implements SHELLINTEGRATION-01..03, -05, -07..-10, -13, -15, -16, -20, -21, -30,
NAVIGATION-01, -02, -05..-08, -12, -14, -15, -17..-19, -28, -29, -32,
SCROLLBACKSEARCH-09..13, -17, -19, -31.

## 1. Marks and blocks
- OSC 133 `A` (prompt start), `B` (input start), `C` (output start), `D[;status]` (end),
  `L` (fresh line), `P` (prompt row). Options are `key=value` after the mark, per mark
  (SHELLINTEGRATION-05):

  | Mark | Options |
  |---|---|
  | `A` | `redraw=0\|1`, `special_key=0\|1`, `k=i\|r\|c\|s`, `click_events=0\|1\|2`, `cl=<mode>` |
  | `C` | `cmdline=<shell-quoted>`, `cmdline_url=<percent-encoded>` |
  | `P` | `k=i\|r\|c\|s` |
  | `B`, `D`, `L` | none |

  Unknown keys and keys given on the wrong mark are ignored; a malformed value ignores
  that key only. OSC 633 and OSC 1337 `SetMark` map onto the same marks (R2).
- `L`: if the cursor is not in column 0, perform CR LF first (no-op otherwise); it opens
  no block.
- **Continuation prompts.** `A;k=c`, `A;k=s` and `P;k=c|s` mark the current row as a
  continuation-prompt row inside the current input zone; they never start a new block
  and never trigger the `A`-after-`A` rule. `k=i` (or no `k`) is a primary prompt; `k=r`
  is a right prompt, recorded as prompt cells of the current row.
- The transition machine is lenient: a primary `A` after a primary `A` with no input
  discards the empty prompt; `D` with no running block is ignored; a nested shell's
  primary `A` implicitly ends the outer block.
- Each row carries a `u32` block id; the block store keeps the last 1000 command records
  per pane: state, prompt/input/output pin ranges, exit status, start and end time, cwd.
  Cells carry the 2-bit semantic class (T-02 §1.2).
- **Command-line text** (`cmdline=`) is held in memory only, never written to disk, logs,
  session files or the semantic tree; it is available to rules as a match field.

## 2. Shell integration delivery
Snippets for bash, zsh and fish are embedded data assets (T-00 §3.3), each ≤ 8 KiB,
injected without editing rc files: zsh by a temporary `ZDOTDIR` shim that restores the
user's value; bash by `--rcfile` shim / `PROMPT_COMMAND`; fish and nushell through
`XDG_DATA_DIRS`. `shell-integration.enabled` `auto|off`; feature flags `cursor`, `title`,
`cwd`, `marks`, `sudo-terminfo`. Shells that emit OSC 133 natively need nothing.
`apoth shell-init <shell>` prints the snippet for manual use.
Each snippet defines `ap` as an alias of `apoth` (T-12 §5), only when `APOTHEOSIS_PANE`
is set, so a manually sourced snippet has no effect outside a pane.

## 3. Working directory and process
OSC 7 (`file://host/path`, percent-decoded; non-local host ignored for local spawns) is
primary; `/proc/<pid>/cwd` of the foreground process group leader (`tcgetpgrp`) is the
fallback. `/proc/<pid>/stat` is parsed from the last `)`. Foreground process name and
argv feed profiles and rules (T-11). Foreground process and cwd are sampled from /proc only on events: an output-idle edge (first 200 ms without output after output), focus or tab switch, an OSC 133 mark, a binding or rule evaluation that needs them; never on a period.

## 4. Actions on blocks (R1)
`block.jump` (previous/next/first/last, count), `block.select-output`,
`block.copy-output`, `block.pipe-output` (argv), `block.open-output` (pager argv) — each
for the last or Nth block — and `block.copy-command`; classes per T-11 §1. Scrollbar pips
per block coloured by exit status, and the
`command-finished` event (status, duration, cwd). Click-to-move-cursor inside the input
zone is R2.

## 5. Hyperlinks
OSC 8 links: hover underline and URI tooltip; activation requires the open modifier
(`links.open-modifier`, default Ctrl) or a hint. Schemes are allow-listed
(`links.schemes`, default `http https mailto ftp file`); `file://` with a non-local host is
refused; the full URI is shown before opening when it differs from the visible text
(T-18). Opening goes through the `open` Action with an argv template (default
`xdg-open {url}`); a link's default handler, the Open menu and the picker are §11.

## 6. Search
- Overlay search bar (glass, T-08). Modes: smart-case (default), case-sensitive,
  insensitive, regex; whole-word; scope `all|screen|selection|block`.
- Engine: `regex-automata` hybrid DFA over logical lines (wrapped rows joined) with an
  offset → pin map; matches may span wraps.
- A worker searches history newest-first in time-budgeted slices against page snapshots;
  history results are cached as immutable, the active area is re-searched when dirty.
  Typing debounces 150 ms. Match count and progress are shown; matches are ticked on the
  scrollbar; the current match is a tracked pin pair so `n`/`N` are stable under output.
- History is read one page per term-lock hold (T-07 §1); a page whose wrap_width differs from the current width is converted first (T-02 §3).
- Hard guard: pattern compile size limit and a per-page time budget; an over-budget
  pattern reports an error instead of stalling.

## 7. Hints
`hints.start` Action (optionally naming a matcher set): snapshot the viewport, run the enabled matchers (built-in: URL, path with
optional `:line:col`, git hash, IP, UUID, OSC 8 links; user regexes in KDL), assign
prefix-free labels from `hints.alphabet`, and run the matcher's Action on the typed label
(`open`, `copy`, `paste`, `select`, any Action with `{match}`), checked under that
Action's own class (T-11 §1). Trailing punctuation and
unbalanced brackets are trimmed and the trimmed span re-validated.

## 8. Copy mode
A built-in key table over a cursor pin and pure motion functions `(grid, motion) → pin`:
char/line/word/WORD, line ends, screen H/M/L, paragraph, prompt and block motions, `f/t`
jumps, search `n/N`, visual/line/block selection, yank. Default tables `vi` and `emacs`;
both are ordinary KDL key tables and fully rebindable.

## 9. Command palette
One overlay, modes `actions | tabs | workspaces | layouts | profiles | hints-history`,
fed by composable sources. Every `Action` appears with its generated name and current
binding. Scoring is an fzf-v2-class algorithm implemented from its published description.
`>` prefix switches mode. R2: launch-menu items, recent directories by frecency.

## 10. Export
`capture` Action: extent (`screen|scrollback|selection|last-output|block`) × destination
(`clipboard|file|pager|editor|command argv`), with or without SGR. Class `read-content`
plus `clipboard` for the clipboard destination and `spawn` for every other (T-11 §1).

## 11. Open with
Anything the terminal recognises as a path or URL can be opened with a chosen app: hint
targets (`path`, `url`, `link`), OSC 8 links, a right click on a recognised path or URL
(`menu.context-menu`, when nothing is selected), a selection (copy mode included) and the
`open.*` Actions, which the socket, binds and palette reach like any other (T-11 §1).
Never automatic: nothing opens on output.
- **Actions.** `open.default {target?, placement?}` launches the default handler;
  `open.menu {target?}` shows the Open menu; `open.with {target?}` shows the picker. A
  target is at most 4096 bytes with no control characters. With no target the selection
  is the target; with nothing selected, hint mode starts with the `link`, `url` and `path`
  matchers and the picked label carries the Action's intent. A hint label typed in upper
  case (Shift, with a lower-case alphabet) opens the menu for that target instead of the
  matcher's default; the URL and link defaults open through the default handler, the path
  default still copies. Default bind: `ctrl+shift+m` → `open.menu`.
- **Menu.** On the palette sheet: "Open with <default>" (the handler named, e.g. "Open
  with Firefox", "Open with apoth icat in a float"), "Open with…" (the picker), for a
  terminal handler the other placements (inline split, float, separate window via
  `--ext`), then "Copy" / "Copy link" and "Copy path" (the absolute path when it differs
  from the text). The target is shown as program text.
- **Picker.** The terminal handlers for the type, then the desktop apps that declare the
  type (or a parent type), then `links.open-command`, then every other shown desktop
  app, fuzzy-filtered by the palette's scorer (§9). A pinned "Remember for <type>" toggle
  writes an `open.handlers` entry for the exact type of the target on the pick (T-10 §3)
  and reloads.
- **Type.** URLs: `x-scheme-handler/<scheme>`; a `file://` URL naming this host is its
  path. Paths: `~` and relative paths (against the pane's OSC 7 directory) made absolute;
  a `:line[:col]` suffix is dropped when the full text does not exist. A directory is
  `inode/directory`; a FIFO, socket or device is never opened for reading. A regular file
  is typed by the shared-mime-info database (`globs2`, `magic`, `subclasses`, `aliases`
  under `$XDG_DATA_HOME/mime` and `$XDG_DATA_DIRS/*/mime`, read in Rust; a built-in table
  when none is installed): the first 8 KiB sniffed, magic winning over a weaker or
  conflicting glob, text vs binary by content.
- **Default handler**, first that applies: an `open.handlers` entry (exact type, then
  `type/*`, then the same along the parent types); the built-ins for local files,
  `image/*` → `apoth icat` and `video/*`, `audio/*` → `apoth play`, shown at
  `open.placement`; for a URL, `links.open-command` when the user set it; the
  freedesktop default (`mimeapps.list` per the XDG MIME Applications spec:
  `$XDG_CONFIG_HOME`, `$XDG_CONFIG_DIRS`, then `applications/` under the data dirs, each
  `<desktop>-mimeapps.list` before `mimeapps.list`; Default Applications only from the
  desktop-specific files; Added/Removed Associations apply to their directory and below; a
  default must be installed (`TryExec`) and not hidden; a type is settled before its
  parents); else, for a URL, `links.open-command`. A local file with no default after that
  opens in the **default browser** (`x-scheme-handler/https`, then `http`; its `Exec` gets
  the percent-encoded absolute `file://` URL as one argv element through `%u`/`%U`), but
  only for types a browser renders: `image/{png,jpeg,gif,webp,avif,svg+xml,bmp}`,
  `video/{webm,mp4,ogg}`, `audio/{mpeg,ogg,opus,flac,wav,webm,aac}`, `application/pdf`,
  `application/xhtml+xml`, `text/html`, `text/plain`. Any other type has no default, and
  `open.default` shows the Open-with picker instead of doing nothing. The menu names the
  effective default ("Open with Firefox" when the browser is the fallback).
- **`apoth play` fallback.** `apoth play` exits 69 (`EX_UNAVAILABLE`) for media it cannot
  play; a build without `play` exits 2 (usage). On either, the opener launches the
  freedesktop default (else the browser for a renderable type, else nothing) instead: from a pane when the pane
  closes, from a `--ext` launch when the process exits.
- **Launch.** Always an argv, never a shell. Desktop `Exec` lines are unquoted and
  unescaped per the Desktop Entry spec, then field codes expanded: `%f`/`%u` one target,
  `%F`/`%U` the list (alone as an argument), `%i` the `--icon` pair, `%c` the name, `%k`
  the entry's path, `%%`; deprecated codes dropped. A field code inside quotes, an unknown
  code, two file codes or a list code not standing alone makes the entry unusable; an
  `Exec` without a file code gets the target appended; `%f` with a non-`file` URL is
  unusable (nothing is downloaded). Paths passed are absolute, so they never read as
  options. Terminal handlers and `Terminal=true` apps run in a new pane (split or float);
  other apps detached, without the activation token variables.
- **Security (T-18).** A link target passes the §5 checks first. A path from a remote
  pane (T-18 §10, or an OSC 7 directory naming another host) is never opened locally: the
  menu shows Open and Open with… disabled with "path is on <host>"; Copy stays. Paths, URLs
  and file contents are never logged; the host label is program text, filtered to
  `[A-Za-z0-9.-]`, at most 64 bytes.
- Tests: type detection (globs, magic, subclass chain, text/binary), `mimeapps.list`
  precedence (user over system, Added/Removed, desktop-specific files), `Exec` expansion
  and escaping, remote-path refusal, the remember write, and a headless gate opening an
  image path's hint into an `apoth icat` float.

## 12. Test Plan
Corpus fixtures for the OSC 133 machine including sloppy-shell traces recorded from bash,

(the primary block survives); option-parsing tests (per-mark keys, unknown and

test (catastrophic pattern returns an error within 50 ms); label allocation property test

hints and palette; the §11 tests.

  the bits are reserved either way.

# T-15 — Graphics (Draft v0.2)

Crate: `apoth-image` (AGPL-3.0-only; deps `png`, `gif`, `zune-jpeg`, `image-webp`,
`miniz_oxide`, `base64`). Implements GRAPHICS-01..04, -06..-18, -21, -23, -26, -27, -33,
-34, -39..-44, RENDERING-35..37, PERFORMANCE-51..53.

## 1. Kitty graphics protocol
Implemented from the published protocol specification only; kitty's source is not a
reference for this crate (T-00 §3.4). All pixel inputs (source rectangles, X/Y offsets, s/v sizes) are physical buffer pixels per T-03 §3.1 (pixel space).
- **R1**: transmission `d` (direct) with chunking (`m=1`, ≤ 4096 base64 bytes per APC),
  formats `f=24|32|100`, `o=z`; actions `t`, `T`, `p`, `d`, `q`; ids `i`, numbers `I`,
  placement ids `p`, quiet `q=1|2`; source rect, cell box `c,r`, sub-cell offsets `X,Y`,
  `C=1`; z-index incl. the below-background range; **Unicode placeholders** (`U=1`,
  U+10EEEE with row/column/id diacritics, id in fg colour); full delete selector set;
  responses and error codes as specified.
- **R1, local panes only**: transmission `f` (file), `t` (temp file, must be under a
  known temp dir and contain `tty-graphics-protocol`), `s` (POSIX shm). Refused for
  remote panes (T-18 §10) and when `graphics.file-transmission` is `off`; otherwise
  decided by the `graphics: file / temp / shm media` class (T-18 §3, local default `ask`).
- **File opening rules** (`f`, `t`; `s` uses `shm_open` with the same checks): open with
  `O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC`; paths under `/proc`, `/sys` and `/dev` are
  refused before opening; `fstat` must report a regular file (`S_ISREG`); the size is
  checked against the decoded-size and quota caps (§4) before any read. Every failure of
  these checks — not found, permission, wrong type, oversize — produces one identical
  reply (`ENOENT`), so the reply never tells a program whether a path exists. A
  transmission denied by policy has no effect and no reply (T-18 §11).
- **R2**: animation (`a=f`, `a=a`, `a=c`: frames, composition, gaps, loop control),
  relative placements (depth ≤ 8, cycle check).
- Auto-assigned ids come from the upper half of the u32 space so they never collide with
  client ids.

## 2. Sixel
All pixel inputs (sixel raster, kitty source rectangles, X/Y offsets, s/v sizes) are physical buffer pixels per T-03 §3.1 (pixel space).
Our own streaming decoder (state machine with limits built in): colour registers RGB/HLS,
repeat, raster attributes; decoded-pixel cap independent of the byte cap.
XTSMGRAPHICS reads and sets colour registers (≤ 1024; out-of-range clamps) and geometry,
and reports the configured caps (GRAPHICS-18). Decoded images are stored as cell-row
slices so scroll, erase and overwrite are slice bookkeeping. R1 (foot parity).

| Mode / parameter | Default | Semantics |
|---|---|---|
| DECSDM `?80` | reset | **reset** (scrolling on): image drawn at the cursor; rows scroll as needed; afterwards the cursor is on the row below the image's last row, in the image's start column — or, when `?8452` is set, on the image's last row, one column right of the image. **set** (scrolling off; xterm ≥ patch 369 polarity): image drawn at the screen's home position, never scrolls (rows below the screen are clipped), cursor unchanged. |
| `?1070` private colour registers | set | set: each image starts from its own fresh register set; reset: registers are shared and persist across images. |
| `?8452` sixel cursor right | reset | see DECSDM reset. |
| P2 = 1 | — | pixels not written are transparent. |
| P2 = 0 or 2 | — | pixels not written are filled with the pane's current background colour. |

All three modes are listed in the T-03 §2 mode table and answer DECRQM.

## 3. iTerm2 inline images
OSC 1337 `File=` with `inline=1` only: `name`, `size`, `width`, `height`
(cells, px, %, auto), `preserveAspectRatio`. `inline=0` (download) is refused. R2.

## 4. Store, quota, lifetime
- One store per pane, partitioned main/alternate screen; alternate-screen images vanish on
  exit and never reach history.
- One byte budget across kitty, sixel and iTerm2 images: `graphics.quota` (default
  320 MiB per pane) and `graphics.quota-total` (default 1 GiB per process); animation
  frames have a separate `graphics.animation-quota`. Eviction is tiered: unreferenced
  first, then off-screen placements oldest first; a referenced on-screen image is never
  evicted — the transmit fails with `ENOSPC` instead.
- Per-axis cap 10 000 px; decoded-size cap enforced before allocation.
- Placements are anchored to buffer rows (tracked pins), scroll with text, reflow by
  re-anchoring, and are freed when their rows leave history.
- Identical payloads share one decoded image (content hash).

## 5. Decoding
Never on the io thread. PNG/JPEG/GIF/WebP decode on the worker pool with output caps and
returns by channel. From M34 on, all untrusted image decode moves into the sandboxed
media helper (T-16 §4) when `graphics.sandbox-decode` is `#true` (default once available).

## 6. Rendering
One textured quad per placement in the pass given by its z; adjacent placeholder cells
with consecutive coordinates merge into one quad; animation frames upload only the changed
rect.

## 7. Capability reporting
`a=q` query; DA1 attribute 4 (sixel); `CSI 14/16/18 t`; cell-size report `CSI 16 t`.

## 8. Test Plan
Protocol fixtures written from the specification's examples (one per action × medium ×
format, each error code); sixel corpus (hand-written cases for every control function plus
generated images round-tripped through an independent encoder in the test harness); fuzz
targets `kitty_apc`, `sixel`, each decoder wrapper; quota and eviction tests; placeholder
merge test; headless screenshot gates (`apoth icat` of a fixture image; `chafa`-style
sixel output file replayed).

## 9. Open Decisions
None.

# T-16 — Media (Draft v0.2)

Crates: `apoth-media` (helper process `apoth-media-helper`, AGPL-3.0-only) and the client
side in `apotheosis`. Implements MEDIA-01..03, -05, -07..-10, -13, -15..-17, -20, -22, -23,
-26..-29, PERFORMANCE-54..56, -62. Scope and exceptions: ADR 0118.

## 1. Tiers
| Tier | Content | Release |

### 1.1 `apoth icat` and `apoth play` lifetime
Owner requirement (recorded at M32 for `icat`, binding on `play` at M34):
- **Inline by default.** The command runs in the foreground of the pane it was started
  in. Animations (and, for `play`, video) stay live while it runs. Ctrl+C deletes the
  command's own placements, restores the tty and exits 130. A still image from a normal
  exit stays in the scrollback; animations and video are removed when the command ends,
  however it ends.
- **Terminal-side cleanup.** A placement must never outlive a command that died without
  cleaning up (SIGKILL: no frozen frame is left). The command opens a session in-band,
  `ESC _ M a=b,i=<n>,p=<pid> ESC \` (`n`: a per-invocation id; `p`: the command's pid),
  before its first image and closes it with `a=e,i=<n>` on a normal exit. Placements made
  while a session is open belong to it. A clean `a=e` keeps the session's still images and
  deletes its animated ones. Other `M` commands are the §2 protocol.
  - With `p=`, the terminal binds the session to that process when it is in the pane's
    session (`getsid(pid) == tcgetsid(pty)`): it opens a pidfd and polls it with the PTY.
    When the process exits with the session still open, every placement of the session
    is deleted at once, with no further output needed. This holds for a command started
    in the background (its own process group) as well.
  - Without `p=`, or when the pid cannot be watched (another session, already gone, no
    pidfd), the session binds to the pty's foreground process group. Whenever that group
    no longer holds the foreground with the session still open, the session's placements
    are deleted. The check is one `tcgetpgrp` per io step. While such a session is open
    the io thread also rechecks every 250 ms, so a SIGKILL is seen without further
    output. That timer exists only while a group-bound session is open (T-23 `IDLE`).
- **`--ext` / `-x`.** Asks the instance over the control socket to open a separate
  borderless glass window showing only the media (`media.window-open`, T-12 §2). The
  bytes the command would have written to the pane go to the window instead
  (`media.window-write`). The window has one grid of the size the media needs, no PTY and
  no cursor. The command stays in the foreground until that window closes: Escape or `q`
  in the window, or the compositor's close, ends the command with 0. Ctrl+C in the origin
  pane drops the connection, which closes the window, and exits 130. The window belongs
  to the connection that opened it, so a killed command takes its window with it.
- **Unsupported media.** `apoth play` exits 69 (`EX_UNAVAILABLE`) for a file it cannot
  play, before drawing anything; "Open with" then falls back to the desktop default
  (T-14 §11).
- Tests: Ctrl+C cleanup and SIGKILL cleanup on the headless session (no placement left,
  exit 130 for Ctrl+C), SIGKILL of a background command; `--ext` opens and closes its
  window headlessly (Escape, and SIGKILL of the command).

## 2. Media placement protocol
An APC namespace of our own, `ESC _ M <keys> ; <payload> ESC \`, key=value control data
in the style of the graphics protocol:
- `a=o` open: source `s=p` (path, local panes only), `s=f` (fd passed out-of-band by
  `apoth play` over the control socket, the default), `s=d` (chunked bytes, small clips
  and remote panes); placement `c,r` cells, `i` id, `z`.
- `a=c` control: `play`, `pause`, `seek=<ms>`, `rate`, `loop`, `volume`, `mute`.
- `a=q` query: position (ms), duration, state, tracks. `a=x` close.
- Events back to the client: `ready`, `ended`, `error=<code>`, position ticks on request.
  `ready` is `ready,w=<px>,h=<px>,d=<ms>,vw=<px>,vh=<px>[,dar=<W>:<H>]`: the output size
  the picture is scaled to inside the box, the duration, the coded video size and, when
  the container declares a display aspect other than the pixel aspect (anamorphic
  sources), that aspect in lowest terms. Clients read the fields by name and ignore ones
  they do not know.
- **Box fit.** On `ready` the box shrinks (never grows) to the picture's display aspect,
  so a placement takes the cells it shows: the columns or rows it does not need are freed.
  When the cursor sits on the row just below the box (the client wrote nothing since the
  open), it moves up by the rows freed; output that already moved the cursor keeps it
  where it is. An `--ext` window shrinks with its box.
- The interface plays and pauses a placement on click (T-08 §4) as if its client had sent
  `a=c` `play`/`pause`; the client gets no reply for it and sees the state in `a=q`.
A media placement is a tracked-pin placement like an image (T-15 §4); it scrolls with
text and is stopped and freed when its rows leave the screen (playback never continues in
history: `media.offscreen` `pause` (default) or `stop`).

## 3. Decode pipeline
- Demux: Matroska/WebM (`matroska-demuxer`); MP4 after the M0-flagged spike confirms a
  pure-Rust demuxer that exposes video packets (else MP4 stays Tier A).
- Video: `rav1d` (AV1), declared
  `rav1d = { version = "=1.1.0", default-features = false, features = ["bitdepth_8", "bitdepth_16"] }`
  (rav1d's default features enable its `asm` family, which is forbidden by T-00 §3.1
  outside the nasm exception). Cargo feature `av1-asm` (on in packaging, off in dev and
  CI default) enables rav1d's `asm` feature **on x86_64 targets only**, through a
  target-specific dependency table; x86_64 assembly is assembled by `nasm` at build time
  only (`makedepends`), with no runtime dependency. rav1d's arm64 asm features
  (`asm_arm64_*`) are never enabled; aarch64 and dev builds use the Rust fallback.
  T-24 §3 asserts that no build's resolved feature set contains an arm64 asm feature and
  that `asm` appears only for x86_64. Feature names are re-checked against the pinned
  rav1d `Cargo.toml` when the pin moves.
- The helper calls rav1d through its dav1d-compatible `extern "C"` API (the stable
  surface; its Rust API is partial, Appendix A row 1504), via one thin wrapper module in
  `apoth-media` that is the helper's only rav1d `unsafe` (T-18 §7) and is covered by the
  `av1_obu` fuzz target. Source is crates.io, never a git dependency.
- Hardware: a vendored `cros-libva` fork with **committed** bindings (generated by a
  dev-only xtask; no bindgen or libclang in CI or packaging) and a `cros-codecs` fork with
  the gbm dependency removed. The fork replaces link-time linkage with `libloading`-resolved symbols (the committed bindings are a function-pointer table); the helper's `DT_NEEDED` contains no `libva*`, and `libva`/`libva-drm` are loaded only when hardware decode is requested (T-00 §3.2, T-24 §4). Decoded NV12 is read back
  (`vaDeriveImage`/`vaGetImage`) into the shared frame ring; zero-copy dmabuf to a
  `wl_subsurface` is a later optimisation (R3, MEDIA-24).
- Audio: Opus (`opus-decoder`), AAC-LC/Vorbis/FLAC/MP3 (`symphonia`); resample with
  `rubato`; output through the pure-Rust `pulseaudio` crate to the `pipewire-pulse`
  socket behind `trait AudioSink` (ADR 0118: no linked audio library). No pulse socket ⇒
  video plays muted and the placement reports `audio-unavailable`.
- **A/V sync**: audio is the master clock, derived from `GetPlaybackLatency`
  (write offset − sink latency). Video frames are presented on the terminal's frame clock:
  show the latest frame whose PTS ≤ audio position + one refresh; drop late frames; hold
  on underrun. With no audio track the frame clock is the master.

## 4. The helper sandbox
All demuxing and decoding of untrusted bytes runs in `apoth-media-helper`, one process per
playing placement, started by the terminal with: no network, Landlock with an empty
filesystem view (inputs arrive as already-open fds), a seccomp allow-list, `PR_SET_NO_NEW_PRIVS`,
`RLIMIT_AS`, and a CPU watchdog. The sandbox reuses the Landlock/seccomp approach of
`abyss/crates/ec-agentd/src/sandbox.rs` as a design reference; it shares no code with
that TCB file.

1. **Order.** The helper reads no untrusted byte before step 3. (1) Initialise: for
   Tier C, open nothing itself — use the render-node fd passed in by the terminal — and
   call `vaInitialize`, which loads the VA driver (`*_drv_video.so`), `ld.so.cache` and
   drirc; Tier B has no initialisation step. (2) Restrict: `PR_SET_NO_NEW_PRIVS`,
   `landlock_restrict_self` with an **empty** filesystem view (no path rules at all, so
   any path open after this point fails, including a late driver `dlopen`), then load
   the seccomp filter. (3) Only then accept the input fd and begin demuxing.
2. **Seccomp.** One base allow-list; Tier C adds the `DRM_IOCTL_*` set of the detected
   driver family from a per-family table in `apoth-media` (i915/xe, amdgpu, nouveau).
   An unknown driver family gets no hardware decode (Tier B or Tier A instead).
3. **Fail closed.** If the Landlock ruleset is not reported fully enforced, or
   `prctl` or the seccomp load fails, or the driver family has no table entry, the helper
   exits before step 3 and the placement reports `error=sandbox-unavailable`. Playback
   never runs unsandboxed or partially sandboxed; there is no configuration to allow it.
4. **Frames.** Frames return through a persistent ring of memfds shared once (sized by
   the terminal from the negotiated geometry). Frame metadata (slot index, byte length,
   stride, PTS) travels over the socket, never through the ring; the terminal validates
   every field against the negotiated ring geometry, copies the slot's bytes once into
   its own buffer, and treats them as opaque pixel data. A message that fails validation
   kills the helper (`error=helper-protocol`).
5. **Audio.** PCM returns over the socket and is written to the audio sink by the
   *terminal* process, so the helper needs no audio socket. The terminal accepts only the
   sample rate and channel count negotiated at open (rate ≤ 192 kHz, ≤ 8 channels) and at
   most 1.1 × the negotiated byte rate averaged over 1 s; excess kills the helper.
6. **Failure reports.** The helper's `Info` carries the output size, the coded video size
   and the declared display aspect (0:0 for none). Every exit other than a protocol
   violation by the terminal sends `Failed(<code>)` first — a demux, decode, seek or
   frame-ring write failure is reported as its code, and audio packets that fail to
   decode are skipped (32 in a row fail the stream as `decode`) — so `helper-crashed`
   means the process died without a word (a signal or a panic).

## 5. Policy
- Audio never starts without a user gesture or an explicit `apoth play` invocation in the
  focused pane; a program writing the media APC in an unfocused pane gets video muted
  until the pane is focused (`media.autoplay-audio` `focused|never|always`).
- `s=p` path open is refused for remote panes (T-18 §10), is decided by the
  `media APC: path source` class (T-18 §3, local default `ask`), honours
  `media.allow-paths`, and opens with the T-15 §1 file opening rules (no symlink follow,
  regular files only, `/proc`, `/sys`, `/dev` refused, one identical error for every
  failure).
- Quotas: frame ring size, max resolution (default 3840×2160), max concurrent placements
  per pane (default 2) and per process (default 4).

## 6. Test Plan
- Tier A budget `VID-MPV` (class M with a recorded procedure; CI-N runs a 5-second
  synthetic kitty-animation stream and counts presented frames).
- Protocol fixtures; helper fuzz targets (`mkv_demux`, `av1_obu`, `va_slice_params`)
  under the same seccomp profile; sandbox checklist (class M): helper cannot open a path,
  cannot connect a socket, is killed on RLIMIT; VA-API init succeeds under the profile on

- A/V sync test with a synthetic clip (flash + click) and a fake `AudioSink` clock:
  |skew| ≤ 40 ms steady-state.

# T-17 — EclipseOS Integration (Draft v0.2)

Crate: `apoth-eclipse` (AGPL-3.0-only), the only crate that depends on `ec-ipc`,
`ec-theme` and `ec-term-pub`. Everything here is additive: with the crate's runtime
detection negative, Apotheosis is a complete terminal on any Wayland compositor.
Implements INTEGRATION-01, -02, -07, -24, -25, -27 (must); INTEGRATION-03..06, -08 (should).
Amends P-04 §1, §2 (surface root and tab levels above `terminal`), §6.1, §8, §9 item 1
(§4–§5 below; ADRs 0114, 0115; P-04 §3, §4, §6.2 and §7 apply unchanged), S-05 §5
rule 6 (§5; ADR 0115), ADR 0084 (§2; milestone X5), D-01/D-05/D-07 (T-24), policy
(ADR 0117).

## 1. Detection
Abyss is present when `ec_ipc::Client::connect()` succeeds on the default socket
(`$ECLIPSE_SOCKET_DIR/abyss.sock`, else `$XDG_RUNTIME_DIR/eclipse/abyss.sock`) and
`get_theme` returns a reply that parses as theme seeds. No new control-socket method is
needed or added. Detection runs once at start on the pool and again on socket loss
(backoff 1 s → 30 s). Every integration below has a defined non-Abyss fallback. Detection governs integration features only. Agent-peer identification and policy deference on the control socket (T-12 §4.1) do not depend on it: a lost or absent Abyss connection never relaxes them.

## 2. Theme
- On Abyss: `get_theme` at start and the `theme` event thereafter give the theme seeds;
  `ec_theme::derive` produces the palette for the glass interface, and
  `ec_theme::terminal_scheme(&Seeds) -> TermScheme` (16 ANSI colours, foreground,
  background, cursor, cursor text, selection foreground/background; contrast-checked by
  `ec_theme::validate`) produces the terminal colour scheme when `theme "system"`.
  `terminal_scheme` does not exist today: milestone X5 adds it to `abyss/crates/ec-theme`
  as an amendment to ADR 0084, before M19. A theme change re-derives, re-validates
  contrast, repaints, and emits the mode-2031 report to subscribed programs.
- Off Abyss: seeds come from KDL; light/dark follows the settings portal.
- Both derive steps live in `ec-theme`, shared with the shell; Apotheosis never
  re-implements either and holds no seed → colour mapping of its own.

## 3. Glass
On Abyss, blur through `ext_background_effect_v1` only, with one region box covering the window geometry so the compositor draws backdrop, rim, bezel and shadow (COMP-06 §1, COMP-02 C-14/C-15); server-side decorations are requested; the client lays only the tint (STYLE.md §Colour; T-08 §3). Off Abyss the T-09 §5 ladder applies (ext → `org_kde_kwin_blur` → tint). Apotheosis asks for no entry in any compositor allow-list and has no private glass protocol.

## 4. Semantic publishing
- `abyss/crates/ec-cataclysm-pub` is renamed `ec-term-pub` and its C ABI removed
  (ADR 0114). Its node model changes in exactly these ways, recorded in ADR 0114:
  (a) the fixed `ROOT_ID`/`SLOT_BASE`/`GROUP_BASE` constants become a per-surface node-id
  allocator; each pane gets a disjoint id range for the life of the surface, ids are
  never reused within it; (b) the publisher takes the parent node id to attach its
  `terminal` node under, instead of being the surface root. Line nodes, command-block
  groups and their `ext` keys are unchanged.
- `apoth-eclipse` owns **one publisher per toplevel surface** (the `eclipse_semantic_v1`
  tree is per surface), on a dedicated thread fed by a bounded channel of coalesced
  snapshots. It reads the grid with `Screen::snapshot_since` (T-02 §5) and its own SeenSet, never clearing the renderer's dirty flags. Rate and triggers are P-04 §7 unchanged: at most 5 Hz, plus the edge
  triggers (OSC 133 D, 100 ms output idle, alternate-screen toggle, new prompt).
- Tree, using only roles that exist in COMP-09 and `ec-term-pub` `Role`:
  `window` (surface root) → `tablist` → `tab`* (label, selected) → `terminal`* (one per
  pane of the selected tab; `ext` `rows`, `cols`, `echo`) → `terminal_line` per screen
  row, with OSC 133 command blocks as P-04 §2 `group` nodes carrying `ext.is_prompt`,
  `ext.command`, `ext.exit_code` and their `terminal_line` children. There are no
  `prompt`, `command` or `output` roles. Unselected tabs publish no pane children.
- Extent: visible rows by default; scrollback per P-04 §4 (up to 2 000 lines by range
  request, line nodes marked `ext.scrollback=true`).
- `ext.command` is the grid text between the OSC 133 B and C marks at the B→C
  transition (P-04 §3, feeding the S-06 irreversible matcher). Text supplied by OSC 133
  `cmdline=` is used for local interface only and is
  never published.
- Provenance (P-04 §6.2, S-05 §6): every `terminal_line` content is `untrusted`; a line
  carries a `Human` provenance link only when it lies between OSC 133 B and C and the
  bytes were produced by human-seat input to that pane.
- Never published: anything for a pane while it is in the credential state (§5) except
  the raise itself, command-line text supplied by `cmdline=`, anything typed while echo
  is off.
- P-04 §8's FFI fixture under ASan is replaced by the same fixtures re-expressed as Rust
  tests in `ec-term-pub` (ADR 0114); P-04 §1 and §9 item 1 (cataclysm, C ABI, ADR 0034)
  are superseded by ADRs 0109 and 0114.

## 5. Sensitivity and the credential signal
- The credential state of a pane is **`ECHO` off and `ICANON` on** in the PTY's termios,
  sampled on output-idle edges and before any content leaves the process (publishing,
  socket `read-content`, capture). Full-screen programs (vim, htop) run with both off and
  are *not* credential prompts; today's unconditional raise is wrong (ADR 0115). This
  amends S-05 §5 rule 6 for Apotheosis panes: the raising condition is the credential
  predicate, not `ECHO` alone.
- Credential state raises the toplevel's sensitivity to `secret` for its duration plus
  `downgrade_grace` (S-05 §5.2, default 500 ms; raise only; the app-declared class can
  never lower — root invariant). For that whole period it suppresses semantic publishing,
  socket content reads, key streams, scrollback persistence, output-match rules, and
  broadcast from or to that pane (as source broadcast is suspended; as receiver it is excluded — T-13 §5), redacts the pane's content-bearing `observe` fields (title,
  foreground argv, OSC 133 command text) to `null`, and shows a small lock indicator on
  the pane frame.
- **Wire signal.** The raise travels as `ext.echo=false` on the pane's `terminal` node
  (P-04 §2), the one field the publisher sends while the pane is in the credential state;
  `ext.echo=true` is sent when the state and its grace end. For Apotheosis, `ext.echo` is
  driven by the credential predicate, not by raw `ECHO`. The reserved `ext.credential`
  key (COMP-09 §2, S-08 §3.2) is not used.
- **What stays visible.** The `terminal` node hangs under a window node the host owns
  (ADR 0114). While the credential state holds, agents see that bare window node (role
  `window`, no text) and nothing beneath it: the terminal subtree and all text are
  withheld. The window's existence is not secret (owner decision 2026-11-13).
- **Remote panes.** Inside a remote pane (T-18 §10) the local PTY is raw, so a remote
  `sudo` or `passwd` prompt never shows the credential predicate locally. Remote panes
  are therefore treated as possibly in the credential state for keystroke egress: the
  `keys` stream (T-12 §4) is suppressed for them, and broadcast input (T-13 §5) *out of*
  a remote pane requires a confirmation per broadcast session, unless the pane's profile
  sets `security { remote-keys #true }`. Sensitivity raise and publishing are not
  changed by this rule (there is no reliable signal; T-22 §7).
- Keystroke content is never logged anywhere, in any state.

## 6. Notifications, bell, progress
OSC 9, OSC 777 `notify` and OSC 99 become one `Notification` event (T-03); delivery is
the freedesktop notification D-Bus interface from a pool task (the Abyss service
implements it). Filters: `notifications.when` `unfocused|invisible|always|never`; OSC 99
activation reports require consent per pane. Bell channels are independent switches:
`bell.audible` (xdg-system-bell), `bell.urgent` (xdg-activation), `bell.visual`
(tab badge + brief rim brightening; no full-window flash by default), `bell.notify`,
`bell.command` (argv). OSC 9;4 progress shows on the tab and is exported as an event.

## 7. Policy
- OSC 52 read, paste guard, window ops and remote-pane rules are enforced by Apotheosis
  itself (T-18) and behave identically off Abyss.
- There is no terminal app class; the rule lists app ids. ADR 0117's change is: add
  the glob `"org.eclipseos.Apotheosis*"` to `target_app_id` of
  `untrusted-origin-into-shell` in `abyss/crates/ec-policyd/src/default-policy.kdl`,
  regenerate `abyss/crates/ec-policyd/tests/golden/default-policy.tsv`, and update the

  review.
- On Abyss an app id override (`--app-id`, profile; T-09 §4) must start with
  `org.eclipseos.Apotheosis`; an override that does not is ignored with a diagnostic
  (`apoth doctor` reports it) and the default id is used, so no pane or profile can leave

- Control-socket requests from agent sessions defer to seat policy (T-12 §4.1); identification is by cgroup on every host, and an unreachable policy service is a deny.
- No everyday feature requires the user to edit `policy.kdl`; consent is asked in glass.

# T-18 — Security (Draft v0.2)

Cross-cutting; owned by `apoth-term` (sequence policy), `apoth-vt` (limits), `apotheosis`
(consent), `apoth-pty` (process hygiene). Implements SECURITY-01, -03, -04, -06, -07, -09,
-11, -12, -14..-16, -19..-21, -23..-26, -28, -31, -32, -45, -47, -49, -52, -53 (must);
SECURITY-05, -10, -13, -17, -22, -29, -43, -46, -48, -50, -55 (should).

## 1. Threat model
1. **Untrusted bytes on the PTY** (a `cat` of a hostile file, a compromised remote host):
   may attempt memory exhaustion, parser confusion, reply injection (making the terminal
   "type" attacker-chosen text into the shell), clipboard theft or poisoning, UI spoofing,
   file probing through graphics media, link deception.
2. **Untrusted local clients** of the control socket under the same uid, including agents.
3. **Untrusted media**: images and video containers.
4. **Hostile paste**: clipboard content crafted to execute on paste.
Out of scope: a hostile compositor, a root attacker, side channels.

## 2. Reply-injection rule
No reply ever echoes attacker-controlled bytes unescaped. Replies that must carry data
(XTGETTCAP, DECRQSS, OSC colour queries, kitty graphics errors) are generated from
internal state and encoded (hex, base64, or a closed alphabet). Title reporting
(`CSI 20 t`, `CSI 21 t`) is **never** answered with content: the reply is always the empty
`OSC L ST` / `OSC l ST` of T-03 §3.1, and no key changes that. ENQ answerback is empty by
default. DECRQSS builds its answer from state, never from the request.

## 3. Sequence policy table
One table (CONFIG-30) lists every sequence with a policy class and a decision
`allow|ask|deny` per domain kind (local, remote). These are the defaults:

| Class | Local default | Remote default |
|---|---|---|
| clipboard-write (OSC 52 set, ≤ 1 MiB) | allow | allow |
| clipboard-read (OSC 52 query) | ask | deny |
| primary-selection access | as clipboard | as clipboard |
| title set | allow (sanitised, ≤ 4096 bytes, T-03 §3.1/§5) | allow |
| title/icon report | allow (empty reply only, T-03 §3.1) | allow (empty reply only) |
| window ops: size/cell reports (14, 16, 18, 19), title stack 22/23 | allow | allow |
| window ops: move, resize, raise, iconify, fullscreen | deny | deny |
| colour set/query (OSC 4, 10–19, 104–119) | allow | allow |
| font query/set (OSC 50) | deny | deny |
| notifications | allow (filtered) | allow (filtered) |
| notification activation report | ask | deny |
| pointer shape (OSC 22) | allow | allow |
| graphics: direct transmission | allow | allow |
| graphics: file / temp / shm media | ask | deny |
| media APC: path source | ask | deny |
| user variables | allow | allow |
| hyperlinks | allow (T-14 §5 rules) | allow |
| kitty keyboard, mouse modes | allow | allow |

**Overrides** (SECURITY-31): `domain "<name>" { security { <class> allow|ask|deny } }`
and `profile "<name>" { security { … } }` override the column for panes of that domain
or profile; the profile wins over the domain. An `ExecDomain` (T-13 §2) uses the remote
column unless its domain block overrides it, since its template may cross a host or
container boundary. A pane that is remote only by process detection (§10 test 2) uses
the plain remote column: no override loosens it, so a local profile cannot relax a
detected ssh session.

`ask` uses the consent bar: allow once / always for this pane / deny, with a rate limit
(one pending question per class per pane; repeated asks within 10 s of a deny are
auto-denied). A consent bar or sheet ignores all key and pointer input for 500 ms after
it appears, and Return and Space never answer a consent bar; it answers only to its
explicit keys or a click on a button (T-08 §5 focus rules otherwise apply), so a program
cannot time a question to catch keys the user was already typing. The table is user-editable in KDL and on the ec-settings collection page (T-10 §5); `apoth doctor` and
OSC 60–62 (R2) introspect it.

The table is the KDL node `security { sequence "<class>" local="allow|ask|deny" remote="allow|ask|deny" }`, one child per class; class names are the kebab-case ids of the rows above (`clipboard-read`, `clipboard-write`, `primary-selection`, `title-set`, `title-report`, `window-ops-report`, `window-ops-control`, `colour`, `font`, `notification`, `notification-activation`, `pointer-shape`, `graphics-direct`, `graphics-file`, `media-path`, `user-var`, `hyperlink`, `input-modes`) as enum values. Override class `security` (T-10 §1.1): never runtime-overridable.

## 4. Paste
This is the single normative paste definition (T-05 §6 points here).
- Keys (node `paste`, T-10 §3): `paste.guard auto|always|never` (default `auto`); `paste.confirm-bytes` (default 4 KiB); `paste.max-bytes` (default 5 MiB hard limit; larger pastes are refused with a toast); `paste.newline as-is|cr|confirm` (default `cr`); `paste.trim-trailing-newline` (default #false).
- Sanitising, both modes: C0 controls other than TAB, LF, CR, plus DEL and C1 (U+0080–U+009F), are replaced by their visible pictures (U+2400 block / U+2421); nothing is silently dropped.
- Mode 2004 on: every embedded `ESC [ 201 ~` is removed (after sanitising, none can remain) and the content is wrapped in `ESC [ 200 ~ … ESC [ 201 ~`; newlines are sent as-is.
- Mode 2004 off: newlines follow `paste.newline` (`cr`: LF and CRLF → CR).
- Under `auto` the guard confirms in a glass sheet showing the sanitised text when the paste (a) contains a newline and the target is at an OSC 133 prompt without bracketed paste in force, (b) contained control characters before sanitising, (c) exceeds `paste.confirm-bytes`, (d) comes from a `text/uri-list` drop, or (e) is clipboard content last set by OSC 52 from a pane (tagged program-origin; remote panes are untrusted) and the target is at a shell prompt or its foreground process is a shell (T-14 §3). `always` confirms every paste; `never` confirms none except (e).
- Mode 2004 counts as `in force` for (a) only if an OSC 133 prompt mark has been seen since it was last set; 2004 set by other output and not followed by a prompt does not exempt the paste.
- On Abyss, clipboard content whose provenance is an untrusted origin always confirms (ties into `untrusted-origin-into-shell`).

## 5. Resource limits
Every string sink in the parser declares a byte budget (T-01); overflow aborts the
sequence and resets any half-built transaction. SOS/PM are skipped in constant memory.
Images: per-axis 10 000 px, decoded bytes checked before allocation, per-pane and
per-process quotas (T-15 §4). Titles, notification fields, user variables, hyperlink
URIs (≤ 2083 bytes) and ids are capped. Scrollback is bounded by bytes. Reply queue is
bounded (64 KiB per pane); overflow drops replies and counts them. The io thread is its only producer and main its only consumer: main moves replies into the pane's outbound queue in arrival order as whole units (T-00 §4.2); no thread but main writes the PTY. The control socket
bounds lines and buffers (T-12).

## 6. Interface integrity
- Text from programs shown in the interface (titles, notification text, badges, link
  tooltips) has control characters, bidi overrides and isolates stripped, is length
  capped, and is rendered in a visually distinct style from interface-owned text.
- Consent bars and sheets are drawn outside the pane's grid area and cannot be imitated
  by cell content at the same position; they name the pane and the requesting class.
  (They are application UI, not the compositor's Trusted UI; decisions that belong to the
  compositor's policy are asked by the compositor.)
- Hyperlinks: T-14 §5.
- Consent and sheet answers (allow once/always/deny, paste-guard confirm, askpass submit) are not registry Actions (T-11 §1): they respond only to real seat input on the sheet and cannot be reached from the socket, rules, macros, binds or layouts. `input.send-keys` never enters bind lookup or interface focus (T-12 §2).

## 7. Processes and file descriptors
Every fd is `CLOEXEC`; the child closes everything above 2 with `close_range`. Child
environment is built from a clean base: other terminals' variables and
`XDG_ACTIVATION_TOKEN`/`DESKTOP_STARTUP_ID` are removed. Exit detection is by pidfd.
Close escalates SIGHUP → SIGTERM → SIGKILL on the process group with bounded waits.
`unsafe` is confined to `apoth-pty`, `apoth-wl` and the media helper's FFI modules, each
`unsafe` block carrying a `// SAFETY:` comment; all other crates are
`#![forbid(unsafe_code)]`.

## 8. Media and decoding
All container and video decoding happens in the sandboxed helper (T-16 §4); the terminal
process never links a video decoder. Image decode moves into the helper from M34. Media
surfaces die with their pane.

## 9. Persistence and logs
- Nothing a user types is ever logged. Pane output is not logged. Diagnostics name
  sequences and sizes, never payloads.
- Session files are `0600` under `$XDG_STATE_HOME/apotheosis/`; they hold layout, cwd,
  argv and profile only. The saved argv is only the argv a pane was launched with
  (command line, layout file, `launch` request) — never the observed foreground process.
  A pane that has ever been in the credential state is saved with layout and profile
  only (no argv, no cwd) (SECURITY-26). Restored commands start **suspended** (shown,
  run on Enter).
- Scrollback disk spill and content persistence are off by default. When enabled, spill
  blocks are encrypted with `chacha20poly1305` (RustCrypto, `=0.10`, pure Rust,
  Apache-2.0 OR MIT; already in the workspace through `ec-brokerd`) under a random key
  generated at process start and held **only in that process's memory**; the key is
  never written to any file, keyring, socket or environment. Spill therefore lives
  exactly as long as the process that holds it: under the R2 daemon, history survives
  GUI and compositor restarts (the daemon holds it) but **not** a daemon restart. Spill
  files are unlinked after creation; on start, any spill file left by a previous process
  is deleted unread. Panes that have ever been in the credential state never spill
  (ADR 0121).
- `password`-role values are never delivered, logged or stored (root invariant); the
  terminal's contribution is §T-17 §5.

## 10. Remote panes
A pane is *remote* when any of these holds — every test only **tightens**:
1. its domain is not local (`SshDomain`, remote mux), or it is an `ExecDomain` without a
   local override (§3);
2. any process in the tree rooted at the pane's foreground process group — walked by
   pidfd from the group's processes through their descendants, depth ≤ 8, ≤ 256
   processes — has an `argv[0]` basename on the remote-client list. Default list:
   `ssh`, `mosh-client`, `telnet`, `docker`, `podman`, `kubectl`, `tmux`, `screen`
   (attached multiplexer clients count, since their server's panes are not visible to
   the walk); configurable, and user additions only extend it. A process whose
   `/proc/<pid>/cmdline` cannot be read, or a walk that hits a bound, counts as a match.
The test runs when the PTY's foreground process group changes (`tcgetpgrp` on output-idle
edges) and before every decision of a class
whose local and remote defaults differ. Remote panes use the remote column of §3.

## 11. Fuzzing and review
Fuzz engine: `cargo-fuzz` with `libfuzzer-sys`, in the non-shipping workspace
`apotheosis/fuzz/` with its own `rust-toolchain.toml` pinning a dated nightly (needed for
`-Zsanitizer`). This is the second standing exception to the T-00 §3.1 language rule:
that workspace alone may build libfuzzer's C++ runtime in a build script; it is never a
dependency of a shipping crate, `lang-rule.sh` skips it entirely, and T-24 §3 asserts no
shipping crate depends on it (ADR 0110). Structure-aware generators and differential
tests against the `vte` oracle run in the normal stable test suite. Targets: `vt_parse`, `term_feed`, `kitty_apc`, `sixel`,
`osc_all`, `kitty_keyboard_decode`, `config_parse`, `proto_json`, `match_lang`,
`template`, `compose`, plus the helper targets (T-16). Each has a seed corpus in-tree and
a CI smoke run (60 s each, on the fuzz workspace's pinned nightly); longer runs are a
scheduled job. Policy conformance tests run
the sequence corpus twice — allowed and denied — asserting that denied means *no
observable effect and no reply*.

## 12. Test Plan
As §11, plus: reply-injection corpus (every query sequence with hostile parameters;
assert replies match a closed grammar); paste-guard table tests covering cases (a)–(e) and the 2004 rule; fd-leak test (spawned
child lists `/proc/self/fd`); environment scrub test; consent rate-limit test and
consent input-delay test (keys typed within 500 ms of a bar appearing do not answer it);
socket permission tests; remote-detection tests (`ssh` under `tmux`, `sudo ssh`,
`docker exec`, a nested shell running `ssh`, an unreadable child process — all remote);
file-transmission probe test (a nonexistent path, a FIFO, a `/proc` path and a symlink
each give the identical `ENOENT` reply and never block); session-file test (a pane that
entered the credential state is saved without argv and cwd); spill test (spill readable
after a GUI restart under the daemon; after a daemon restart the old spill files are
deleted unread and no key exists on disk).

## 13. Open Decisions
- Per-pane systemd scope (SECURITY-29): R2, needs a D-Bus call per spawn; measure.
- Password-manager integration (SECURITY-33): R2 via Secret Service.

# T-19 — Identity & Terminfo (Draft v0.2)

Crate: `apoth-terminfo` (Apache-2.0). Implements PACKAGING-01, -07..-10,
INTEGRATION-26, -50, -51. Decision record: ADR 0124.

## 1. Names
- `TERM=xterm-apotheosis` (256-colour, `setaf`/`setab` in the `38;5` form with RGB
  flags `Tc`/`RGB` semantics as below) and `xterm-apotheosis-direct` (direct colour).
  The `xterm-` prefix is deliberate: much software enables features by prefix.
- Before spawning, the terminfo database is probed (`TERMINFO`, `~/.terminfo`,
  `TERMINFO_DIRS`, `/etc/terminfo`, `/lib/terminfo`, `/usr/share/terminfo`; letter and
  hex directories). If our entry is absent, `TERM=xterm-256color`.
- Environment: `COLORTERM=truecolor`, `TERM_PROGRAM=Apotheosis`,
  `TERM_PROGRAM_VERSION`, `APOTHEOSIS_*` (T-12 §3). Variables of other terminals are
  scrubbed (T-18 §7).

## 2. One source
The entry is a Rust table in `apoth-terminfo`. From it: (a) a pure-Rust writer emits the
compiled `term(5)` binary (extended-number format, with the user-defined capability
section) at package time — `tic` is not a build dependency; (b) the sorted static
name → value table that answers XTGETTCAP; (c) the human-readable `.ti` text
(`apoth terminfo --source`) for users who need to install it on a remote host. A unit
test asserts the three agree and that the compiled output is byte-identical to `tic -x`
on the generated source (dev-only test, skipped when `tic` is absent).

## 3. Capabilities
Standard xterm-compatible set plus: `Tc`, `RGB` (direct variant), `Su` (styled
underline), `Smulx`, `Setulc`, `Ss`/`Se` (cursor style), `Cs`/`Cr`, `Ms` (OSC 52),
`Sync`, `XT`, `BD`/`BE`/`PS`/`PE` (bracketed paste), `fe`/`fd` (focus), `XF`, `Smol`
(overline), `hs`/`tsl`/`fsl` (title as status line), `fullkbd`, `rep`, `E3`, `XM`.
The table records, per capability, the T-03 sequence that implements it; a test feeds
each capability string through `apoth-term` and asserts the expected effect.

## 4. Device identification
- DA1 at R1: `CSI ? 62 ; 4 ; 22 c` (VT220 class, sixel, ANSI colour); before M25 (sixel) the build sends `CSI ? 62 ; 22 c`. Attributes 6 (selective erase) and 28 (rectangular editing) are added in the milestone that lands VTCORE-33/-32 (R2). 52 is not sent: it is not in xterm ctlseqs; OSC 52 support is advertised by XTGETTCAP `Ms`. This is the only DA1 definition (T-03 §3.1 refers here). DA2:
  `CSI > 1 ; Pv ; 0 c` with `Pv = major × 10000 + minor × 100 + patch` of the application
  SemVer, in decimal (foot's encoding; 1.4.2 ⇒ `CSI > 1 ; 10402 ; 0 c`; minor and patch
  are each < 100, enforced by a release-time test); pre-release and build metadata are not
  encoded. DA3: `DCS ! | 00000000 ST`.
- XTVERSION: `DCS > | Apotheosis <semver> ST`.
- XTGETTCAP `DCS + q Pt ST`: `Pt` is a `;`-separated list of hex-encoded names (two
  hex digits per byte, either case accepted; replies use uppercase). Names are processed
  in order, one reply each:

  | Name | Reply |
  |---|---|
  | known string or numeric capability | `DCS 1 + r HEX(name) = HEX(value) ST`; numbers as decimal text before hex encoding |
  | known boolean capability | `DCS 1 + r HEX(name) ST` (no `=`) |
  | unknown name | `DCS 0 + r HEX(name) ST`, and the remaining names are not processed (xterm behaviour) |
  | name that is not valid hex | `DCS 0 + r ST` (nothing received is echoed), and processing stops |

  Answers come from the `xterm-apotheosis` table of §2 (they describe the emulator, not
  the database), plus: `TN` = the `TERM` value exported to this pane's child (so
  `xterm-256color` under the §1 fallback), `Co` = `256`, `RGB` = `8/8/8`, `Tc` boolean.
  Hex encoding of both name and value satisfies the reply-injection rule of T-18 §2; every
  reply goes through the pane's reply queue (T-00 §4.2).
- `sudo-terminfo` shell-integration feature exports `TERMINFO` across `sudo`; ssh
  shipping of the entry is handled by `apoth ssh` (T-22).

## 5. Test Plan
§2 and §3 tests; golden replies for DA1 (both the R1 and the pre-M25 forms)/2/3 (DA2 for versions 0.1.0, 1.4.2, 12.34.56),
XTVERSION, XTGETTCAP (string, numeric, boolean, unknown, invalid hex, unknown in the
middle of a list ⇒ later names unanswered, `TN` under the fallback); probe-order test with
a temp directory tree; `infocmp` round-trip (dev-only). Interop fixture (CI-N): vim with
`TERM=xterm-apotheosis` and an empty vimrc parses the DA2 reply (`v:termresponse`
non-empty) and ends with `ttymouse=sgr`; the fixture records vim's resulting
`ttymouse` and `t_RV`-derived properties as a golden so a vim heuristic change is seen.

## 6. Open Decisions
None.

# T-20 — Accessibility (Draft v0.2)

Crate: `apoth-a11y` (AGPL-3.0-only; `accesskit`, `accesskit_unix` with its default
async-io executor — no tokio). Implements ACCESSIBILITY-01, -02, -04, -06..-09, -11, -16,
-17, -23..-29, -31, -32, -35 (must); -03, -05, -10, -12..-15, -33, -34, -36 (should).

## 1. Activation
Nothing is built until an assistive technology is present. `org.a11y.Status.IsEnabled`
is not a reliable signal on its own (it stays true after the first Orca run and is
always true on some distributions; Appendix A row 1695), so under `auto` the adapter
thread activates when `IsEnabled && ScreenReaderEnabled`, **or** on the first AT-SPI
request addressed to our bus name, whichever comes first. Until then the cost is the
idle D-Bus matches only: no snapshot, no tree, no rebuild timer. The tree and snapshots
are dropped again when both properties are false and no AT-SPI request has arrived for
60 s. `accessibility.enabled` `auto|on|off`; `on` activates unconditionally, `off`
makes every handler return early. T-23 carries an IDLE budget row for "a11y active, no
AT client".

## 2. Tree
The tree builder is a pure module that turns UI model + pane snapshots into AccessKit
`TreeUpdate`s and knows nothing about the transport (testable without D-Bus).
```
Window
├─ TabList → Tab* (selected, label, badges as description)
├─ Pane* (group, label = pane title, focused state)
│   └─ Terminal (one TextRun per visible row; caret; selection)
│       └─ (with OSC 133) Prompt / Command / Output ranges as navigable landmarks
├─ Search bar, Palette, Consent bar, Sheets (standard roles, when open)
└─ Toast (live region)
```

## 3. Text model
- Offsets are Unicode scalar indices into extracted text, with grapheme clusters grouped
  by `character_lengths`; never cell indices, no padding blanks. A per-row position table
  maps offsets ↔ cells (wide cells, combining marks, tabs as copied).
- Wrapped rows are joined without a line break; hard line ends carry `\n`.
- Character extents come from real cell rectangles; offset-at-point is the inverse.
  Coordinates are window-relative.
- Granularity queries (char, word, line, paragraph) use the same word rules as selection
  (T-02) so double-click and screen-reader words agree.
- Attribute runs (R2): underline, strike, weight, italic, fg/bg, link.

## 4. Updates
A per-pane snapshot of visible text is kept only while activated. Output marks it stale;
a coalescing timer (default 100 ms, off the render path) rebuilds from the rows changed since its last snapshot (`snapshot_since`, T-02 §5; it never reads or clears the renderer's dirty flags) and
pushes one update; the adapter derives insert/remove events by prefix/suffix diff.
Viewport scrolls are reported as scroll changes, not as text churn. Caret and selection
changes are pushed immediately. Announcements (bell, notification, command finished with
status) are polite live-region messages; typing interrupts pending output announcements.
The credential state (T-17 §5) suppresses echo announcements (there is nothing to read)
and exposes the node as protected.

## 5. Interface accessibility
Every glass control is an AccessKit node with role, name, state and default action;
keyboard traversal reaches all of them (T-08 §5); the settings pages are ec-settings'
responsibility under the same bar.

## 6. Visual accessibility
`colors.minimum-contrast` (type `Ratio(1.0..=21.0) | automatic`, default 1.0 = off; `automatic` raises only
indistinguishable pairs) nudges foreground lightness per cell, skipping emoji, images and, unless `colors.minimum-contrast-builtin-glyphs #true`, the built-in glyphs of T-06 §6; applied by the renderer per cell (T-07 §4). This is the only key for the behaviour (`render.min-contrast` removed).
`cursor.thickness`, `cursor.blink` (off honours reduce-motion), bold-is-bright off by
default, `interface.motion` (T-08 §2). Palette generation from the base 16 (R2).

## 7. IME
text-input-v3 per seat (T-09 §3): preedit rendered in place at the cursor with an
underline style, never written to the PTY; the cursor rectangle follows the terminal
cursor so the candidate window is positioned correctly.

## 8. Test Plan
Tree-builder unit tests (snapshot → expected nodes, offsets, extents) including wide and
combining text; diff tests (single insert/remove per update); a headless AT-SPI client
test in nested Abyss that reads the focused terminal's text and caret over the real bus;
**Orca checklist (class M, a deliverable of M30)**: read line, read word, review by
character, announce new output, navigate prompts, tab switch announced, palette usable,
across the Orca versions packaged for EclipseOS at that time.

**Fallback if the checklist fails.** No terminal has shipped an AccessKit text-node
model that Orca reads (Appendix A rows 1698–1699). If the `Terminal` text-run model
fails any read/review item of the checklist, M30 closes with the line-only model
instead: each visible row is a read-only static-text node inside a `List`, focus and
caret move by line, announcements are unchanged, and §3 granularity below line is
dropped until the text-run model passes. The tree builder supports both models behind
one switch so the fallback is a configuration of tested code, not new work.

## 9. Open Decisions
- Prompt as a separate editable node (ACCESSIBILITY-10): decide after the Orca pass.
- Text-run model vs line-only fallback (§8): decided by the M30 Orca checklist result.

# T-21 — Sessions & Daemon (Draft v0.2)

Implements REMOTE-05, -06, SECURITY-25, -26 (must, R1 parts); MUX-03 family, REMOTE-17,
-18, PACKAGING-02 (R2). Decision records: ADR 0120 (single process), ADR 0121
(persistence), ADR 0123 (mux sync).

## 1. R1: one process
One `apotheosis` process owns all windows of an instance. A second launch hands its
request to the running instance (T-12 §5) and exits; `--new-instance` opts out. If the
instance does not answer within 300 ms the launcher starts its own. A crash therefore
takes every window; this is accepted for R1 and bounded by the fuzz and soak gates.
Start-up is single-binary and has no daemon to manage.

## 2. R1: layouts and restore
Named layouts and "restore last session" (layout, cwd, argv, profile; T-13 §6). Restored
commands other than the profile's shell start suspended.

## 3. R2: the daemon
`apotheosis --server` hosts the `Session` (T-13 §1), PTYs, parsers and grids without any
Wayland connection; GUI processes attach as views. Because `apoth-mux` and `apoth-term`
are GPU- and Wayland-free from the start, this is a relocation. Benefits: sessions
survive GUI and compositor restarts; detach/attach; several views of one session.
- **Sync** (ADR 0123): on attach the server sends a versioned binary snapshot of each
  visible pane (pages, styles, links, cursor, modes, images by reference) and then tees
  the PTY byte stream with sequence numbers; the view runs its own `apoth-term` over the
  same bytes, so rendering is identical by construction and there is no cell-diff
  protocol to keep correct. History pages are fetched on demand. Input goes view →
  server → PTY. Resize policy across views: `smallest|latest|largest` (default `latest`).
- Flow control: per-view bounded tee buffer; a slow view is resynchronised from a fresh
  snapshot instead of blocking the PTY.
- Local views pass shm and dmabuf-free image data by memfd; remote views (T-22) get
  images inline.
- **Attach transport and authority.** A view holds every pane's content and an input
  path, so attach is gated exactly like the control socket (ADR 0116):
  - Socket `$XDG_RUNTIME_DIR/apotheosis/server-<session>.sock`, under the same `0700`
    directory as T-12 §1, socket `0600`, the same ownership and mode check at startup,
    `SO_PEERCRED` uid must equal ours, peer identified by `SO_PEERPIDFD`; no TCP, no
    abstract namespace, no forwarding.
  - `attach` requires both `read-content` and `input` (T-12 §4) for every pane it
    receives, decided per pane by the T-12 §4 rules including seat-policy deference: a
    peer that is (a descendant of) an agent session is refused unless the compositor's
    policy would allow that agent the equivalent seat operation; no reachable policy
    service ⇒ refuse. A view granted `read-content` but not `input` for a pane receives
    that pane read-only; a pane with neither is omitted from the snapshot and tee.
  - Pre-granted only: a peer whose pidfd resolves to the installed `apotheosis` GUI
    binary (the path the package installs, checked through `/proc/<pid>/exe` on the
    pidfd) started by the user, not as a descendant of any pane or agent session. Every
    other peer — including `apoth` and any binary started from inside a pane — goes
    through consent (a glass sheet in an already-attached view; with no view attached,
    refuse).
  - Grants are rechecked on every pane added to the session after attach.
  - `apoth proxy` (T-22 §5) is a peer of the remote server's socket and is subject to
    the same check there; its consent is asked on the remote session's attached views or
    refused.
- systemd user unit with socket activation is shipped but not enabled by default; the
  daemon mode is opt-in (`sessions.server` `off|on`) until it has a release of soak.

## 4. Version skew
Every stream opens with protocol version and capability set; a view and server with
different major versions refuse to attach with a clear message. Snapshot records are
typed and length-prefixed so unknown records are skippable within a major version.

## 5. Content persistence (R2, off by default)
`scrollback.persist` lets the daemon spill history to encrypted disk so it survives GUI
and compositor restarts and detach/attach; it does **not** survive a daemon restart,
because the key lives only in the daemon's memory (T-18 §9, ADR 0121). Rules in T-18 §9.

## 6. Test Plan
R1: second-launch hand-off tests (exit-code relay, activation token, stale socket);
restore tests (suspended start). R2: snapshot round-trip property tests
(`Term` → snapshot → `Term` equal); tee equivalence test (server and view grids
byte-identical after a replayed corpus with random attach points); slow-view resync;
version-refusal test; attach-authority tests (socket mode/owner, foreign uid refused,
agent-descendant attach refused with a stub policy service for allow, deny and
unreachable ⇒ refuse, `read-content`-only view cannot send input, GUI binary
pre-granted, `apoth`-from-a-pane asks); spill survives a GUI restart and is deleted
unread after a daemon restart; soak: 24 h scripted session with periodic attach/detach.

## 7. Open Decisions
- Whether daemon mode becomes the default after soak (owner decision at M35 exit).

# T-22 — Remote Domains (Draft v0.2)

Implements REMOTE-08, -11, -24, -25, SECURITY-31 (must); REMOTE-09, -10, -13..-15
(should). R2 (milestone M37) except §1, which is R1. In-process ssh libraries are rejected
(REMOTE-28); the transport is the system `ssh` binary.

## 1. R1: remote awareness
- A pane running `ssh` is detected (T-18 §10) and gets the remote policy column.
- In-band resize (mode 2048) is implemented in T-03.
- OSC 7 with a non-local host is honoured for display and profile matching, never for
  local spawns.

## 2. `apoth ssh`
A wrapper that runs the system `ssh` with a private `ControlMaster=auto`,
`ControlPath` under `$XDG_RUNTIME_DIR/apotheosis/ssh/%C` (with the short-path symlink
workaround when the path would exceed the socket limit), `ControlPersist`, and
`ServerAliveInterval`. Before reuse, a stale master is probed (`ssh -O check`, 5 s).
Features, each consented once per host and recorded in KDL:
- install the terminfo entry into `~/.terminfo` on the remote (`infocmp`-free: we send
  the compiled entry);
- inject shell integration for the remote shell for that session only;
- carry selected environment (`COLORTERM`, `TERM_PROGRAM*`).
Falls back to plain `ssh` semantics when any step fails; never downloads binaries.

## 3. Askpass
`SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force` point at `apoth askpass`. Askpass is armed
per `apoth ssh` session, following the SECURITY-30 template:
- `apoth ssh` asks the instance over the control socket to arm askpass for one ssh
  process; arming is refused unless the peer is a descendant of one of our panes and not
  of an agent session. The instance creates a 256-bit random one-time token and a
  dedicated listening socket `$XDG_RUNTIME_DIR/apotheosis/askpass-<random>.sock` (same
  `0700` directory as T-12 §1, socket `0600`, `SO_PEERCRED` uid check), separate from the
  JSON control socket. `apoth ssh` passes the socket path and the token to the ssh child
  only through its environment (`APOTHEOSIS_ASKPASS_SOCK`, `APOTHEOSIS_ASKPASS_TOKEN`);
  an inherited fd is not used because `ssh` closes inherited descriptors at startup. The
  token is never logged, never sent on any other channel, and never forwarded to the
  remote host (it is excluded from the §2 environment carry). The socket is unlinked
  and the token revoked when that ssh process exits.
- `apoth askpass` connects to that socket and sends `{token, prompt}`. The instance
  accepts a request only when the token matches, the peer's pidfd ancestry contains the
  armed ssh process, and no other request for that token is pending (one sheet at a
  time). The token is valid only while the armed ssh process lives. A request without a
  valid token, over any other channel (including the JSON control socket), or failing
  the ancestry check is refused and `apoth askpass` exits 3 with no sheet shown.
- The sheet shows the requesting host (from the armed `apoth ssh` invocation) as
  interface-owned text, visually separate from the remote prompt, which is
  program-supplied text sanitised per T-18 §6; host-key prompts show the fingerprint in
  a monospace block.
- The secret travels instance → `apoth askpass` over the armed askpass socket only, then
  askpass → ssh over the pipe ssh provides. It is never sent over the JSON control
  socket, never logged, never stored; the sheet's text field is a protected field (not
  published, not accessible-readable).
- Plain `ssh` (not through `apoth ssh`) gets no askpass from Apotheosis.
On Abyss the sheet is superseded by `ec-secret-prompt` when that service is available;
the token and ancestry checks are the same.

## 4. `SshDomain`
`domain "name" { ssh "user@host" }` makes spawn/split in that domain run a remote shell
through the shared master, with cwd inheritance from OSC 7. Hosts can be imported from
`~/.ssh/config` (non-wildcard `Host` entries) as suggestions in the palette.

## 5. Remote mux
With the daemon (T-21 §3) installed on the remote by the user's package manager,
`domain { ssh "host"; mux #true }` runs `apoth proxy` over ssh stdio and attaches with
the T-21 sync protocol — no listener, no extra port. Version skew rules apply. We do not
install or download the remote binary.

## 6. Test Plan
Integration tests against a local `sshd` in a container-free user-mode setup
(`sshd -f` with a temp config on a high port, dev-only and CI-N): master reuse, stale
probe, askpass round-trip with a scripted password, terminfo install, remote policy
column in effect, proxy attach (and proxy attach from an agent-descendant peer
refused, T-21 §3); askpass refusal tests (no token, token after the armed ssh exited, token from a process
outside the armed ssh's ancestry, request over the JSON socket — each exits 3 and shows
no sheet).

## 7. Open Decisions
- Predictive local echo (REMOTE-16): not planned; revisit only with a reliable
  no-echo signal over ssh.

# T-23 — Performance (Draft v0.2)

Owns the named budgets every other section cites. Implements PERFORMANCE-01..10 and the
measurement rows of the matrix. Harness: `apoth-testkit` (`benches/`, `apoth-bench` bin).

## 1. Method
- **Budgets are relative to the best measured peer on the reference machine**, not to
  published figures: published numbers (matrix Appendix B) come from other hardware and
  are context only. The reference machine is the owner's desktop (recorded in
  `apotheosis/bench/REFERENCE.md`: CPU, GPU, driver, kernel, compositor commit, monitor
  refresh). Peers: foot, kitty, alacritty, ghostty, wezterm at the versions packaged on
  the day of measurement, each in its documented low-latency configuration and in its
  defaults.
- Milestone M17 records the peer baselines and fills the **Absolute** column below; until
  then the absolute values are provisional ceilings that must not be exceeded.
- Corpora are deterministic, generated by `apoth-bench gen` with fixed seeds, and checked
  in by hash (not by content) so results are comparable across runs.
- Every run: release profile with the packaging flags, fixed window size 120×40 and
  240×67, fixed font, warm-up discarded, median of ≥ 10 runs, serial, AC power,
  performance governor. Results are written as JSON to `apotheosis/bench/results/` and
  compared against the previous accepted baseline. Regression tolerance is per metric
  kind: headless throughput medians > 5 %; e2e medians > 10 %; e2e p99 latencies > 15 %;
  counts (frames, wakeups, dropped frames) are compared against the budget exactly. A
  regression beyond its tolerance fails W5.
- **Clocks.** Wayland input event times (`wl_keyboard.key`, `wl_pointer`) are u32
  milliseconds in an unspecified base and are never used for a budget. The input
  start event of every latency budget is the **client stamp**: `CLOCK_MONOTONIC` read by
  main when the Wayland display fd becomes readable, before dispatch; budgets measured
  from it are labelled `client-side` and exclude compositor input delivery. Where the
  compositor offers `zwp_input_timestamps_v1`, its nanosecond time is recorded as a
  second, informative series (it is in the event-time clock domain, not necessarily
  `CLOCK_MONOTONIC`, so it is never subtracted from a presentation time). Abyss (smithay
  0.7.0) does not offer it; it is not a gate input. Presentation times are used only when
  `wp_presentation.clock_id` is `CLOCK_MONOTONIC`; otherwise `LAT-PHOTON` is recorded as
  unavailable for that run, never converted.
- Two layers are measured separately: **headless** (parser + grid, no PTY, no renderer —
  runs in CI on any machine, gates relative regressions) and **end-to-end** (real PTY,
  real renderer, nested headless Abyss or the reference machine — class M for absolute
  numbers, CI-N for regressions).

## 3. Design rules that the budgets force
1. Input is written to the PTY from the main thread on the event, never queued behind a
   frame, and without taking the term lock: encoders read only the `InputModes` mirror
   (T-00 §4.2; `LAT-KEY`).
2. The render thread snapshots dirty rows under a lock held for a bounded time (≤ 100 µs for a full-screen snapshot at 300×80, measured at M11; every lock taker of T-07 §1 has the same bound) and builds the frame unlocked; the io thread never waits on the GPU.
3. Frame scheduling is T-07 §2 (callback-gated, coalescing timers ≤ 8 ms, echo bypass of the timers but not the callback gate) (`LAT-ECHO`).
4. No frame without damage; no timer without a consumer (`IDLE`).
5. The parser has a bulk printable fast path and does not allocate per sequence; the grid
   writes runs, not cells (`THR-*`).
6. Start-up defers everything not needed for the first frame: font fallback discovery,
   emoji atlas, shell-integration assets, accessibility, the control socket bind is
   non-blocking, config is parsed once; the pipeline cache is persisted
   (`$XDG_CACHE_HOME/apotheosis/`) (`START-COLD`).
7. Throughput under flood never starves input or rendering: the io thread yields the
   term lock at bounded byte counts (64 KiB) and the renderer is guaranteed a snapshot
   at least once per refresh; render and main wakeups are edge-triggered and coalesced,
   and per-pane events are bounded (T-00 §4.3), so a sequence flood (e.g. looping
   `OSC 2`) costs main at most one drain per ping.

## 4. Instrumentation
- Tracing spans (off by default, `--trace` or `debug.trace` Action) for input, parse
  batch, snapshot, frame build, submit, present feedback; written as a Chrome-trace JSON
  file. Spans carry sizes and durations only — never content.
- `render.status` and `debug.stats` IPC expose live counters: frames, dropped frames,
  snapshot lock time histogram, atlas occupancy, parser limit hits, page counts.
- A latency overlay (debug) shows the last key's stages.
- Photon latency (class M) uses presentation-time feedback as ground truth and, where the
  owner chooses, an external measurement; the procedure lives beside the results.

## 5. Build profile
`[profile.release]`: `lto = "fat"`, `codegen-units = 1`, `panic = "abort"`,
`opt-level = 3`, debug info split and stripped in packaging. PGO is a packaging-time
option evaluated at M17 (foot's own figures show 25–35 % on parse-heavy work); it is
adopted only if the training corpus run is reproducible in the PKGBUILD without network.
`target-cpu` stays the distribution baseline (`x86-64-v3` if the EclipseOS repo targets
it, else `x86-64`), with runtime-dispatched SIMD (`std::arch` + `is_x86_feature_detected`)
in the parser scan and UTF-8 validation.

## 6. Test Plan
`apoth-bench` subcommands per budget; CI runs the headless set and compares to the
committed baseline with the §1 tolerances on a pinned runner class; CI-N runs the e2e
regression set under nested headless Abyss (relative only); class-M runs are recorded in
`docs/internal/apotheosis/bench/` with the reference-machine block. W5's third agent
executes this and reports budget by budget. `LAT-KEY` is also measured with a `THR-E2E`
flood running in the same pane and in a sibling pane (same budget), and with a looping
`OSC 2` title flood (main-loop pings per second ≤ refresh rate).

## 3. Language rule check
A CI script (`apotheosis/ci/lang-rule.sh`) enforces T-00 §3.1–§3.2 in five parts; any
failure fails the gate.
1. **Files.** No file with a C-family or assembly extension (`.c .h .cc .cpp .cxx .hpp
   .hh .hxx .inl .m .mm .s .S .asm`) exists in the workspace or in a vendored fork outside
   an explicitly listed, uncompiled reference directory.
2. **Graph.** For each shipped feature set — default, packaging (`av1-asm`), and
   `xkbcommon` — `cargo tree -e build,normal --target x86_64-unknown-linux-gnu` contains
   no `cc`, `cmake`, `bindgen`, `nasm-rs` or `autotools` package except through the
   reviewed (crate, build-dependency) allow-list, which is exactly `rav1d → nasm-rs` and
   `rav1d → cc` (archiver only), both under `av1-asm`.
3. **Behaviour.** The gate build of each feature set runs with `CC`, `CXX`, `CC_<target>`
   and `CXX_<target>` set to `/usr/bin/false`, so any compiler invocation by a build
   script fails the build; only `rav1d`'s `NASM` and `AR` are real tools. (The rustc
   linker driver is unaffected.) M1 dry-runs this over the dependency graph and records
   any crate that merely *probes* for a compiler and degrades cleanly; such a crate is
   allowed only if its probe failure changes no shipped code, recorded in the allow-list
   with the reason.
4. **Link and load.** `readelf -d` of each shipped binary lists only `DT_NEEDED` entries
   of T-00 §3.2 rows marked "linked" (no `libva*`, no `libxkbcommon` outside the
   `xkbcommon` feature). A CI-N e2e step reads `/proc/<pid>/maps` of `apotheosis` after
   the first frame and of `apoth-media-helper` after media start (software ICD and no
   libva in CI; libva present in the class-M run), and asserts every mapped shared object
   is a T-00 §3.2 library or in the `DT_NEEDED` closure of a loaded Vulkan ICD or VA
   driver.
5. **Feature and graph assertions.** For every shipped feature set:
   - the release/packaging build's `cargo tree -e features` does not enable the `apoth-term`
     feature `esctest` (T-03 §3.3); presence fails the gate;

     built without the `gles`, `webgl` and `angle` features (T-07 header);
   - `cargo tree` contains no `ttf-parser`, `rustybuzz`, `fontdb` or `cosmic-text` (T-06 §1);
     cargo-deny `[bans]` lists `read-fonts` and `skrifa` with `multiple-versions = "deny"`
     for those crates;
   - no shipping crate's dependency graph contains `libfuzzer-sys` (the non-shipping
     `apotheosis/fuzz/` workspace is skipped entirely by `lang-rule.sh`, T-00 §3.1);
   - the resolved feature set of `rav1d` in every build contains no `asm_arm64_*` feature, and
     `asm` appears only for x86_64 targets with `av1-asm` on (T-16 §3).
Non-Rust files permitted: KDL, TOML, Markdown, WGSL shaders, the embedded shell snippets

  cursor position and style, mode state, **replies written to the PTY**, events emitted,
  scrollback excerpt.
- Fixtures are pure `apoth-term` tests: no PTY, no time, no GPU. `feed` must be
  deterministic — the same bytes in any chunking produce the same state; the harness
  re-runs every fixture with chunk sizes 1, 7, 4096 and random splits.
- `cargo xtask fixture new|bless|show` creates, updates and pretty-prints fixtures;
  blessing is never automatic in CI.
- Every T-03 conformance row cites at least one fixture id; a test fails if a row has
  none (the conformance table is machine-readable).
- Target counts: 300 at M9, 1 500 at M13, 3 000 at M31.

## 2. Differential oracles
`vte` + `alacritty_terminal` (dev-dependencies) are driven with the same bytes; grids
are compared cell-by-cell under a documented exclusion list of intentional differences
(each exclusion cites a T-03 row). Disagreement without an exclusion fails. Oracles
detect accidents; they are never the specification.

## 3. External conformance suites
`vttest` (scripted through a PTY driver with expected-screen checkpoints for the
automatable menus; the remainder is a class-M checklist), `esctest2` subset run headless
against the real binary, the kitty keyboard and graphics protocol examples from their
specifications, `notcurses-info`/`chafa`/`timg` capability smoke runs, and the
Unicode width and grapheme test files (T-04). Suites are fetched by a dev script into
`~/.cache/apotheosis-suites/`; they are tools we run, not code we ship or read for
implementation.

## 4. Property and fuzz tests
`proptest`/`arbtest` generators for byte streams (structure-aware: valid sequences with
mutated parameters), grid operations, reflow round-trips, selection, pins, config edits,
match-language and template inputs. Invariants are stated per section. Fuzz targets
(T-18 §11) live in `apotheosis/fuzz/`, a separate workspace excluded from packaging and
from the whole language-rule check (`lang-rule.sh` skips `apotheosis/fuzz/`).

## 5. Render goldens
`apoth-render` renders offscreen on the software Vulkan adapter (lavapipe) at fixed
size and scale into PNG; comparisons use a per-pixel tolerance plus a structural
threshold so driver rounding does not flake. Goldens cover glyph placement, decorations,
cursor shapes, selection, images, every glass surface state. Atlas and shaping tests
that need no GPU live in `apoth-font`/`apoth-ui`.

## 6. Headless end-to-end driver
- `apoth-testkit::session` starts `ec-abyss --backend headless` (pid captured, killed by
  pid; never by name), launches `apotheosis` inside it, and drives it through (a) the
  control socket, (b) synthetic input via the compositor's test input path, (c) PTY
  scripts. It captures screenshots through the compositor's screenshot path and reads
  grid text through `pane.text`.
- This is the only way agents exercise the UI: never a visible window, never the live
  session.
- A minimal test compositor fixture (for protocol-absence tests, T-09 §8) is a dev-only
  binary built on the pinned Smithay.

## 7. Recording and replay
`apoth record` (dev builds only) captures a session's PTY output with timing into a
`.apothrec` file; `apoth replay` feeds it headless or at speed. Recordings of real
programs (shells, vim, tmux, htop, less, fzf, git log, cargo) form the regression
corpus. Recordings never include input bytes, and the recorder refuses to run while the
pane is in the credential state.
