| INPUT-01 | Kitty keyboard protocol, all five flags (disambiguate 1, event types 2, alternate keys 4, all keys as escapes 8, associated text 16) | Full CSI u encoder: `key:shifted:base ; mods:event ; text u`. Flags live in a push/pop stack of 8 per screen (main and alt swapped on screen switch; pop on empty resets to 0; push on full evicts the oldest). Set (`CSI = f ; m u`, modes 1/2/3), push (`CSI > f u`), pop (`CSI < n u`), query (`CSI ? u`). ## Open questions

- kbvm vs libxkbcommon as the default (INPUT-07): kbvm maturity and Compose/layout parity are still unverified; the differential corpus and oracle design are specified in gap-kbvm-accesskit-parity-checks but not yet run.
- Should key sequences (INPUT-27) have a default per-key timeout, given ghostty has none and wezterm/kitty do? Proposed: on, 1000 ms, configurable.
- Is modifyOtherKeys (INPUT-11) kept at "should" or raised to "must" if tmux compatibility tests require it?
- Global shortcuts (INPUT-29): which Abyss IPC interface registers them, and portal fallback behaviour on other compositors, is undecided.
- Smart-selection rules (INPUT-38) in iterm2 were not verified from primary sources.
- Warp docs for syntax highlighting (INPUT-55) were navigation-only and not verified.
- Whether legacy encodings 1005/1015 (INPUT-20) are worth shipping at all.
