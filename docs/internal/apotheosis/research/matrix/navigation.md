## navigation

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| NAVIGATION-01 | Hint mode: labelled on-screen matchers | Overlay snapshots the viewport, joins wrapped rows into logical lines with a byte-to-cell map, runs each enabled matcher (built-in url/path/file:line/hash/ip/word, OSC 8 ranges, user regex), de-overlaps results, labels them, filters by typed prefix, then runs the matcher's Action list on the pick. Multi-select with a joiner. Named regex groups become action arguments. User matchers are KDL data, no scripting. | KDL `hint "name" { regex; action ...; persist; multiple }`; Actions `hint.open`, `hint.copy`, `hint.paste`, `hint.select`, `hint.run`; mouse/key bindings; CLI `ec-term hint <name>` | must | kitty, wezterm, foot, alacritty, rio, ghostty (requested) | Five mature terminals ship it and it is the headline keyboard feature. Foot's logical-line join is adopted so wrapped URLs match; wezterm's `then-action` and alacritty's action list are both subsumed by the shared Action vocabulary. Matchers in KDL replace kitty's Python and wezterm's Lua. |
| NAVIGATION-02 | Prefix-free label allocation | Minimal-length labels from a configurable alphabet, such that no label is a prefix of another. Longer labels only when matches exceed the alphabet size (breadth-first expansion, as in foot; equivalent to wezterm's compute_labels_for_alphabet). Labels are drawn nearest-to-cursor first. Dedupe identical match text onto one label. | KDL `hints { alphabet "asdfghjkl"; label-style ... }` | must | kitty, wezterm, foot, alacritty | Wezterm and foot both produce minimal prefix-free sets; alacritty's incrementing counter with split ratio is less compact. Pick the BFS/minimal form: single keystroke for the common case, no ambiguity at commit time. |
| NAVIGATION-03 | Match post-processing and revalidation | After a regex match, trim trailing punctuation and unbalanced brackets, re-checking the trimmed span still matches (alacritty HintPostProcessor technique). At activation, re-run the matcher at the stored start cell so a match that scrolled or changed is rejected rather than used. | KDL `hint { trim "default"; revalidate #true }` (defaults on) | should | alacritty, foot (url trim) | Cheap correctness: avoids pasting wrong text or `url).`. Only alacritty documents both; defaults on because there is no reason to disable. |
| NAVIGATION-04 | Default hint set and safe open routing | Ship built-in matchers for URL (common schemes), absolute/relative paths with optional line:col, git hashes, IPs, UUIDs. Default URL hint bound to a key and ctrl-click. Open goes through the Action `open` which uses the portal on Abyss (consent prompt) and falls back to xdg-open on other compositors. | Built-ins named `url`, `path`, `hash`, `ip`; binding `ctrl+shift+o` default; `open` Action | should | alacritty, kitty, foot, rio, konsole | Every terminal that ships hints ships a URL default. Routing through consent matches the EclipseOS no-ambient-authority stance. The path regex must not need lookbehind (rio needs Oniguruma for that); use a Rust regex engine with hand-written boundary checks. |
| NAVIGATION-05 | OSC 8 hyperlinks | Parse `OSC 8;params;URI ST`; empty URI closes. The `id` param joins non-contiguous cells into one link for hover and hint. Hover shows the URL in the status area. Click or hint opens only through an Action, with a scheme allow-list (default http, https, mailto, file with host check, ssh). Links participate in hint mode as a matcher. | KDL `hyperlinks { schemes ...; modifier "ctrl"; hover-style }`; Action `open` | must | Escape-registry spec; kitty, foot, wezterm, iterm2, konsole | The universal link mechanism for ls, gcc, ripgrep. The allow-list is the security boundary, since the URI is attacker-controlled. Spec: https://gist.github.com/egmontkob/eb114294efbcd5adb1944c9f3cb5feda |
| NAVIGATION-06 | Semantic history and hotspot filter chain (file:line) | A filter chain over the displayed text produces hotspots with tooltip and Actions: URL, existing-file (resolve relative path against the pane cwd, stat before offering, accept `:line:col` and `(line,col)`), colour, and user regex. Click resolves to an editor command template with `{path}`, `{line}`, `{col}` placeholders. OSC 8 `file://...#line:col` handled the same way. | KDL `editor { command "..." }`; `hotspots { modifier "ctrl" }`; Action `open-path` | must | iterm2, konsole, kitty, wezterm | Daily productivity feature. Only offering paths that exist avoids false underlines (konsole FileFilter technique). The template is typed placeholders, not a shell string, to avoid injection. |
| NAVIGATION-07 | Smart selection with precision classes and context actions | Double-click or the Action `smart-select` tests rules containing the cursor cell; per rule take the longest match; highest precision class with any match wins, then score. Each rule carries an Action list shown in a context menu, with `\0..\9`, cwd, user, host substitution. | KDL `smart-select { rule "name" { regex; precision "high"; action ... } }`; Action `smart-select` | must | iterm2 (kitty, wezterm via hints/word rules) | iTerm2's ordering is deterministic and fully specified, so it is the one to copy. Context actions reuse the Action vocabulary rather than a second mechanism. Merged with iTerm2 actions-and-substitutions row. |
| NAVIGATION-08 | Copy (vi) mode as pure motion functions on a rebindable key table | Copy mode is a cursor point plus a motion function `(grid, motion) -> point`; viewport follows. Keys live in a named key table of Actions, so every motion is bindable and shown in the settings GUI. | KDL `keytable "copy-mode" { bind ... }`; Actions `copy-mode.enter`, `cursor.move motion=...`, `selection.toggle kind=...`; JSON control socket exposes the same | must | alacritty, wezterm, tmux, rio, contour | Pure functions are unit-testable (alacritty vi_mode.rs) and the table form is what wezterm and tmux ship. | NAVIGATION-09 | Vi text objects including command blocks | `i`/`a` objects for word, WORD, paragraph, brackets, quotes; `im`/`am` for a command block or output (needs shell integration). ### Open questions

- Hint regex engine: which crates.io engine gives lookbehind-free paths that are fast enough over the viewport, and is a hand-written boundary check enough for URL/path (NAVIGATION-04)?
- Undo close (NAVIGATION-26): how long may a closed pane's process live hidden, and does it interact with the sandbox and resource limits?
- Whether block navigation (NAVIGATION-15) is available only with shell integration or also via heuristic prompt detection; the rows do not settle a fallback.
- Settings GUI representation of the copy-mode key table (NAVIGATION-08): the rows say bindable, not how the GUI shows chords across modes.
- Frecency weighting constants (NAVIGATION-22) were not given; iTerm2 documentation is unspecific. Unverified.
- Whether palette history and recent-dir data are persisted, and the retention default (privacy).
- Konsole script-aware word modes (NAVIGATION-13): whether UAX 29 segmentation alone is sufficient; unverified.
