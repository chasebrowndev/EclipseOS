## vt-core

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| VTCORE-01 | Separable terminal core crate | Grid, parser driver, selection, search, damage and PTY loop live in a crate with no windowing, Wayland or wgpu types; GUI, mux, control socket and tests consume it. | internal | must | alacritty | Headless tests, benchmarks, a sandboxed or remote core, and reuse by the control socket all depend on it. |
| VTCORE-02 | Packed 8-byte cell with style and extras side tables | Cell is a u64: codepoint (21 bits), wide state, flag bits, content tag, style id, extras id. Zero-width marks, grapheme tails, hyperlink and graphics refs live in an extras table; default cell needs no lookup and rows stay memcpy-able. Ghostty's 64-bit layout (24-bit content, style id, protected, hyperlink, semantic bits) and Rio's are near-identical; take whichever fits grapheme clusters. VTE's 20-byte and tmux's spill-record cells are budget references only. | internal | must | ghostty, rio, alacritty, vte-konsole, tmux-zellij | Three mature designs converge on 8 bytes; per-cell heap (alacritty Arc extra) or 20+ byte cells cost too much at 100k-line scrollback across many panes. Grapheme clusters force an extras concept, so alacritty's char-per-cell is not copied. |
| VTCORE-03 | Background-only cell tags | A content tag marks cells that are only a palette or RGB background; the colour sits in the content bits, so they never touch the style table. | internal | should | ghostty, rio | Large blank coloured regions (TUIs, selection, cleared lines) skip style interning; cheap once VTCORE-02 has a content tag. |
| VTCORE-04 | Ref-counted style interning | Per-grid (per-page) table of packed styles (fg, bg, underline colour, SGR flags); id 0 is default; open-addressed table over a flat item array so ids are item indices and refcount changes skip hashing; dead items reclaimed lazily; a full table grows capacity. | internal | must | ghostty, rio | O(1) style access and small cells; ghostty's Robin Hood table at 0.8125 load is the proven concrete choice. | VTCORE-05 | Row hint flags and occupancy high-water mark | Each row carries one-sided flags (wrap, continuation, grapheme, styled, hyperlink, semantic prompt) that may false-positive, never false-negative, plus an upper bound of modified columns since reset. | VTCORE-08 | Wide-char spacers and seam repair | Wide chars use a spacer cell; a leading-spacer state marks a wide char split by soft wrap; erase and insert name the seams they cut and repair them in O(1), preserving the wrap flag. | internal | should | alacritty, rio, ghostty | Prevents half-glyph corruption and false hard breaks on reflow. |

### Open questions

- Ring buffer (alacritty, rio) versus paged list (ghostty) for scrollback: ring is O(1) scroll but per-page style tables and compressed or shared scrollback for many panes need a decision (VTCORE-04, -06).
- Cell layout: bit budget for graphemes (extras id width) and graphics refs; is 16-bit style id per grid enough or must it be per page?
- Exact numbers and report syntax for theme/visibility modes (2031, 2033, 996, 998, 999) and 2048 were not verified (VTCORE-18).
- iTerm feature-reporting syntax unverified (VTCORE-39).
- Sync-output timeout default and whether to cap total hold time.
- Which DA1 feature codes to claim honestly for the implemented subset.
- vttest licence terms to confirm before bundling anything.
