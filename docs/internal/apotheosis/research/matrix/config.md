## config

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| CONFIG-01 | Single option schema table | One Rust table (key, type, default, constraints, scope, doc text, widget) generates the KDL parser, validation, settings GUI pages, docs, `config show` and the socket's get/set. Doc text lives in the table. | schema table; `apo config show`; settings GUI | must | kitty (options/definition.py), ghostty (Config.zig doc comments, helpgen.zig), windows-terminal (MTSMSettings.h), tmux (options-table.c), wave (counter-example), topic-config-automation | Only way to guarantee "every setting in GUI and KDL" with no drift. Wave's conn:enablewsh vs conn:wshenabled mismatch is the failure case. Data table beats derive-macro-only because the GUI and docs need the same metadata at runtime. |
| CONFIG-02 | Cascading layers with optional-per-layer values and scopes | Every setting optional per layer; getter walks parents. Order: built-in defaults < Abyss/system defaults < user file < includes/profile fragments < `profiles.defaults` < profile < CLI `-o` < runtime override. Option scope (global/window/tab/pane) is declared in the schema. | `profiles.defaults`, per-profile keys; schema scope field | must | windows-terminal (IInheritable.h, FinalizeLayering), tmux (options.c parent chain), zellij (options.rs#merge), topic-config-automation | Sparse files and inherited/overridden indicators need a real layer model. tmux scopes give per-pane settings without a second mechanism. |
| CONFIG-03 | Config introspection CLI | Subcommands over the same parser: `validate` (non-zero exit on error, line-numbered), `show` (effective merged, with layer of origin), `explain <key>`, list actions/keybinds/themes. | `apo config validate/show/explain`, `apo actions list` | should | ghostty (+validate/+show/+explain-config), foot (-C, exit 230), topic-config-automation | CI for dotfiles and layering debugging. Origin-layer output is our addition. List verbs for ghostty are unverified. |
| CONFIG-04 | Published KDL schema for editors | Emit a KDL schema/completion file from the option table at build time. | generated file | could | windows-terminal (settings JSON schema) | Free once CONFIG-01 exists. |
| CONFIG-05 | Keybind grammar | Trigger = modifiers (any order) + one key. Key may be a produced character, a physical key name (explicit `physical:` prefix, physical wins on conflict), or `catch_all` (modified tried before bare). Multi-key sequences `ctrl+a>b`, `combine` for action lists, `mouse_map` (button + mode). Match mode (keysym / keycode / base-layout symbol) selectable so shortcuts work on non-Latin layouts. All bind the shared Action vocabulary. | `bind` nodes; `mouse-bind`; `keyboard.layout-independent-binds` | must | kitty (map, combine, mouse_map), ghostty (Binding.zig Trigger), wezterm (keys docs), topic-keyboard | Combines kitty's sequences/combine/mouse grammar with ghostty's explicit physical-vs-unicode rule. An explicit prefix is clearer than guessing. |
| CONFIG-06 | Per-profile/rule keyboard overrides | Profiles and rules can swap bind sets and switch kitty/modifyOtherKeys modes. | `profile { keyboard { } }`, rule actions | should | topic-keyboard (internal design) | Legacy-tool compatibility without a global compromise. Single-source row. |
| CONFIG-07 | Includes and imports | `include` with relative, glob and optional forms; later overrides earlier; recursion depth cap; each include has its own scope for errors. Theme files and Abyss system defaults arrive through the same mechanism. | `include`, `include-glob`, `include optional=true` | must | alacritty (config/mod.rs#load_imports), kitty (include/globinclude), foot (include=), topic-config-automation | Three mature terminals ship it. Kitty's glob/optional forms added for per-machine dotfiles. |
| CONFIG-08 | CLI `-o` overrides and launch-flag overrides | `-o path=value` and flags (command, cwd, title, app-id, hold) form an Overrides layer applied after config load and re-applied on every reload. | `-o key=value`, `-c`, launch flags | must | foot (-o), alacritty (cli.rs), rio (cli.rs Overrides::apply), kitty (-o) | Hot reload must not discard per-window launch intent (rio). |
| CONFIG-09 | Runtime overrides scoped to window/tab/pane | `Set{path,value,scope}` action stores data in a transient override layer on that scope; resettable (`Reset{path,scope}`, global reset); survives reload; shown in GUI as an override. Setting an identical value emits no change event (loop guard). | Action `set`/`reset`; `apo set`; socket `set` | must | wezterm (set_config_overrides), alacritty (msg config, --reset), kitty (set-* remote), topic-config-automation | Data overrides rather than wezterm's handler-returns-table avoid its documented reload loop. Alacritty's -1 for all windows maps to scope `all`. |
| CONFIG-10 | Runtime-only appearance actions | Named actions (toggle-opacity, set-font-size, set-colors, set-spacing) as sugar over CONFIG-09; never write the file. | actions; palette | should | ghostty (issue #5047), kitty (remote-control set-*) | Demonstrated demand in two terminals. Unifying them with Set keeps one mechanism. |
| CONFIG-11 | Config watcher | Watch parent directories of config and every include, canonicalise symlinks but remember base paths, short debounce, poll fallback, rebuild watch set when the include list changes. | automatic; `reload` action/SIGUSR1 | must | alacritty (config/monitor.rs#ConfigMonitor::new), rio (watcher.rs), wezterm (config/src/lib.rs#watch_path), kitty (SIGUSR1) | Handles atomic-rename editors and symlinked dotfiles. Parent-dir watching is the right technique. |
| CONFIG-12 | Atomic apply with keep-last-good and diagnostics | Parse into a fresh model, collect all errors (file, line, key), apply only if valid; per-field tolerance drops bad entries (bad binds) with a warning. Errors show as glass toast and in the settings GUI. | toast; settings GUI error list; `validate` | must | alacritty (event.rs ConfigReload, ui_config.rs#deserialize_bindings), ghostty (ErrorList.zig), wezterm (config_builder rejects unknown keys) | Never brick the terminal on a typo. Unknown keys are errors with did-you-mean, not silent. Per-field tolerance vs all-or-nothing: error-list collection, apply valid remainder only for non-structural fields; open question below. |
| CONFIG-13 | No live reload | Not adopted: parse-once, new windows only. | | no | foot | We hot-apply file and GUI edits. |
| CONFIG-14 | Comment-preserving KDL round-trip editing | GUI and `config set` edit a lossless KDL document model (comments, order, unknown nodes kept), changing only affected nodes. | settings GUI; `apo config set/get` | must | zellij (config_file_edit.rs), windows-terminal (issue #2933 complaints), topic-config-automation | File stays authoritative. Zellij shows the technique works with KDL. |
| CONFIG-15 | Whole-file rewrite on save | Not adopted. | | no | windows-terminal (WriteSettingsToDisk, inferred) | Loses comments and ordering. |
| CONFIG-16 | Atomic write plus self-write suppression | Write temp+rename; record content hash and mtime; watcher ignores events matching it; reload throttled. | internal | must | windows-terminal (_writeSettingsToDisk, ReloadSettingsThrottled) | Prevents GUI-to-watcher reload loops. |
| CONFIG-17 | Inheritance indicators and reset in GUI | Each control shows inherited-from layer, overridden state and a reset button; changed-only filter. | settings GUI | must | windows-terminal (cascading-settings spec), tmux (customize-mode) | Required for GUI/text parity with CONFIG-02. |
| CONFIG-18 | Settings browser for every option | GUI lists all options generated from CONFIG-01, searchable, changed-only filter; CLI `config get/set` equivalents. | settings GUI; `apo config get/set` | must | tmux (window-customize.c), zellij (configuration plugin) | Direct requirement. |
| CONFIG-19 | Schema version and migrations | `version` node; ordered migrators rename keys and flag rewrite; rename compatibility table so old keys warn and map; `apo config migrate` with dry-run. | `version`, `apo config migrate --dry-run` | should | alacritty (migrate/mod.rs), windows-terminal (FixupUserSettings), ghostty (compatibility table) | Three terminals do renames. Migrations go through CONFIG-14 so comments survive. |
| CONFIG-20 | Importers from other terminals | One-shot import of foot.ini and alacritty.toml (and kitty.conf if time) into KDL. | `apo config import <file>` | should | foot, alacritty (rows suggest) | Adoption path. Source rows say "required"; kept should since single-source. |
| CONFIG-21 | Light/dark theme pair | `theme light=X dark=Y` following portal colour-scheme and Abyss theme changes; CSI ? 996 n report and DECSET 2031 push; SIGUSR1/2 and switch/toggle actions kept; initial theme setting. | CONFIG-22 | Theme gallery with live preview | GUI gallery applying a theme by writing one include or `theme` node; seeds derived from Abyss ec-theme. | settings GUI | could | kitty (themes kitten) | Nice-to-have atop CONFIG-21. |
| CONFIG-23 | Typed `when` conditions | `when` block over closed predicates (os, host, compositor, scheme, battery, output scale); no expressions. | `when` node | should | ghostty (conditional.zig), kitty (KITTY_OS), topic-config-automation | Common dotfile branching without scripting. |
| CONFIG-24 | Profiles with inheritance and override protection | Profile = property bag (shell, theme, fonts, binds, env, init scripts) with parent inheritance; per-session runtime tweaks tracked so reapplying a profile does not clobber them unless asked. | `profile` nodes; action `set-profile`; `apo profile list/apply` | must | vte-konsole (Profile.cpp, ShouldApplyProperty.cpp), windows-terminal, iterm2, topic-config-automation | Core requirement. | CONFIG-25 | Automatic profile switching | `match` on user, host (exact or wildcard), path wildcard, job; additive score (exact host 16, wildcard host 8, job 4, user 2, exact path 1) picks the best; per-pane profile stack (match existing pops above, no match empties); `sticky` keeps. | `profile { match user host path job sticky }`; rule event connect | must | iterm2 (automatic profile switching docs), topic-config-automation | Concrete tested scoring; sane revert semantics. |
| CONFIG-26 | Dynamic profile sources | Watched dir `profiles.d/*.kdl`, per-file error isolation (iTerm2's one bad file blocks all is rejected); optional generators for ssh hosts, distrobox, toolbox tagged with source. | `~/.config/apotheosis/profiles.d/`; `hidden`, `source` | should | iterm2 (dynamic profiles), windows-terminal (generators), topic-config-automation | Two mature terminals ship it. ### Open questions

- CONFIG-12: apply valid remainder with per-field tolerance, or whole-file reject on any error? Proposed: whole-file reject for structural errors, per-field drop for binds and rules.
- Which colour-scheme source takes priority between portal colour-scheme and Abyss ec-theme when both exist?
- CONFIG-20: how many importers at launch, and do they need round-trip fidelity?
- CONFIG-25: is the iTerm2 scoring weight set right for Linux (no remote job names without shell integration)?
- Ghostty list/validate action names were unverified in the input rows.
- Do includes carry a trust boundary (profiles.d from untrusted dirs)?
