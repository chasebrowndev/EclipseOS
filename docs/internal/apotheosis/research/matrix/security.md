## security

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| SECURITY-01 | OSC 52 clipboard policy | Separate read and write gates per target (c to Wayland clipboard, p/s to primary), each `allow`/`deny`/`ask`. Default: write ask-or-allow from the focused pane only, read always ask. Payload size cap, never log contents. Ask goes through the glass prompt (Abyss trusted UI consent on Abyss). Primary selection implemented via the primary-selection protocol, not only wl_data_device. | KDL `security { osc52 { write; read; max-bytes } }` per profile; GUI toggle | must | xterm, kitty (clipboard_control), ghostty (clipboard-read/write), foot (osc52), alacritty (Osc52 modes), rio, vte-konsole, topic-escape-registry | Every terminal ships it. Foot/alacritty enum modes are too coarse; kitty and ghostty ask variants plus per-direction gating are the best model. Defaults tighter than all of them (read never silent). |
| SECURITY-02 | Kitty clipboard protocol (OSC 5522) with write bound | Streaming base64 chunks, MIME-typed read/write, id sanitising, strict base64, in-flight transaction replacement. Buffered writes bounded (ghostty uses 64 MiB; ours configurable). Same allow/deny/ask policy as SECURITY-01. | `clipboard-write-limit-bytes`; shares osc52 policy | should | ghostty, kitty | Richer than OSC 52 and the memory bound is the key hardening. Needs the same consent path. |
| SECURITY-03 | Paste safety and bracketed paste | Bracketed paste (2004) with embedded CSI 201~ stripped and C0 controls (BS, DEL, ENQ, EOT, ESC, NUL, stty specials) neutralised, tab/newline kept. When mode is off, or text is multi-line or large, confirm in glass prompt (optionally only at a shell prompt, via semantic marks). Optional tab-conversion prompt, URL quoting, paste-slowly. | `paste { sanitize; confirm-multiline; confirm-bytes; paste-slowly }`; Action `paste-slow` | must | xterm, kitty (paste_actions), ghostty, iterm2, windows-terminal, topic-escape-registry | Universal. Unify xterm's neutralisation with iterm2's confirmation UX; use ghostty's bracketed-safe idea (skip confirm when mode 2004 is active and content sanitised). |
| SECURITY-04 | Capability policy gates per feature class | One policy table in KDL: colour ops, font ops, mouse ops, termcap, title ops, window ops, selection ops, each with `allow`/`deny`/`ask` and named sub-features (xterm disallowed* lists with wildcards). Escape sequences can never change policy; only GUI/KDL/socket can. Denied sequences are silent-drop plus a counter. | `security { <class> { <subfeature> "deny" } }` per profile; settings GUI matrix | must | xterm | Best structured model (named sub-features beat boolean switches). Defaults stricter than xterm. |
| SECURITY-05 | Policy introspection (XTQALLOWED/DISALLOWED/ALLOWABLE) | OSC 60, 61, 62 reply with comma lists built from policy state. | OSC 60/61/62 | should | xterm | Lets programs and tests detect blocks instead of timing out. Only xterm ships it, but it is cheap and pairs with SECURITY-04. |
| SECURITY-06 | Title and icon label reporting | CSI 20/21 t reporting default deny (or hex-only via title modes); every title shown in glass tabs has control characters stripped and length capped. Title stack push/pop (22/23) allowed. | `security { title-report "deny" }` | must | xterm, topic-escape-registry | Classic injection vector; xterm title modes (raw/hex/UTF-8) are the best technique, but deny-by-default is simpler and enough. |
| SECURITY-07 | XTWINOPS safe subset | Allow reports 14, 16, 18, 19 (pixel and cell sizes, needed by image tools) and 22/23. Deny 21. Move/resize/raise/iconify/fullscreen: ask or deny, rate limited, routed through the compositor on Abyss (Wayland cannot honour moves anyway). | `security { window-ops { report-size "allow"; manipulate "deny" } }` | must | xterm, topic-escape-registry | Two rows agree; merged. Reports are required by graphics clients, manipulation is not. |
| SECURITY-08 | Font set/query (OSC 50) | Ask or deny; restricted to installed family names, no paths; query reply never exposes local config. | `security { font-ops "deny" }` | could | xterm | Niche; leaks fontconfig and path abuse risk. Only if a use case emerges. |
| SECURITY-09 | ENQ answerback empty | ENQ returns a configurable string, empty by default. | `security { answerback "" }` | must | xterm, topic-escape-registry | Non-empty answerback is a PTY injection channel. |
| SECURITY-10 | DECRQSS generated-only replies | Support SGR, DECSTBM, DECSCUSR, DECSCA; reply built from internal state, never echoing request bytes. | DCS $ q | should | xterm, topic-escape-registry | Needed by some apps; echo bugs are a known class (iTerm2 CVE-2022-45872, unverified id). |
| SECURITY-11 | Legacy OSC 777 / OSC 666 hardening | Legacy urxvt-style 777 handlers (precmd, preexec, container) off by default; strings length-capped; termprops blocklist and well-known type enforcement. | `security { osc777-legacy "off" }` | must | vte-konsole | Escape-driven features are attack surface; default off. |
| SECURITY-12 | Notification (OSC 99) id and payload sanitising | Identifier charset restricted and sanitised on echo; plain text only, no markup; C0/C1 forbidden unless base64. | OSC 99 `i=`, `e=1` | must | kitty | Stops escape injection through reports. |
| SECURITY-13 | Policy conformance tests | Policy tests run twice, window ops allowed and denied, asserting identical safe behaviour in the denied case. | test suite | should | xterm (esctest2) | Cheap regression net for SECURITY-04/07. |
| SECURITY-14 | Graphics file/shm medium policy | Medium as capability flags: direct always; file (t=f) regular files only; temp (t=t) deleted only if under a known temp dir and path contains `tty-graphics-protocol`; shm (t=s). Refuse devices, sockets, /proc, /sys, /dev. Default local sessions only; prompt mode for others. All read failures return one identical error (no filesystem existence oracle). | `media { file-transmission "off\|local-only\|always\|ask" }`; per-pane rule | must | kitty, ghostty (Limits), topic-graphics, topic-escape-registry, topic-media | Five rows converge. Ghostty's Limits struct is the cleanest shape; kitty's uniform error is the key trick. |
| SECURITY-15 | Image storage quota with LRU eviction | Per-screen byte counter (kitty and ghostty 320 MiB default); oldest/least recently used evicted on overflow; 0 disables the protocol. | `media { max-image-memory }` | must | kitty, ghostty | Primary DoS defence. |
| SECURITY-16 | Dimension and payload caps before allocation | Reject width/height over 10000 and payload over 400 MB (kitty) before allocating; check w*h*4 against budget; sixel capped at 10000 px with canvas growth clamped; iTerm2 inline capped (wezterm 100,000,000 bytes). | `media { max-dimension; max-payload }` | must | kitty, foot, wezterm, topic-graphics | Same defence across protocols; one shared budget. |
| SECURITY-17 | Sandboxed decoder worker | PNG/JPEG/GIF/WebP decoded in seccomp/Landlock helper returning RGBA over pipe or memfd with dimension limits set on the decoder. | internal; reuses media helper | should | topic-graphics (design inference, unverified in other terminals) | Decoder bugs cannot reach the terminal process. Not shipped by a mature terminal, so should, not must. |
| SECURITY-18 | iTerm2 download mode (inline=0) | Not implemented. | n/a | no | topic-graphics | Arbitrary file write from output violates no ambient authority. |
| SECURITY-19 | Media surface lifetime and cleanup | Media surface and helper destroyed with the pane; images deleted on reconfigure/exit (mpv a=d behaviour); per-pane memory cap. | `media { max-image-memory }`; Action `media-close` | must | topic-media (mpv vo_kitty) | Crash or kill must not leak GPU memory or helpers. |
| SECURITY-20 | Hyperlink safety UX | Modifier-click or context menu to open, URI shown on hover, confirm unknown schemes, scheme allow-list, local `file:` only when host matches, option to disable. | `links { open-modifier; allowed-schemes; confirm-unknown; show-uri }` | must | vte-konsole (OSC 8 spec, Konsole allow-list) | Prevents deceptive link text and scheme handler abuse. |
| SECURITY-21 | Control socket authentication | Socket in XDG_RUNTIME_DIR, directory 0700, refuse directory not owned by user or with group/other bits (tmux, wezterm, zellij), SO_PEERCRED uid check on every connection. Filesystem permissions alone (alacritty) are rejected. | `control { socket-path }` | must | tmux, wezterm, zellij, topic-mux-remote, alacritty (as counter-example) | Same-uid processes are the threat; add per-client scopes (SECURITY-22). |
| SECURITY-22 | Per-client capability grants | Named capabilities (read pane contents, write input, run commands, read clipboard, manage layout), granted per socket client, cached, prompted via consent UI. Model borrowed from zellij plugin permissions. | `control { grant "<client>" { ... } }`; consent prompt | should | tmux-zellij (zellij) | We have no plugins but socket clients and add-ons need the same split. |
| SECURITY-23 | Key event stream opt-in and redacted | Subscription requires capability, per-pane opt-in, suppressed in no-echo state; never logged. | `apo events keys` | must | topic-keyboard (EclipseOS invariant) | Human input is never logged by content. |
| SECURITY-24 | Consent for command-running actions | Any action that runs a command or injects input and is triggered by output, link, import or rule needs explicit per-rule opt-in plus confirm-once. Prompt shows the command in a bounded monospaced box, ignores Return, activates only on explicit choice. Imported rule packs show a review dialog. | rules `{ requires-consent }`; glass/Abyss trusted prompt | must | iterm2, rio, topic-config-automation | Output-driven run-command is an injection surface; rio's prompt design is the best UX detail. |
| SECURITY-25 | Resurrected commands start suspended | Restored command panes show the command and wait for a keypress; layouts carry `start_suspended`. | layout `start-suspended`; restore confirmation option | must | zellij (two rows) | Avoids unseen re-execution of destructive commands. |
| SECURITY-26 | Session file and socket hygiene | Saved sessions in XDG state, mode 0600; password-role panes excluded; optional wipe-on-detach and idle lock. | `session { persist; wipe-on-detach }` | must | synthesis (zellij, wezterm, project invariants) | Persistence extends secret lifetime. |
| SECURITY-27 | Command rewrite for saved sessions | Exclude/rewrite rules in KDL that strip tokens or wrappers from saved commands (no shell hook). | `session { redact "<regex>" }` | should | zellij (post_command_discovery_hook) | Keeps secrets out of saved layouts without scripting. |
| SECURITY-28 | PTY fd and child lifecycle | Close-on-exec on every PTY fd (rio fixed a bug leaking panes' ptys into later shells); termination escalates after 1 s grace, bounded post-SIGKILL reap, signals reach descendants. | internal | must | rio | Concrete past security bug. |
| SECURITY-29 | Per-surface systemd scope | Transient scope per surface with optional memory and process limits so OOM hits one shell. | `process { cgroup; memory-limit; processes-limit; hard-fail }` | should | ghostty | Cheap isolation; Linux only, falls back silently without systemd user manager. |
| SECURITY-30 | Armed one-time-password channels | Terminal-initiated data transfers (DCS requests) validated against a request id and one-time password held in local shared memory, so arbitrary remote output cannot trigger transfers. | internal template for any terminal-armed channel | must | kitty (ssh kitten) | Template for any channel that moves data on request. |
| SECURITY-31 | Per-domain escape policy for remote panes | Remote panes get stricter default policy than local (clipboard, graphics medium, DCS channels), set per domain/profile, prompt-by-default. | `domain "<name>" { security { ... } }` | must | synthesis (kitty, wezterm) | Remote output is untrusted. |
| SECURITY-32 | Bounded buffers and reply caps | Output watermarks, minimum write size, max age, reply cap (tmux control: 512/8192 B, 300 s, 64 MiB); fuzz the codec. | internal limits | must | tmux | Hostile or stale peers must not exhaust memory. |

### Open questions

- OSC 52 write default: allow from focused pane silently, or ask once per session per pane? Rows disagree (xterm allow, topic-escape ask).
- Does `ask` fall back to deny when no trusted UI exists (non-Abyss compositor)? Glass prompt is ours, so probably prompt in-window, but spoofing resistance there is unproven.
- Should SECURITY-17 (decoder sandbox) be must given hostile image input, despite no mature terminal shipping it?
- kitty uniform-error and temp-dir rules: kitty/graphics.c function names unverified.
- Whether ghostty bracketed-safe skip of confirmation is safe when the shell mishandles 2004.
- Persisted scrollback spill (SECURITY-42) opt-in encryption design.
