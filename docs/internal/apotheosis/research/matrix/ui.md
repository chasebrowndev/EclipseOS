## ui

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| UI-01 | Glass background: opacity, alpha-mode, compositor blur | Alpha applies to default-background cells by default, with foot's alpha-mode semantics (default / matching / all) so coloured cells and text stay opaque; premultiplied output from the wgpu renderer; opacity changeable at runtime by Action. Blur is requested from the compositor (ext_background_effect_manager_v1, richer first-party protocol on Abyss); we do not blur in-process. | `colors { alpha; alpha-mode; blur }`, Action `set-opacity` | must | kitty, foot, alacritty | Core of the glass aesthetic. Three terminals ship it; foot's alpha-mode is the most precise rule for which cells are translucent. |
| UI-02 | Background image / window logo | Optional image drawn behind the grid inside the same wgpu pass, with position, opacity and scale. | `background { image; opacity; position }` | could | kitty | Single-source feature; cheap in our renderer but not essential. |
| UI-03 | Cursor trail | Four cursor-quad corners chase the target with a time-composable exponential ease-out (1 - 2^(-10 dt/decay)), which stays correct across irregular frame times under event-driven pacing; leading corners use a faster decay to form a smear; fades when the cursor is hidden; start threshold and decay pair configurable. | `cursor { trail { enabled; decay-fast; decay-slow; threshold } }` | should | kitty, rio | Two terminals ship it and users rely on it for orientation. Rio's composable easing chosen over fixed-duration tweens because it needs no per-frame state reset. Off by default. |
| UI-04 | Shared animation primitives | One spring and ease helper in the renderer used by tabs, overlays, quick-terminal slide, bell flash and trail; honours a global reduce-motion setting. | `ui { animation { enabled; reduce-motion } }` | should | rio, ghostty | Fluid motion is a stated aesthetic; one helper keeps chrome consistent. Rio's spring helper is the model. |
| UI-05 | Command registry | A single table of (name, brief, doc, Action, menu placement) from which palette, menus, settings keybind editor, CLI help and docs are generated. | Action vocabulary; event `augment-palette` becomes KDL `palette { entry }` | must | wezterm | One metadata source avoids drift between five surfaces. |
| UI-06 | Command palette with nested and iterated entries | Palette lists every registry command plus user entries; entries may nest and iterate over a collection (profiles, schemes, layouts, saved macros) like Windows Terminal iterateOn; user entries come from the same list as bindings. | `palette { entry { name; icon; actions } }`, Action `palette-open` | must | wezterm, windows-terminal | Palette is first-class and must surface user layouts and macros automatically. |
| UI-07 | Template language for tab titles, status and badges | Small expression language: variables (cwd, process, user vars, index, zoom, exit status, host), filters (truncate, basename), if/else, and style spans (colour, weight); no functions or scripting. Used by tab titles, status bars, badges and window titles. Konsole-style separate local and remote title formats are expressed as conditionals. | `tab { title "..." }`, `status { left; right }`, Action `rename-tab` | must | wezterm, konsole, kitty | format-tab-title and update-status are the main reasons people use Lua in wezterm; this covers them without a script engine. Wezterm's attribute-list builder rejected in favour of an inline template that the GUI can edit as text. |
| UI-08 | Tab bar | Glass tab strip drawn by the grid renderer with real depth; styles (floating, flat, hidden), max width, per-tab colour and activity colour, inline rename with IME, drag reorder. | `tabs { style; max-width; position }`, `tab { color }`, Action `rename-tab` | must | kitty, wezterm, rio, konsole | Tabs are core. Immediate-mode rendering (rio) is the simplest lifecycle; kitty's style list is the reference for variants. |
| UI-09 | Tab and pane status badges | Native indicators on tabs: unseen output, bell, progress (OSC 9;4), command running, tab status set by rules. | `tabs { badges { unseen; bell; progress } }`, Action `set-tab-status` | should | wezterm, iterm2 | Users depend on unseen-output cues. Native rather than template-driven so they work with defaults. |
| UI-10 | OSC 9;4 progress | Parse ConEmu states 0 remove, 1 normal, 2 error, 3 indeterminate, 4 paused/warning, with percentage; render as eased bar in the tab (about 0.2 s) and optionally forward to compositor/taskbar as a hint; clears on timeout if not refreshed. | `progress { forward-to-compositor }` | should | rio, wezterm, windows-terminal | Emitted by winget, cargo, systemd tools. Safe sequence. |
| UI-11 | Quick terminal / dropdown / hotkey window | Edge- or centre-anchored window with size, screen choice, slide animation, autohide on focus loss and keyboard-interactivity mode. On Abyss uses a first-party protocol; elsewhere wlr-layer-shell, disabled when absent. Modelled as a window role/profile (not a magic name), with the process resident after the last window closes. Toggled by Action, CLI or compositor binding. | `quick-terminal { position; size; screen; animation; autohide; keyboard }`, Action `toggle-quick-terminal`, `apo` CLI | must | ghostty, iterm2, windows-terminal, wezterm | Top-requested feature in several trackers (wezterm #1751, WT #9996). Role-based design chosen over WT's magic `_quake` name. |
| UI-12 | Pane frames, titles and border styles | Translucent rim and title per pane; modes full, titles-only, none; per-pane override and borderless flag; dim-inactive option; focus = brighter fill plus crisp rim, not a glow. | `panes { frames; border-style; dim-inactive }`, per-pane override | must | zellij, tmux, konsole | Needed for splits; per-pane override and titles-only mode come from zellij. |
| UI-13 | Visual pane select | Overlay of short labels on panes; typing a label focuses it (or targets another Action). | `pane-select { characters }`, Action `pane-select` | should | kitty, wezterm | Palette-free pane jump, shipped twice. |
| UI-14 | Typed prompt Actions: Pick, Prompt, Confirm | Actions open glass UI (list picker, text line, yes/no) then run a `then` action list with `$input` / `$choice` variables, replacing Lua callbacks. | Actions `pick`, `prompt`, `confirm` with `then { }` | should | wezterm | Enables interactive macros without scripting. |
| UI-15 | Character / emoji picker | Searchable Unicode and emoji picker overlay that inserts into the pane. | Action `char-select` | should | wezterm, kitty | Two terminals ship it (kitty unicode input); easy in the glass UI. |
| UI-16 | KDL context menu | Right-click menus per target (pane, tab, bar, common) of item / separator entries that run Actions, with toggled labels, after/before placement, remove and clear-defaults so users patch defaults without copying them. | `context-menu { pane { item; separator; remove } }` | should | zellij, wezterm | Same Action vocabulary drives menus; zellij's patch semantics are the best merge model. |
| UI-17 | Popup / command overlay pty | Floating pane that runs a command in its own pty with size, close-on-exit and auto-size; modal option. | Action `popup { command; size; close-on-exit }` | should | tmux, zellij | Fuzzy pickers and git UIs in a float are heavily used; treated as a floating pane, not a separate subsystem. |
| UI-18 | Settings GUI with full parity | Pages generated from the option table with search; edits go to the same model as the KDL; live apply with undo, plus a preview terminal; per-setting "show in KDL" jump and open-file action. | UI-19 | Theme pair following system light/dark | `theme` accepts a light/dark pair switched with the system or compositor theme; chrome and panes both switch; report via DEC mode 2031; optional hue override when detection is wrong. | `theme { light; dark; follow-system; hue }` | should | windows-terminal, tmux, zellij | Three tools ship it; Abyss gives compositor-level sync. |
| UI-20 | Per-host colour scheme | Rule on ssh/host change applies a scheme variant (dark and light) to the pane as a production-host cue; restored on exit. | rule `on host-change -> set-scheme` | could | kitty | Only kitty ships it; falls out of the rules engine for free. |

## Open questions

- Which compositor-side protocol does Abyss expose for quick terminal and blur beyond ext_background_effect_manager_v1? Needs an Abyss spec decision.
- Sticky command header and block status chrome in Warp are unverified; confirm behaviour or design from first principles.
- Is UI-27 copy-block split into must (copy) and should (chrome)? Left merged.
- Remote mux (lag indicator, UI-33) depends on whether Apotheosis ships a mux server; unresolved.
- Cursor trail default (off) and global reduce-motion interaction with UI-04 need a UX decision.
- Template language grammar (UI-07) is shared by titles, status, badges and rules; needs its own spec to avoid becoming a scripting language.
- UI-02 background image: confirm decode path (shared with the media decoder helper or a plain image crate).
