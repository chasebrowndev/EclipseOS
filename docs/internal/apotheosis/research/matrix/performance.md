## performance

Merged from the per-terminal and per-topic surveys. "Seen in" names the sources of the input rows. Settings named below are proposed KDL keys under `performance { }` / `media { }`; each is also exposed in the settings GUI, as an Action, and over the control socket. Source locations are those cited in the input rows; items marked "unverified" were not verified.

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| PERFORMANCE-01 | Event-driven render loop, zero idle wakeups | Render only when PTY data, input, a timer (blink, animation) or resize dirties state. One central timer queue on a calloop timer source drives blink, bell and animations, so the loop sleeps otherwise. | internal; `performance { animation-fps }` | must | foot, kitty, ghostty, alacritty, wezterm | All mature terminals do this. Energy and latency. wezterm's separate low cap for easing effects (default 10 fps) is adopted so blink and fades do not pull full-rate frames. |
| PERFORMANCE-02 | Wayland frame-callback pacing state machine | Per-surface state None/Requested/Received. Request the frame callback at present time, never speculatively. A callback requested with no commit never fires and wedges the loop. Redraw only when none is pending. Pacing follows compositor callbacks, not a timer. `wp_presentation` refresh prediction can refine the schedule. | `performance { frame-pacing }`, `max-fps` (ignored on Wayland, as in wezterm) | must | rio, kitty (`sync_to_monitor`), wezterm, vte-konsole (GNOME 46), rio vblank throttle | Pacing matters more than parse speed (GNOME 46 VTE result). We choose frame callbacks over rio's mHz-derived one-shot timer because the callback is the compositor's own truth and handles VRR and multi-monitor. The wedge comment in rio documents a real deadlock class. |
| PERFORMANCE-03 | Frame skipping under flood, coalesced scroll | When output outpaces refresh, parse as many lines as arrive, then render the latest state once per callback. Intermediate states are dropped and frames are never queued. Scroll and damage accumulate between frames (the GPU analogue of xterm jumpScroll). | `performance { frame-pacing }` | must | foot, xterm (jumpScroll/fastScroll), wgpu Mailbox semantics | Prevents lag after `cat` of a large file. Never render per escape sequence. |
| PERFORMANCE-04 | Delayed-render lower/upper timers (anti-flicker) | Each PTY read re-arms a short lower timer. The first read of a burst arms a hard upper timer. Render when the lower timer fires with no further data, or when the upper timer fires. Defaults follow foot: 0.5 ms lower, 8.33 ms upper. Also honour the kitty-style `repaint_delay` and `input_delay` semantics: the delay is ignored when input is pending or the backlog is large. | `performance { render-delay-lower, render-delay-upper }` (ns, 0 disables), `input-delay`, `repaint-delay`; a `low-latency` profile sets them to 0 | must | foot, kitty, topic-gpu-latency | foot users rely on no flicker from programs that lack mode 2026. We choose foot's two-timer form over kitty's single fixed delay because the upper cap bounds latency while the lower timer still ends the wait early. |
| PERFORMANCE-05 | Keystroke-echo fast path | Output arriving within a short window after a local key event renders immediately and skips the coalescing timers. | `performance { echo-fast-path-ms }` | must | proposal (derived from kitty `input_delay` tradeoff) | Typing latency is the key budget. Coalescing is for bulk output. Not shipped as such by any surveyed terminal, so the window length needs measurement (see Open questions). |
| PERFORMANCE-06 | Synchronized output (DECSET 2026) with safety timeout | Hold rendering from BSU to ESU. Reset by force after 1000 ms (ghostty's constant) so a crashed program cannot freeze the display. | `performance { sync-timeout-ms }` | must | kitty, ghostty | Protocol facts only. Interacts with PERFORMANCE-04: while sync is active the lower/upper timers are suspended. |
| PERFORMANCE-07 | Parse off the render path, with snapshot handoff | VT parsing runs on a worker. The renderer takes only the dirty rows it needs, either as a short-lived snapshot or via channel handoff. A wakeup tells the renderer to draw. | internal | must | kitty, ghostty, alacritty, rio, topic-gpu-latency | Smoothness under floods. Terminals split on the mechanism: alacritty and rio use a shared lock with try-lock and fair hand-off, ghostty uses a short-lock row snapshot. We prefer the snapshot or channel form because the EclipseOS rule is no locks on the hot path. See Open questions on who owns the grid. |
| PERFORMANCE-08 | Bounded, fair PTY drain | Cap bytes per parse slice and per wake. The seen values are: foot 24 KiB per read and 10 reads per wake; alacritty 1 MiB buffer in about 64 KiB slices; rio 64 KiB reads, 4 chunks (256 KiB) per lease; vte about 8 KiB chunks with a 1-byte overlap for split UTF-8 and a 100 ms processing cap per tick. Use 64 KiB reads, about 256 KiB per slice, and a time cap in ms. Unbounded only after hangup. A short read is trusted as drained except after child exit. | `performance { max-read-bytes, max-process-ms }` | must | foot, alacritty, rio, vte-konsole | Four terminals bound the drain, so this is required. Throughput comes from large reads, fairness from the per-wake cap. A time cap is added to the byte cap, taken from vte, because bytes alone do not bound slow sequences. A single noisy pane must not starve input or other panes. |
| PERFORMANCE-09 | Coalesced damage wakeup flag | The parser posts one lightweight "damaged" event and sets an in-flight flag. No more events are sent until the renderer consumes it. The damage itself stays in the terminal state. | internal | must | rio | Prevents event-queue floods under heavy output and keeps the renderer the single consumer. |
| PERFORMANCE-10 | Bulk ground-state text decode with ASCII bypass | In ground state, scan for the next ESC or control byte with a vector scan, bulk-decode UTF-8 up to it into a codepoint buffer (4096-entry chunks). If every byte was ASCII, skip decoding and use the input bytes directly. A partial trailing sequence goes to a scalar decoder. | internal | must | kitty, ghostty | Text is the dominant stream. The SIMD scan is credited for kitty's throughput lead. Avoids a per-byte state machine. |
| PERFORMANCE-11 | Printable-run splitting and width-class batch fill | Split decoded text into printable runs (single mask test for C0/C1) and pass slices to the handler. Fill cells in batches specialised by width class (narrow/wide), grapheme mode and styled state. Codepoints up to 0xFF skip the width lookup. | internal | must | ghostty | Amortises per-codepoint cost on the hot path. Only ghostty is documented here, but it is the same hot path every terminal needs. |
| PERFORMANCE-12 | Bulk OSC/APC/DCS consumption and streaming payload decode | Vector-scan for terminator or abort bytes, then give the whole slice to the string parser. Base64 graphics/media payloads are stream-decoded into a preallocated buffer with no allocation per chunk. | internal | must | ghostty, topic-media | A 1080p direct kitty frame is about 2,025 chunks of 4096 base64 bytes (8.3 MB), about 249 MB/s at 30 fps (arithmetic from the kitty protocol chunk limit). Without a fast path the parser is the bottleneck. |
| PERFORMANCE-13 | Rust vector techniques, no C++ | Use `memchr`-style and `simdutf8`-style crates or stable `std::arch` intrinsics for the scans. Benchmark every hot loop (PERFORMANCE-29) and never assume auto-vectorization. | internal | should | ghostty, kitty | Ghostty measured a 2.8x ASCII slowdown when a replaced memset lost LLVM auto-vectorization. Licences of candidate crates must be checked against the allowed list (unverified). |
| PERFORMANCE-14 | Line-range damage from core to compositor | The terminal emits Full or Partial line-range damage. The renderer keeps damage for two frames to handle buffer age, merges rects with some overdamage, and reports them via `wl_surface.damage_buffer`. A debug mode paints damage. | `debug { paint-damage }` | must | alacritty, windows-terminal | Cuts GPU and compositor work. Same structure serves the instance-buffer rebuild. |
| PERFORMANCE-15 | GPU scroll copy and dirty-region present | Copy the scrolled region on the GPU and redraw only invalidated rows. | `rendering { partial-invalidation }` (default on) | should | windows-terminal | Lower power. Whether wgpu on Wayland can use it is open (see Open questions). |
| PERFORMANCE-16 | Opaque-region hint | When the background is opaque, set an opaque region on the surface so the compositor can skip blending. | follows `opacity` | could | windows-terminal (analogue) | Apotheosis glass surfaces are mostly translucent, so the benefit is small. Applies in fullscreen or opaque-background profiles. |
| PERFORMANCE-17 | Compact instanced quad buffer | One instance per cell or quad, with i16 positions, u16 size and texcoords and a u32 colour, in a CPU-written instance buffer. Instance-buffer size was the biggest performance and power lever in the source terminal. | internal | must | windows-terminal | Direct guidance for the wgpu vertex layout. |
| PERFORMANCE-18 | Sprite atlas keyed by cell size | Render box-drawing, block and powerline glyphs once per (cell size, codepoint) into the R8 atlas, so all glyph kinds use the same instanced draw path. | internal | must | rio, ghostty | Zero steady-state cost, simple draw path. |
| PERFORMANCE-19 | Atlas dirty and resize counters | Rectangle-bin atlas with separate modification and resize counters, so the renderer uploads only on change. R8 for masks, RGBA8 for colour glyphs. | internal | should | ghostty, rio | Cheap upload tracking under wgpu. |
| PERFORMANCE-20 | Generation counters for invalidation | Separate settings, font and misc generations decide which GPU resources to rebuild. | internal | should | windows-terminal | Cheap config hot-reload without a full rebuild. Also drives shape-cache invalidation (PERFORMANCE-21). |
| PERFORMANCE-21 | Row-bounded, position-independent shaping runs and shape cache | Runs never cross rows and split on style or font. The run hash uses relative cluster positions, so identical text at different columns hits the same cache entry. Clear the shape cache when fallback fonts change (wezterm's ClearShapeCache signal; here the font generation counter). | `font { ligatures }` | must | ghostty, wezterm | Main CPU saver for ligature fonts. Unchanged rows are not reshaped each frame. |
| PERFORMANCE-22 | Shared font grid across surfaces | Font set and atlases are shared between windows and panes, keyed on the font config. | internal | should | ghostty | Memory and startup savings with many panes. |
| PERFORMANCE-23 | Delayed reflow during interactive resize | While the window is dragged, truncate the grid cheaply, withhold the new size from the child and hold the pty. After an idle delay reflow the original grid to the final size and resume. Resize notifications to the pty are coalesced (about 25 ms in ghostty). | `performance { resize-delay-ms }`, `resize-by-cells`, `resize-keep-grid` | must | foot, ghostty | Avoids reflow storms and a flood of SIGWINCH. Users rely on it. |
| PERFORMANCE-24 | Dedicated PTY write path and timing constants | Writes, resize coalescing, sync-output safety reset and selection auto-scroll tick are kept off the read hot path. Starting constants: 25 ms resize coalesce, 1000 ms sync reset, 15 ms auto-scroll tick. | internal | should | ghostty | Concrete constants. We use a single-threaded core plus a pool, so this becomes timers in the loop, not a thread. |
| PERFORMANCE-25 | Parallel row rendering workers | Not adopted. | n/a | no | foot | CPU-renderer specific. On the GPU, row work is filling the instance buffer, which is cheap on one thread. |
| PERFORMANCE-26 | `wp_presentation` telemetry and built-in latency probe | Attach feedback to each commit. Use the presented timestamp, refresh prediction and flags (vsync, hw_clock, zero_copy) to compute commit-to-photon time and count missed refreshes. Discarded events count as drops. A control-socket method injects a synthetic key into a PTY loopback and records the time to presentation, reporting p50, p99 and p99.9 under idle and under background load. | control socket `perf.latency-probe`, CLI, settings GUI page | must | foot, topic-gpu-latency, Dan Luu methodology | It is the only way to measure real latency in the app, and it makes budgets enforceable in CI without hardware. Tail percentiles matter more than the mean. |
| PERFORMANCE-27 | Frame stats overlay and log | Overlay with frame time split into wait, render and present, queue depth, missed-refresh buckets and damage area. Optionally log to the journal. | `debug { render-timer = off\|osd\|log\|both }` | should | foot, alacritty | Foot and alacritty both ship a render timer. |
| PERFORMANCE-28 | External latency measurement | Typometer-style software measurement and a high-speed camera or photodiode rig, used once to validate the in-app probe and for cross-terminal comparison. | documentation only | could | topic-gpu-latency | Typometer is X11-centric, so its Wayland adaptation is unverified. |
| PERFORMANCE-29 | Benchmark harness with pre-generated corpora | Deterministic synthetic corpora, files fed to the parser and stream benches, serial runs compared by median. Add the vtebench workloads (scrolling, regions, dense/medium/light cells, cursor motion, unicode, sync_medium_cells) as the CI throughput baseline. Add the frame-time and input-latency tests that vtebench disclaims, plus resize, width and grapheme benches. | `apotheosis bench` CLI | must | ghostty, alacritty, kitty | Reproducible regression gate. Throughput and latency are tracked separately. |
| PERFORMANCE-30 | Randomized damage-pipeline mirror test | Replicate the renderer's frame-consumption and row-rebuild decisions against a painted mirror. Run randomized editor-shaped traffic over many seeds and assert that every change has a wakeup and that the painted mirror equals the grid. Add property tests for zero-width attach damage. | test suite | must | rio | Found a whole class of stale-glyph and scroll-offset bugs automatically. Cheapest insurance for a damage-driven renderer. |
| PERFORMANCE-31 | Parser fuzzing and conformance replay | Fuzz or property tests on the parser (panics, unbounded growth) and replay of a conformance corpus (vttest, esctest). | test suite | should | topic-escape-registry | Catches panics. Throughput numbers come from PERFORMANCE-29. |
| PERFORMANCE-32 | Golden-table key encoder tests and fuzzing | Pure-function encoder writing into a fixed stack buffer. Table tests against the kitty keyboard spec and fuzzing of modifiers and flags. | test suite | should | topic-keyboard | Zero-allocation hot path with conformance. |
| PERFORMANCE-33 | Input-rate sustained presentation for VRR | Rolling 100 ms window. Only when input reaches about 60 events/s does the loop keep presenting after input. | `performance { vrr-sustain }` | should | rio | Single-key presses do not force a redraw burst, while fast drags keep VRR displays from downclocking. Single source only, kept at should for the VRR benefit. |
| PERFORMANCE-34 | Occlusion and hidden-surface throttle | Stop rendering when frame callbacks stop or the surface is occluded. Unfocused or hidden panes render at a reduced rate or not at all. | `performance { render-hidden = off\|throttle }` | should | rio, topic-gpu-latency | Saves power and avoids a wedge when a callback never fires (links to PERFORMANCE-02). |
| PERFORMANCE-35 | Startup cost budget and lazy init | Create the wgpu instance, adapter and device asynchronously while the Wayland window shows a solid background first frame. Defer atlas warm-up and pipeline compilation, and cache pipelines. | `performance { pipeline-cache }` | must | proposal | wgpu adapter init and shader compile dominate cold start. No verified published numbers were found, so budgets must be measured by us. |
| PERFORMANCE-36 | Page pool with demand-paged memory | Standard-size pages come from a pool of zeroed, demand-paged buffers. Idle preheated pages cost address space only. Pruned pages are reused for new pages. | `scrollback { lines }` | should | ghostty | Steady-state output at the scrollback limit allocates nothing. We choose page-granular incremental eviction over tmux's batch scheme (PERFORMANCE-41). |
| PERFORMANCE-37 | Page capacity growth hints | A ring of capacities that recent full pages needed (styles, graphemes, strings, hyperlinks) sizes the next page. Row trimming is bounded to keep at least 90 percent rows-per-byte. | internal | could | ghostty | Avoids regrowth on styled output at the cost of complexity. Revisit after benchmarks. |
| PERFORMANCE-38 | Reflow node recycling | During column-resize reflow, reuse one destroyed source page for the next destination page. | internal | could | ghostty | Avoids a decommit/recommit pair per page. Mainly benefits large scrollback. |
| PERFORMANCE-39 | Scrollback compression with an in-tree LZ4 block codec | Fast-strategy LZ4 block coding with caller-supplied buffers and a fixed 16 KiB hash table. Decoded size is stored separately. A pure-Rust crate (`lz4_flex`, licence to be checked) or an in-tree codec both fit the no-C rule. | `scrollback { compress }` | should | ghostty | Memory saving for deep scrollback. | PERFORMANCE-40 | Modular-offset ring storage | A flat Vec of rows with a rotating offset and truncation only when it exceeds live rows by 1000. | internal | could | alacritty | Cheap scroll, but no interning or compression, so it loses to pages (PERFORMANCE-36) unless we choose a simpler store. |
| PERFORMANCE-41 | Batch history eviction (10 percent of limit) | Not adopted. | n/a | no | tmux | Causes stalls with pins and compression. Use page-granular eviction. |
| PERFORMANCE-42 | Struct-of-arrays line storage | Lines as SoA with aligned vectors, O(1) blank lines and mixed-flag scans suited to SIMD. | internal | could | contour | Possible upload and scan speedup. Evaluate against page cells. |

| PERFORMANCE-44 | Type-ahead search line cap | While typing, regex search is limited to a bounded number of lines (alacritty: 1000) from the origin. ## Open questions

- **Grid ownership (PERFORMANCE-07).** Does the parser worker own the grid and publish snapshots, or does the core own it and the worker only emits parsed ops? Needs a spike measuring snapshot cost on a full-screen redraw.
- **Echo fast path window (PERFORMANCE-05).** No surveyed terminal ships this. The window length and its interaction with PERFORMANCE-04 must come from measurement with the latency probe.
- **wgpu damage on Wayland (PERFORMANCE-14, 15).** Whether wgpu's Vulkan present on Wayland honours damage rects or buffer age is not settled by the rows. If it does not, damage only saves instance-buffer work, not compositor work. Unverified.
- **Startup numbers (PERFORMANCE-35).** No published cold-start numbers for wgpu terminals were found. Budgets must be measured.
- **Default values.** Delay, cap and time-budget defaults are copied from other terminals. Re-derive them on the latency and throughput benches before fixing them.
- **Crate licences.** Candidates (`memchr`, `simdutf8`, `lz4_flex`) are assumed acceptable but were not checked against the allowed licence list.
- **Scrollback store (PERFORMANCE-36 to 42).** Pages with compression, or a simpler ring, is a design decision for the scrollback/search category, not settled here.
- **VRR sustain (PERFORMANCE-33).** Single source (rio). Needs a check that Wayland input timestamps give the same signal.
