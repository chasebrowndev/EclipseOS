## mux

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| MUX-01 | Session model separable from windows | Panes, tabs, splits and floats are plain data owned by a session object; a window is only a view. The server owns ptys and terminal state; detach leaves everything running. | attach, detach, new-session, kill-session Actions; CLI and socket verbs | must | wezterm, zellij, tmux, topic-mux-remote | Prerequisite for layouts, rules, profiles, control socket, detach and restore. Benchmarks (kitty docs, alacritty+tmux about 24.7 vs 54.1 MB/s) show an external multiplexer roughly halves throughput, so ours renders cells directly with no re-encode. |
| MUX-02 | Domain abstraction (local, unix, ssh, exec, tmux-cc, serial) | A domain owns spawn/split/attach/detach/state; panes from any domain implement one Pane trait; the GUI is a client of domains. | KDL `domain` blocks; `domain` field on spawn Actions; `connect <domain>` | must | wezterm, topic-mux-remote | One concept covers local, remote, container and tmux panes; maps to KDL profiles and settings GUI rows. Avoids a bolt-on mux. |
| MUX-03 | Headless mux server over Unix socket with auto-start | Server process owns ptys; GUI clients attach. Client spawns the server if the socket connect fails (opt-out). Socket ownership and permission check on connect. Default single-process mode stays; persistence is a per-domain switch. | `serve_automatically`, `socket_path`, `skip_permissions_check` KDL keys | must | wezterm, tmux, zellij | Detach/attach is the core reason people run tmux. Sources disagree on default (wezterm auto-starts, topic row says opt-in); we take auto-start on demand for domains that ask for persistence, off for the default local domain. Ownership check is a cheap security win. |
| MUX-04 | Resident process with shared fonts, glyph cache, multi-window and single-instance targeting | One process hosts all windows sharing config, fonts and glyph atlas; I/O on one calloop-style loop; per-window render. Daemon mode with no window; CLI picks new vs existing window and named windows. | `--daemon`, `new-window`, `--window <name>`, windowing_behavior KDL key | must | foot, alacritty, windows-terminal | Fast spawn and low per-window memory. Isolate panes better than foot (pane crash must not take the process down). |
| MUX-05 | Single-owner state with message-passing threads | One thread owns layout and pane state; pty, writer, decoder and background jobs are threads that send typed instruction enums over channels. | internal | should | zellij, tmux | Matches EclipseOS handle-based single-owner discipline; no locks on the pane tree. |
| MUX-06 | Mux wire framing | Frame = length (top bit marks compression), request serial, stable numeric message id, then compact binary body; server push messages for pane, tab, title, workspace changes. Obsolete ids retired, never reused. Compression only above a small threshold and only if smaller; off on local sockets; use pure-Rust ruzstd, not the C zstd crate. | internal; `apotheosis ctl` uses it | should | wezterm | Good skeleton; C dependency rules out wezterm's zstd. |
| MUX-07 | Protocol handshake with capability negotiation and N-1 grace | Hello exchange of version plus capability set; accept the previous version, refuse older with a clear UI message. | internal | must | wezterm | wezterm requires exact version equality, which strands long-lived sessions on update. Capabilities beat version numbers for incremental features. |
| MUX-08 | Dirty-line render sync with stable row indices | Clients cache lines by stable row index; server pushes changed line ranges (deltas, not polling); missing scrollback and image cells fetched lazily. | internal | should | wezterm | Robust to reconnect and differing client sizes. Push instead of wezterm's poll. |
| MUX-09 | Multi-client attach with window-size policy | Several clients per session; size policy smallest/largest/latest/manual, plus per-client tab sizes so a small client does not shrink everyone. | `window_size` KDL key, `aggressive_resize` | should | tmux, zellij | Per-client sizing (zellij 0.45) avoids tmux's smallest-client problem. |
| MUX-10 | Read-only watcher client | Attach role that follows a session with no input. | socket stream role; `attach --watch` | could | zellij | Pair viewing and demos; falls out of the client role model. |
| MUX-11 | Session list, names, previews, kill/delete | List live and resurrectable sessions; picker in palette shows live previews; aliases and names. | list-sessions, attach, kill-session, delete-session Actions; palette picker | must | zellij, tmux | Needed for any multi-session workflow; previews make switching fast. |
| MUX-12 | Workspaces | Per-window string tag persisted by the server; GUI shows one workspace; built-in save/restore of layouts per workspace. | switch-workspace, workspace-next/prev, rename-workspace, `default_workspace` | must | wezterm, windows-terminal | Simple model; add built-in save/restore that wezterm leaves to plugins. |
| MUX-13 | Built-in layout presets and free split tree | Per-tab layout algorithm over the pane list: even-h, even-v, main-h/v (mirrored), tall, fat (bias and full_size params), grid, stack, plus free splits. Names accept unambiguous prefixes. | `layout` Actions: select-layout, next-layout, prev-layout; layout params in KDL | must | kitty, tmux, zellij | Covers tiling presets and freeform splits under one vocabulary. Kitty's parameterised form is the model; tmux preset names and prefix matching are the muscle memory. |
| MUX-14 | Binary split tree with full pane operations | Own tree: nodes hold split orientation and fraction; operations walk to the neighbour. Actions: split, close, focus-dir, swap, move, rotate, break to tab, join, attach/detach across tabs and windows, resize, equalize, draggable dividers. | split-h/v, move-pane, swap-pane, resize-pane, break-pane, join-pane, rotate Actions | must | windows-terminal, vte-konsole, tmux, zellij, kitty, ghostty, rio | Union of tmux vocabulary and Windows Terminal tree ops. Rio's taffy proves viable but a purpose-built tree plus MUX-15 gives needed control. |
| MUX-15 | Percent-or-fixed dimensions with constraint resize | Geometry is percent or fixed cells; a resizer solves with minimum sizes and fixed bars. | `size=` in layouts; resize Actions with direction and amount | must | zellij | Layouts reserving fixed chrome while others flex; stable resize. |
| MUX-16 | Zoom focused pane | Temporarily expand a pane over the tab; restore on toggle; modal floats may sit above. | pane.zoom-toggle | must | tmux, zellij, ghostty, windows-terminal, warp-wave | Shipped everywhere; used constantly. |
| MUX-17 | Stacked panes | A cell holds N panes; one expanded, others as one-line titles; combine, break out, resize, make room for new pane; horizontal or vertical title list. | `stacked=true` in layouts, toggle-stack-orientation | must | zellij | Named requirement and zellij's most distinctive feature. |
| MUX-18 | Floating pane layer | Tiled and floating panes kept as separate collections per tab; layer show/hide, per-pane pin, z-order, raise on focus, embed/float toggle. | toggle-floating, toggle-embed-float, `pinned`, floating nodes with x/y/width/height | must | zellij, tmux | Named requirement; scratch terminals and popups. |
| MUX-19 | Floating placement search | Try centred half-size, then top-left, then top-right, stepping an offset until the rect fits inside the viewport and avoids existing floats. | internal; coordinates overridable | should | zellij, tmux | Deterministic staggering; simple algorithm. |
| MUX-20 | Modal floating pane | One per window; blocks other panes; options: close on outside click, forward all keys, close on Esc, stay above zoom. | Action parameters | should | tmux | Model for approval dialogs and pickers; maps to glass dialogs. |
| MUX-21 | Swap layouts guarded by pane-count | Ordered list of layouts each with min/max/exact pane count; first fit wins; cycle or pick by name. | `auto_layout`, next/prev-swap-layout, named selection | should | zellij | Automatic tiling policy without scripting. |
| MUX-22 | Named layouts and session files in KDL | KDL `layout` tree: windows, tabs, splits, cwd, command, profile, focus. Applied by apply-layout, saved by save-layout (snapshot of live state, optionally relocatable, using foreground process). | apply-layout, save-layout, load-layout Actions; `--layout`, `startup_layout`; CLI | must | kitty, zellij, vte-konsole, windows-terminal, wezterm | Project workspaces are a core use case; kitty's snapshot plus konsole per-leaf profile/cwd/command; same vocabulary as live Actions. |
| MUX-23 | Periodic session serialization to KDL | Background job writes the live session every interval (default 60 s) when dirty and non-default: geometry, command, args, cwd, title, focus, floats. Offered for resurrection on next attach or start. File doubles as a hand-editable layout. | `session_serialization`, `serialization_interval` KDL keys; dump-layout, save-session | must | zellij | Crash and reboot recovery; closes tmux's persistence gap. |
| MUX-24 | Atomic session-file writes | Write temp, fsync, rename; keep last good copy; validate on load. | internal | must | zellij | Corrupt restore file defeats persistence (zellij fixed this in 0.46). |
| MUX-25 | Restore policy, undo close, buried sessions | Restore last layout on start (positions, tree, cwd, profile; not contents); time-limited undo-close; buried sessions keep running hidden. | `restore` KDL key, undo-close Action, bury/unbury | should | windows-terminal, iterm2, ghostty | Expected on a desktop. Scrollback restore is an open question. |
| MUX-26 | Running-command discovery and rewrite rule | On serialize, walk the pane's process tree for the foreground command; a KDL rule strips wrappers (prefer declarative match/replace over a shell string). | `command_discovery` rule block | should | zellij | Needed to relaunch what the user was running. |
| MUX-27 | Versioned layout serialization | Layout and floats serialized with a schema version and validation; optional checksum is not needed since KDL gives structure. | schema version in KDL and JSON socket forms | could | tmux | Control socket needs a versioned geometry format; checksum is low value. |
| MUX-28 | Broadcast input | Modes: current, all in tab, all in window, selected panes or match expression; persistent visible indicator; per-pane opt-out. | broadcast-input mode=... Action; `--match` | must | iterm2, kitty, tmux, windows-terminal, vte-konsole, warp-wave | Core multi-host admin feature shipped by six; indicator for safety. |
| MUX-29 | Read-only pane | Pane ignores input when set. | toggle-pane-readonly | should | windows-terminal | Protects long-running output panes; cheap. |
| MUX-30 | Remain on exit / hold on close | Dead pane stays with exit status; rerun on Enter; modes on, failed. | `remain_on_exit` KDL key; `hold_on_close` in layouts | must | tmux, zellij | Prevents losing output of failed commands; rerun is a good default for layout command panes. |
| MUX-31 | Run command in new pane | Spawn Action with close-on-exit and zoom flags. | pane.run close=on-exit zoom=true | should | warp-wave | Falls out of the Action vocabulary. |
| MUX-32 | Exec domain command wrapper | Declarative template wraps argv/env of every spawn in the domain (docker exec, distrobox, kubectl); no scripting callback. | KDL `domain` with `wrap { argv "docker" "exec" "{cmd}" }` | should | wezterm | Containers as first-class domains. Wezterm rows disagree should vs could; one ship, high user value, so should. |
| MUX-33 | tmux control mode client domain | Parse `tmux -CC` guarded replies and notifications, decode octal-escaped output, map tmux windows and panes to native panes. GUI owns size via refresh-client -C. Mark experimental. | `connect tmux-cc`; tmux-dashboard | should | iterm2, ghostty, wezterm, topic-config-automation | Three terminals ship it and demand is high (ghostty #1935, WT #3656, wezterm #336). Fragile to tmux internals so lands after native mux. |
| MUX-34 | tmux dashboard and recovery | Window list, detach, force exit, protocol log. | palette entries | could | iterm2 | Operational escape hatches for MUX-33. |
| MUX-35 | Multiplexer passthrough tolerance | Accept tmux/screen DCS envelopes (doubled ESC) and treat unwrapped bytes as untrusted; native mux passes graphics directly. | MUX-36 | Parse-until-boundary API | Parser consumes input up to a requested boundary (ground, string start/end) and reports consumed bytes with state identical to a normal feed. | internal | should | ghostty | Needed for mux proxying and the sandboxed decoder hand-off. |
| MUX-37 | Activity, silence and prompt monitors | Per-pane monitors with silence timeout emit events; tab badge and notification. | events activity, silence, prompt for rules; `monitor` pane setting | should | vte-konsole | Event sources for rules. |
| MUX-38 | Quake drop-down | Toggle Action; on Wayland positioned via Abyss integration, skipped elsewhere. | toggle-quake Action | could | rio | Wayland lacks global hotkeys and placement. |

### Open questions

- Is the mux server the same binary and process as the GUI (opt-in headless mode) or a separate daemon that always runs? Rows lean toward same binary, opt-in per domain.
- Should session restore include scrollback contents (ghostty #1847 asks)? Rows only cover structure, cwd and command.
- Wire body encoding is unspecified (varint-serialized binary vs another serde format); needs a crate licence and size check.
- Does ruzstd performance suffice for remote domains, or is no compression acceptable?
- Which tmux-cc features to support in the first release (layout, scrollback capture, key modes)?
- Quake and tab tear-off need Abyss protocol support; spec unwritten.
- Kitty broadcast row source is a directory path, not verified.
- The Windows Terminal workspaces row cites an action name (OpenWorkspace) that is unverified.
