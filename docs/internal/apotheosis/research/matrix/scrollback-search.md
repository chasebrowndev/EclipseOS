## scrollback-search

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| SCROLLBACKSEARCH-01 | Offset-addressed slab pages with interned styles | Screen and history are a list of fixed-layout pages drawn from a pool. Each page holds rows, 64-bit cells, a ref-counted style table (id 0 = default), a grapheme map and a hyperlink table. All internal references are offsets, so a page can be copied bytewise, compressed, serialized or handed to a search thread. Rows are lazily filled, so memory is proportional to content. Oversized pages go to the heap when styles or graphemes overflow. | KDL `scrollback { lines; limit-bytes }` (see -03) | must | ghostty, foot, xterm, kitty | Memory per history line decides how much history fits. Pages give cheap snapshots, allocation-free steady state and fit handle-based state with no allocation on the hot path. Chosen over foot's power-of-two row-pointer ring (simple, wastes memory) and xterm's row FIFO (no style interning). |
| SCROLLBACKSEARCH-02 | Tracked pins with serials and garbage state | A pin is (page serial, row, col). Viewport, cursor, selection ends, search hits, prompt marks and annotations register as tracked pins. Prune, reflow and erase fix them up. Pins on pruned pages are flagged garbage. Serial ids, not pointers, allow O(1) validation even when memory is reused. | none (internal) | must | ghostty, wezterm, foot | Stable positions across reflow and eviction underpin selection, search and blocks. Serials are preferred to pointers because they survive allocator reuse. |
| SCROLLBACKSEARCH-03 | Dual logical scrollback limits | Limits in uncompressed logical bytes (includes the active area) and in lines. Whichever hits first prunes whole historical pages. Pages overlapping the active area are never split. Both are changeable at runtime. Compression and disk tiers change physical memory only, not the limit. Defaults are far above xterm's 1024 lines. | `scrollback { lines; limit-bytes }`, Action `scrollback.set-limit`, GUI field | must | ghostty, alacritty, xterm, kitty, foot | Users reason about history length, not RSS. Alacritty's hard 100000-line cap is dropped because cold pages are cheap. |
| SCROLLBACKSEARCH-04 | Idle LZ4 compression of cold pages | Complete pages outside the viewport and before the active boundary are LZ4-block compressed in bounded steps on idle ticks, tracked by an activity serial with a verification pass. Physical memory is released (MADV_DONTNEED) while the virtual range is kept, so restore is infallible. Needs a pure-Rust LZ4 crate (lz4_flex, MIT, unverified licence check needed). | `scrollback { compression=#true }` | should | ghostty | Only ghostty ships it, so "should" rather than "must", though one topic row asked for "must". It claims a 70-90% RAM cut on text history with no throughput cost. It is the enabler for large defaults. |
| SCROLLBACKSEARCH-05 | Opt-in encrypted disk-spill tier | Rows beyond the memory budget go to row, text and attr streams in an unlinked 0600 temp file. Fixed 64 kB blocks are LZ4-compressed, then AES-256-GCM encrypted with an overwrite counter in the IV. Writes are batched and reads cached. Password-role content never enters it. Off by default. Uses a RustCrypto AEAD crate (MIT/Apache). | `scrollback { storage memory\|disk; encrypt }` | should | vte, konsole | Effectively unlimited history with low RSS. Konsole's unencrypted file history is rejected, and encryption keeps secrets at rest protected. |
| SCROLLBACKSEARCH-06 | History modes and save/auto-save | Per-profile modes none, bounded in-memory, disk-backed, with a size control, a save-history action and an auto-save interval. Saved files are 0600. | profile `history-mode`, `auto-save-interval`, Action `scrollback.save` | could | konsole | The user model is useful, but most of it is covered by -03, -05 and -31. |
| SCROLLBACKSEARCH-07 | Text-only pager history tier | A separate UTF-8+SGR ring (size in MB), not interactively scrollable, used for pager/export/old-output search and lazily rewrapped by re-flowing the text stream. | `scrollback { text-tier-mb }` | could | kitty | A cheap very-deep tier, but superseded by -04 and -05 if those ship. Revisit only if they slip. |
| SCROLLBACKSEARCH-08 | Renderer-ready split cell layout | Keep a separate GPU-uploadable cell array beside a CPU-only text and attr array, with on-demand segment growth. | none (internal) | could | kitty | A hint for the wgpu renderer design. It conflicts with -01's single page layout, so decide in the renderer spec. |
| SCROLLBACKSEARCH-09 | Logical-line search with offset map | Wrapped physical rows are joined into one logical line per haystack. Matches map text offsets back to (row, col) pins, so matches span wraps. Wide-cell spacers are skipped. | Action `search.*` | must | wezterm, alacritty, ghostty | Correct search over wrapped lines is the core requirement. |
| SCROLLBACKSEARCH-10 | Lazy-DFA regex engine | Regex via regex-automata hybrid DFAs, four per pattern (forward and reverse for each direction). The forward pass finds the match end and the reverse pass finds the start, with no backtracking. Bytes are stepped from cells with the -09 mapping. Cache and NFA size limits apply, with wrap-around across the buffer. Pure Rust, MIT/Apache. | Action `search` arg `mode=regex`, GUI toggle | must | alacritty, rio, wezterm, vte | Linear time with bounded memory. PCRE2 (vte) is rejected as C. |
| SCROLLBACKSEARCH-11 | Match modes | Five modes: literal, smart case (default), case-sensitive, case-insensitive, regex, plus whole-word and wrap toggles. A cycle-mode Action exists. | Action `search` args `mode`, `whole-word`, `wrap`; Action `search.cycle-mode`; KDL `search { mode; wrap }` | must | wezterm, windows-terminal, foot, alacritty, vte, konsole | Expected feature set. It maps one-to-one to Action arguments and GUI toggles. |
| SCROLLBACKSEARCH-12 | Background sliding-window search | A dedicated worker pages through history newest-first. Page text goes through a circular window that keeps only needle-length overlap, so cross-page matches are correct. It works on copied page data to keep lock hold short, reports results as pin pairs, and refreshes the UI on a short timer. Adds progress count and pause-when-hidden, which ghostty lists as TODO. | Actions `search.start`, `search.next`, `search.prev`, `search.end` | must | ghostty, konsole, wezterm | Searches huge history without blocking IO or the render loop. The worker is a pool task returning via channel, consistent with the single-thread core rule. |
| SCROLLBACKSEARCH-13 | Split immutable-history and active-area results | History results are cached as immutable. The active area is re-searched only when dirty. Viewport highlights re-run only for visible pages. An inactive screen keeps its results, so an alt-screen round trip does not restart. | none (internal) | must | ghostty | Live output must not invalidate the whole search. |
| SCROLLBACKSEARCH-14 | Debounced chunked incremental search | Typing bumps a cookie, and stale cookies are dropped. After a short debounce (default 150 ms, shorter than wezterm's 350 ms) the search runs backward in row chunks so first hits appear fast. | `search { debounce-ms }` | should | wezterm, konsole | Responsive and cancellable. Tuned for latency. |
| SCROLLBACKSEARCH-15 | Selected match as tracked highlight | The current match is stored as an index from the end plus a tracked pin pair, so n/N stays stable during live output and pruning. | Actions `search.next`, `search.prev` | should | ghostty | Stable navigation during streaming. |
| SCROLLBACKSEARCH-16 | Bounded viewport highlight scan | Live highlights cover the viewport plus a capped margin of wrapped lines (alacritty uses 100). | `search { highlight-margin-lines }` | should | alacritty, ghostty | Bounds per-frame cost on huge history. Superseded for committed searches by -12. |
| SCROLLBACKSEARCH-17 | Glass search overlay with scrollbar match marks | Compositor-independent glass overlay drawn by our wgpu UI: query box, mode toggles, match count and progress, highlight-all, and match ticks on the scrollbar. | Action `search.toggle`; KDL `search { highlight-all; scrollbar-marks; opacity }` | must | windows-terminal, konsole, wezterm, foot | Required glass UI. Scrollbar marks show where matches lie in history at a glance. |
| SCROLLBACKSEARCH-18 | Match refinement and extend-selection | While searching, keys extend the match by char, word or line, paste into the box, and Return copies to PRIMARY. | search key table (KDL keybinds) | should | foot | A distinctive refinement workflow, layered on top of -10 and -11 (not replacing them). Foot is the only terminal shipping it, so "should". |
| SCROLLBACKSEARCH-19 | Copy mode with vi/emacs key tables | A modal overlay with its own key table. The full motion set is Actions: moves, word and zone motions, jump-to-char, line and rectangle selection, marks, search integration. Rebindable in KDL and drivable over the control socket. | Action `copy-mode.enter` and `copy-mode.*`; `mode-keys vi\|emacs`; KDL `keybinds copy-mode { }` | must | wezterm, tmux, zellij, kitty | Keyboard selection is a differentiator. One Action vocabulary makes it scriptable, with no embedded scripting. |
| SCROLLBACKSEARCH-20 | Copy-mode auto-refresh | Opt-in refresh of copy mode as the pane changes, so logs can be followed while selecting. | `copy-mode { auto-refresh }` | could | tmux | Only tmux 3.8 ships it. Needs -02 pins to avoid selection drift. |
| SCROLLBACKSEARCH-21 | Pin-based selection | Selections are pin pairs (line, rectangle) that survive scroll and reflow. Word boundaries come from a word-chars setting. Options for clear-on-typing, copy-on-select and trailing-space trimming. | `selection { word-chars; clear-on-typing; copy-on-select; trim-trailing }`, Action `selection.adjust` | must | ghostty, foot, wezterm | Correct selection semantics under reflow. |
| SCROLLBACKSEARCH-22 | Reflow with tracked selection and images | Logical lines are rewrapped on resize. Selection, cursor and viewport pins are carried across, and image placements are repositioned. | `reflow { enabled }` | must | foot, ghostty, wezterm | A core incumbent strength. |
| SCROLLBACKSEARCH-23 | Alt screen modes with scrollback policy | Support modes 47, 1047, 1048 and 1049 (1049 saves the cursor, switches to a fixed-size buffer without scrollback, clears it). A per-profile and per-app (rule) policy keeps alt-screen output in scrollback, equivalent to xterm titeInhibit. | `profile alt-screen-scrollback never\|always\|on-exit`, rules | must | xterm, ghostty, foot, kitty | Universal escape feature. The policy is the user control. |
| SCROLLBACKSEARCH-24 | Placements anchored to buffer lines | Image and media placements are stored in buffer coordinates, shift on scroll, and are freed when rows leave scrollback or the limit drops. Reflow policy is defined explicitly (anchor to top row of the placement). | none (internal) | must | ghostty, kitty, foot | Correct scroll behaviour and memory release. |
| SCROLLBACKSEARCH-25 | Block index over continuous scrollback | Store prompt, command and output row ranges and exit status per block as pin-based metadata over a single scrollback, with no grid splitting. Navigate by block. | Actions `block.select-prev`, `block.select-next`, `block.select-all-output` | must | warp, iterm2, wezterm, kitty | Block features without Warp's grid-split cost. Shell integration marks populate it (see the shell-integration matrix). |
| SCROLLBACKSEARCH-26 | Block-atomic eviction | Pruning keeps command blocks whole. Evicted blocks leave a record with a placeholder at the top. | `scrollback { evict-by block }` | should | contour | Avoids half-shown output. Interacts with -03, so page pruning must be block-aware (open question). |
| SCROLLBACKSEARCH-27 | Scoped search | A scope argument (all, screen, selection, block) limits search to a command's output range. | Action `search` arg `scope`; Find-in-block action | should | iterm2, warp | Reduces noise, and is trivial given block ranges. |
| SCROLLBACKSEARCH-28 | Block output filter | A view-layer row mask over the selected or latest block that hides non-matching lines (match, invert, regex). Source data is untouched. | Action `block.filter` args `pattern`, `invert`, `regex` | should | warp, iterm2 | Grep in place without rerunning. A view-layer mask keeps pins valid. |
| SCROLLBACKSEARCH-29 | Instant replay | Time-indexed screen history (default about 4 MB), scrubbed with keys, with timestamps. | Action `replay.toggle`; `replay { size-mb }` | could | iterm2 | Recovers cleared or overwritten TUI screens, but one terminal and a second history store. |
| SCROLLBACKSEARCH-30 | Annotations | Notes attached to pin ranges via UI, rule or OSC. Navigable and toggleable. Content is never logged. | Action `annotate`; OSC 1337 AddAnnotation | could | iterm2 | Cheap on top of -02. |
| SCROLLBACKSEARCH-31 | Export, capture and pipe scrollback | Actions that take an extent (screen, scrollback, selection, last-command output, block) and a destination (file, clipboard, pager, editor, command stdin, control-socket reply). Includes a pipe-to-command Action and a capture call on the socket. Plain text or text with SGR. | Actions `export`, `capture`, `pipe`, `edit-scrollback`; args `extent`, `to`; CLI `apo capture`; config `pager`, `editor` | must | tmux, zellij, kitty, ghostty, windows-terminal, alacritty | The standard escape hatch for reuse and automation, and one Action replaces many per-terminal commands. |
| SCROLLBACKSEARCH-32 | Clear scopes | Clear screen, scrollback or all, as one Action with a scope argument. | Action `clear` arg `scope` | should | windows-terminal, tmux, kitty | Cheap automation. |
| SCROLLBACKSEARCH-33 | Optional viewport and scrollback serialization | Saved layouts may store pane text up to a line cap, shown on resurrection. Default off. File is 0600 and compressed, and password-role and redaction rules apply. | `layout { serialize-viewport; serialize-lines }` | should | zellij | Continuity after restore, but it stores possibly sensitive text. |
| SCROLLBACKSEARCH-34 | Persistent markers and hover patterns | User-defined regex or text patterns highlighted in the grid (kitty create_marker) or matched on hover with a cursor name (VTE). Implemented on the -10 engine. | Action `marker.add`, `marker.clear`; rules `match { pattern } -> actions` | should | kitty, vte | Reuses the search engine. The rules vocabulary replaces a scripting hook. |

### Open questions

- Is block-aware eviction (-26) acceptable when one huge block exceeds the byte limit? Needs a rule for splitting.
- Does the logical limit (-03) include compressed or disk-tier pages, and what is the default? The rows only give ghostty's 50 MB, which is unverified for our target.
- Pure-Rust LZ4 and AEAD crate choice and licence check (-04, -05). Unverified.
- Reflow policy for image placements (-22, -24) is not settled by the rows.
- Whether search runs over the disk tier by default or only on request (-05, -12).
- Whether search-in-cells (-10) or a text haystack (-09) is the single engine for literal search. Rows disagree (alacritty cells, wezterm text). Leaning to cell-byte stepping with the offset map.
- Exact defaults for debounce (-14), highlight margin (-16) and replay size (-29) need benchmarking.
