## unicode

| UNICODE-01 | UTF-8 decoding with maximal-subpart U+FFFD replacement | One decoder semantics (W3C / Unicode Table 3-7 maximal subpart) shared by the scalar state machine and any SIMD/bulk fast path; fuzz the two for parity. | none (fixed behaviour) | must | ghostty | Deterministic invalid-input output, and fast and slow paths cannot drift. Source: ghostty src/terminal/UTF8Decoder.zig; src/simd/vt.cpp (MaximalSubpart). |
| UNICODE-02 | Unicode property lookup tables | Generate at build time, in pure Rust, a multi-stage table (256-codepoint pages, shared all-default page) yielding width 0/1/2, grapheme-break class and emoji flags in one lookup. Pair with a grapheme transition table (prev class, next class, state -> break, next state) generated by driving a conformance-tested reference segmenter, so rules never drift. Flat 128 KiB width table is an acceptable fast path for the BMP/SMP. | none (internal); unicode version fixed at build | must | ghostty, rio, kitty | Single index on the hot path. | UNICODE-06 | Emoji presentation selection (VS15/VS16, Emoji_Presentation) | VT core decides presentation and cell width (VS16 widens to 2, VS15 narrows); the font layer is told to request a colour face (COLR/CBDT/sbix/SVG as supported) or monochrome face; fallback cache key includes the emoji flag. | none (internal); KDL font `emoji-font` | must | kitty, wezterm, foot, ghostty | Correct emoji versus text rendering without guessing from font. | UNICODE-07 | Cluster cell storage | Cell holds a small tag; clusters (rare path) live out of line: either an offset-addressed chunk allocator inside the page/row (ghostty, 4-codepoint chunks, cap 64 codepoints per cluster) or an interned table keyed by sequence hash (foot, VTE vteunistr, konsole ExtendedCharTable). We adopt page-local chunk allocation: no per-cell heap allocation, copy of a page is a memcpy. Reuse the same allocator style for hyperlink id/uri strings (32-byte chunks). Any inter-process frame format (control socket snapshots) carries a cluster table with per-entry and per-record size caps (zellij). Wide tails use a spacer cell. | none (internal) | should | ghostty, foot, vte-konsole, tmux-zellij | Every mature grid solves this; choice matters for performance and snapshot safety. Page-local chosen over global interning because it needs no GC/refcount and bounds memory. Sources: ghostty page.zig, bitmap_allocator.zig; foot terminal.c; zellij structured_render.rs. |
| UNICODE-08 | OSC 66 text sizing protocol | Implement the full kitty protocol: metadata s,w,n,d,v,h; text occupies an s*w by s cell block; client states width so both sides agree; erase operations remove any intersecting multicell block; support detection by CPR probes; renderer draws glyphs at non-uniform scale and fractional placement. | ESC ] 66 ; metadata ; text ST; KDL `unicode { text-sizing }` toggle | must | kitty (spec); requested by topic-escape-registry, topic-fonts | Resolves width disagreement and gives headings and super/subscripts. ### Open questions

- Which unicode version to ship as "latest" and how to track new versions (build-time data generation pinned to a crate version vs vendored UCD).
- Whether UNICODE-05 version selector earns its table-overlay cost, or only the ambiguous-width switch ships.
- Final mode numbers for bidi (2500/2501) and OSC 66 detection behaviour are draft or unverified against current upstream.
- Whether non-kitty terminals' absence of OSC 66 means app adoption is too low to justify must; kept must for renderer-design reasons.
- Glyph-scale handling of OSC 66 blocks interacting with ligatures, selection and reflow is not covered by the rows.
- Not present in the rows: Hangul jamo composition, regional-indicator edge cases, normalization on paste, confusable/security display of wide characters.
