## rendering

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| RENDERING-01 | Instanced quad text pipeline | One instanced quad per glyph (triangle strip from vertex id); instance carries atlas rect, bearings, grid pos, colour, atlas selector (gray vs colour) and flags (no-min-contrast, cursor glyph). Flush on atlas change. Measure cell storage buffer plus instancing vs packed vertex instances. | internal | must | kitty, ghostty, alacritty, rio, zellij (kitty/shaders.c; ghostty cell_text.v.glsl; alacritty text/glsl3.rs InstanceData) | Baseline of every GPU terminal; low CPU per frame, shared across grid and glass UI text. |
| RENDERING-02 | Paged glyph atlas | Glyph sprites rasterised once, packed with skyline (preferred over shelf: tighter) into fixed-size atlas pages; new page appended when full; LRU page/sprite eviction; separate grayscale and colour atlases; cleared on font/size change. Never recreate the whole cache on overflow. | internal; `font { atlas-budget-mb }` | must | kitty, ghostty, alacritty, windows-terminal, zellij, wezterm (anti-pattern) | Grow-only atlases (ghostty, WT, alacritty) never evict; wezterm whole-cache recreation hitches. Paging plus eviction bounds memory and avoids stalls. |
| RENDERING-03 | Persistent GPU cell buffers | Flat bg array (4 bytes/cell, row*cols+col) as storage buffer, per-row foreground instance lists (glyph, underline, strike, overline), list 0 reserved for cursor so it draws first; rows rebuilt and uploaded individually; small uniform block (projection, cursor colours, cell size, min contrast, flags). Per-cell bg sampled in shader for correct blending. | internal | must | ghostty, rio, windows-terminal, kitty | Enables row-granular upload; compact and a direct fit for wgpu. |
| RENDERING-04 | Render-state snapshot per frame | Under a short lock (or via channel from the pool, given our single-threaded core) copy visible rows into reused allocations with fully resolved styles and a map of only referenced extras; build GPU data from the snapshot with no lock held. Plain-text fast path for raw cell copy. | internal | must | ghostty (render.zig RenderState), rio (renderable.rs) | Decouples parse from render, bounds hold time, removes stale-style bugs. |
| RENDERING-05 | Damage model | Four states (Noop, Full, Partial, CursorOnly) plus per-row dirty bits with column bounds from the VT core; cells carry a clean bit; consumed frames record cursor position so idle drains emit nothing; whole-window escape hatch. | `tweak { damage-whole-window }` | must | foot, alacritty, rio, zellij | Idle costs nothing, typing touches one row; cursor bookkeeping avoids rio's idle-wake bug. |
| RENDERING-06 | Frame-callback gated rendering | Record refresh requests; render once per loop iteration after all PTY reads are drained; request wl_surface.frame on each commit, keep one frame in flight, pending damage accumulates and replays from the callback. Pacing derives from the callback, not timers (zellij's refresh pacer is only a fallback if no callback). | internal | must | foot, topic-gpu-latency, zellij | Vsync pacing and batching; supported on every compositor. |
| RENDERING-07 | Present mode and latency policy | Query surface caps: Mailbox if offered, else Fifo; Mesa lists Mailbox and Fifo always and Immediate only when wp_tearing_control_manager_v1 is bound, so never rely on Immediate; do not hard-code (rio's Fifo-only is an X11 workaround); set desired_maximum_frame_latency = 1. | RENDERING-08 | Report damage to the compositor | Convert row damage to wl_surface.damage_buffer rectangles on each commit. | `tweak { damage-whole-window }` | should | foot, alacritty (rio does not; issue 1570) | Cheap on Wayland, less compositor work, especially on Abyss. | RENDERING-09 | Retained grid texture and damage history | wgpu exposes no buffer age: render grid to an offscreen texture updated only on damage, composite with glass UI each presented frame; where partial redraw of swapchain images is used, union last N frames of damage (alacritty keeps 2). | internal | should | alacritty (damage.rs), windows-terminal (dirty-rect model) | Correct partial redraw without buffer age; makes UI animation cheap. | RENDERING-10 | Scroll as ring offset in row buffer | Scrolls recorded as coalesced {region, lines} entries; GPU side rotates row handles / ring offset into the row buffer so scrolled rows are never re-uploaded. | internal | should | foot (term_damage_scroll), windows-terminal (row pointer rotation) | Scroll floods are the worst upload case; the idea ports from memmove to index remap. |
| RENDERING-11 | memfd SHM sliding-window scroll | Not adopted. | none | no | foot (shm.c) | Solves a pixman/shm-specific problem; ring-indexed rows replace it. |
| RENDERING-12 | Buffer-age re-apply / pre-apply (shm fallback) | Only if a CPU/shm fallback ships. | tweak.pre-apply-damage | could | foot | Irrelevant on the wgpu path. |

### Open questions

- Dual-source blending availability in wgpu on target Vulkan drivers: confirm fallback quality (RENDERING-20).
- Cell storage buffer plus instancing vs packed vertex instances: needs a benchmark (RENDERING-01, 03).
- Retained texture vs damage history when partial redraw is needed (RENDERING-09).
- Custom shader sandbox limits and Abyss blur protocol shape (RENDERING-28, 39).
- Dmabuf import into wgpu has no verified end-to-end example (RENDERING-38).
- Whether wgpu surfaces on Wayland can request wp_color_manager tags without hal access (RENDERING-42).
