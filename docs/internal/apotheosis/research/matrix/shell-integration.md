## shell-integration

Merged from the per-terminal survey rows. Sources are cited per row in the survey files; the primary ones are the kitty shell-integration docs (https://sw.kovidgoyal.net/kitty/shell-integration/), the iTerm2 escape-code docs (https://iterm2.com/documentation-escape-codes.html), Ghostty `src/termio/shell_integration.zig`, foot `osc.c` / `terminal.h`, Windows Terminal `adaptDispatch.cpp` and `Marks.hpp`, VTE `termpropsregistry.cc`, and Contour `docs/drafts/semantic-blocks.md`.

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| SHELLINTEGRATION-01 | OSC 133 A/B/C/D semantic prompt marks | Shell hooks emit A (prompt start), B (input start), C (output start, optionally with command line) and D (end, with exit status). Marks are stored as row anchors, not recomputed from cells (see -03). Fires command-started and command-finished events. | `OSC 133;A\|B\|C\|D[;status]`; KDL `shell-integration { enabled }`; events `command-started`, `command-finished` | must | kitty, wezterm, ghostty, foot, rio, iterm2, windows-terminal, vte-konsole, warp-wave, topic-escape-registry | Every mature terminal ships it. It is the foundation for navigation, output selection, notifications and rules. |
| SHELLINTEGRATION-02 | Lenient OSC 133 transition rules | State machine tolerates sloppy shells: A discards a prompt that never ran, D with no running record is ignored, a new A or nested shell implicitly closes an open C, N/I/P(k=r)/L handled, PS1 redraw does not force a fresh line. | none (internal); conformance tests | must | topic-scrollback-search (contour, foot), ghostty | Real shell scripts emit duplicate, missing and out-of-order marks. Strict parsing corrupts the block list. Contour's table is the most complete. |
| SHELLINTEGRATION-03 | Block store with per-row block id | One u32 block id per row (stamped once, carried through reflow). A separate store of up to 1000 command records (state, command line, exit code, start/end times, cwd) that outlives the rows. Derived extents (prompt/input/output) computed on demand from the record. | Action `block.*` family; control-socket `blocks.list`, `blocks.get`; setting `blocks.max` | must | topic-scrollback-search (contour), windows-terminal, ghostty, foot, warp-wave | O(1) row to block lookup, survives reflow and scrollback eviction, and backs pickers, folding and agent perception. Preferred over wezterm's per-query zone scan (-12) and ghostty/foot's per-row flags alone. Row flags remain as the cheap marker. |
| SHELLINTEGRATION-04 | Per-cell semantic content (input vs output) | 2-bit per cell (output/input/prompt) set from the current OSC 133 phase, alongside the row flag, so input and output can be separated inside one row. | internal; used by select-output and click-to-move | should | ghostty, wezterm (zones), topic-scrollback-search | Needed for exact output selection and click-to-move on multi-line prompts. Costs 2 bits per cell. Can be deferred behind -03. |
| SHELLINTEGRATION-05 | kitty OSC 133 extensions | Accept A options `redraw=0`, `special_key=1`, `k=s`, `click_events=1\|2`, `cl=`; C options `cmdline=` (shell-quoted) and `cmdline_url=`; P with kind for continuation prompts. Command line is held in memory in the block record only. | `OSC 133` option keys (interface facts) | should | kitty, ghostty, topic-scrollback-search | Ghostty adopted the kitty options, so scripts from both work. `redraw=0` also feeds prompt protection (-10). Command line capture is needed for re-run and rules. |
| SHELLINTEGRATION-06 | Mark dialect compatibility | OSC 633 (VS Code), OSC 1337 SetMark and ConEmu 9;12 all map onto the same mark set. D with non-zero status marks the block as failed. | `OSC 633;A\|B\|C\|D\|E`, `OSC 1337;SetMark`, `OSC 9;12` | should | windows-terminal, iterm2, vte-konsole | Windows Terminal unifies them; costs only parser branches and lets existing VS Code and iTerm scripts work unchanged. |
| SHELLINTEGRATION-07 | Prompt navigation and scrollbar marks | Actions jump to previous/next/first/last prompt with the prompt placed at viewport top. Marks drawn as pips on the glass scrollbar, coloured by category (success, error, running). Exit-status colour in the gutter. | Actions `prompt.prev`, `prompt.next`, `prompt.first`, `prompt.last` (with count); setting `scrollbar.marks`; KDL `shell-integration { prompt-nav }` | must | kitty, wezterm, ghostty, foot, rio, iterm2, windows-terminal, vte-konsole | Primary visible value of shell integration; every mature terminal has prompt jumping. Pips and exit colours come from Windows Terminal and iTerm2. |
| SHELLINTEGRATION-08 | Output and command actions | Select, copy, pipe or open in a pager the output of the last or Nth command; select the command line; fold output; sticky header of the current command. | Actions `block.select-output`, `block.select-command`, `block.copy-output`, `block.pipe-output <cmd>`, `block.show-in-pager`, `block.fold` | must | kitty, wezterm, foot, iterm2, windows-terminal, vte-konsole, topic-scrollback-search | Selecting and piping output is everyday use and cheap once -03 exists. Folding and sticky header (Contour) can follow; mark as should within this row if scoped down. |
| SHELLINTEGRATION-09 | Command-finished event and notifications | `command-finished` event carries exit status, duration, cwd and command line. Rules can notify, flash the tab, or play a sound when a command longer than a threshold ends in an unfocused tab. | Rule trigger `command-finished` with conditions `exit`, `duration`, `focused`; setting `notify.min-duration` | must | kitty, ghostty, topic-scrollback-search (contour), topic-escape-registry | Delivers the user-visible payoff of -01 and is the first rule-engine event for shell state. |
| SHELLINTEGRATION-10 | Prompt protection during reflow | On resize, rows the shell will redraw (the live prompt) are excluded from rewrap or reflowed as blank rows, so the shell's cursor-up count stays valid. Honours `redraw=0`. | internal; setting `reflow.protect-prompt` | must | kitty, ghostty (via topic-scrollback-search) | Prevents garbled prompts after resize. Both implementations arrived at the same fix independently. |
| SHELLINTEGRATION-11 | Click-to-move cursor in prompt | Clicking inside the input zone sends arrow-key (or shell-handled click events when `click_events` negotiated) to move the cursor. Up/Down within multi-line input optional. | KDL `shell-integration { click-to-move }`; Action `prompt.click-move` | should | kitty, ghostty, vte-konsole | Three mature terminals ship it. Needs -04 for correctness on multi-line input. Default on only when the shell declares support. |
| SHELLINTEGRATION-12 | Zone derivation by cell scan | Do not adopt. Walking every physical line and splitting on semantic type changes is O(history) per query. | none | no | wezterm | The block store (-03) answers the same queries in O(1). |
| SHELLINTEGRATION-13 | OSC 7 current working directory | Parse `file://host/path`, percent-decode, accept only empty or local host (spoofing guard). Also ConEmu `OSC 9;9`. Feeds new-tab-here, split-here, spawn in same directory, and `-D`/`--working-directory` accepting file URIs. | `OSC 7`, `OSC 9;9`; Actions `tab.new --cwd=inherit`, `split.* --cwd=inherit`; CLI `--working-directory` | must | foot, rio, kitty, iterm2, vte-konsole, topic-escape-registry | Expected behaviour everywhere. Host check from rio and VTE is the safer rule. |
| SHELLINTEGRATION-14 | iTerm2 OSC 1337 cwd/host/version | Accept `CurrentDir=`, `RemoteHost=user@host`, `ShellIntegrationVersion`; `SetMark` handled by -06. Remote host shown as tab context. | `OSC 1337;CurrentDir=`, `RemoteHost=`, `ShellIntegrationVersion=` | should | iterm2, wezterm, windows-terminal | iTerm's scripts remain in wide use. Parser-only cost. |
| SHELLINTEGRATION-15 | OSC 8 hyperlinks | Hyperlink id/URI stored per cell in an extras table (not in the base cell). Explicit hyperlinks take precedence over regex matches; unique visible links enumerable for hint mode. | `OSC 8`; Action `hints.open --kind=hyperlink`; setting `links.explicit-precedence` | must | alacritty, foot, kitty, wezterm, ghostty, vte-konsole | Baseline feature of every modern terminal. Precedence rule from Alacritty is sound. |
| SHELLINTEGRATION-16 | OSC 1337 SetUserVar | Base64-decoded named variables stored per pane. Each change fires `user-var-changed`, and values are match fields (`var:x`), template inputs and queryable. | `OSC 1337;SetUserVar=name=base64`; rule trigger `user-var`; condition `user_var`; CLI `ec-term get-user-vars` | must | wezterm, rio, topic-config-automation (kitty match fields) | Primary no-scripting channel for editors and shells to signal the terminal; drives editor-aware bindings and status content. |
| SHELLINTEGRATION-17 | OSC 9;4 progress | Progress state (none, normal, error, indeterminate, paused) stored per pane, drawn as a bar on the glass tab with a timeout (rio uses 15 s) so a crashed program cannot leave it stuck. Also feeds Abyss taskbar progress. | `OSC 9;4;state;value`; setting `progress.timeout` | should | rio, windows-terminal, ghostty (unverified) | Cheap and a good fit for glass tabs. Timeout is the key safety detail. Only rio confirmed in rows. |
| SHELLINTEGRATION-18 | Termprops typed property registry (OSC 666) | Registry of typed properties with well-known names, an app namespace, type checks and a blocklist against spoofing; changes batched into events. Could unify -13/-14/-16/-17 internally. | `OSC 666`; rules on termprop events; CLI query | could | vte-konsole | Clean design but only VTE ships it and few programs emit it. Revisit once -16 exists, and consider using the typed-registry shape internally. |
| SHELLINTEGRATION-19 | OSC 3008 context signalling | `start=ID;type=...;cwd=...;hostname=...` and `end=ID;exit=...` mark shells, containers, ssh sessions. Used for tab badges and spawning panes in the same container. | `OSC 3008`; setting `tabs.show-context` | could | vte-konsole, topic-escape-registry | Useful for the ssh and container story; spec details unverified, and only VTE/Konsole ship it. |
| SHELLINTEGRATION-20 | Shell integration injection without rc edits | Detect shell by basename. zsh: temporary `ZDOTDIR` shim that restores the user's value. fish/elvish/nushell: prepend bundled dir to `XDG_DATA_DIRS` and strip it later. bash: `--posix` plus `ENV` loader that restores rcfile/profile/HISTFILE. PowerShell: encoded command. Feature list passed in one env var and unset by the script. Skipped for explicit `-e` commands. Scripts written once per version to cache. | KDL `shell-integration { mode "detect\|none\|bash\|zsh\|fish" ; features { cursor; title; cwd; prompt-mark; sudo; ssh-env; ssh-terminfo } }`; settings GUI per-feature toggles | must | kitty, ghostty, rio, iterm2 | Zero-touch install with per-feature opt-out maps directly onto the settings GUI. Kitty and Ghostty share the technique; Ghostty's bash handling is more complete than rio's. |
| SHELLINTEGRATION-21 | Terminfo on remote hosts | `ssh-env` fallback: downgrade `TERM` to `xterm-256color` and forward `COLORTERM`/`TERM_PROGRAM`. `ssh-terminfo`: push compiled terminfo (and text source) to the remote `~/.terminfo`, compile with `tic` if present, with a local cache of hosts already done. Opt-in per host with a consent prompt. | features `ssh-env`, `ssh-terminfo`; CLI `ec-term ssh-cache list\|clear`; rule action `ssh.install-terminfo` | must | kitty, ghostty | A custom TERM breaks colours and keys on hosts that lack the entry. Combine kitty's push with Ghostty's ssh-env fallback and cache. |
| SHELLINTEGRATION-22 | Shell integration over ssh and subshells | Remote bootstrap extracts integration scripts to a temp dir, sets env, execs the login shell and cleans up on exit. Also an opt-in snippet and OSC 133 detection for nested shells. Must be transparent and opt-in. | profile `shell-integration auto\|manual`; Action `ssh.install-integration` | should | kitty, iterm2, warp-wave (details unverified; docs 404) | Needed so marks and cwd survive ssh. Three terminals offer some form, but the mechanism is intrusive; consent-gated. |
| SHELLINTEGRATION-23 | sudo terminfo wrapper | Shell function/alias that preserves the terminfo location through `sudo`/`run0`. | feature `sudo` | should | kitty, ghostty | Two terminals ship it; trivial once -20 exists. |
| SHELLINTEGRATION-24 | clone-in-terminal and edit-in-terminal | Shell functions ask the terminal over the control socket to open a window cloning env/cwd/venv, or to edit a remote file locally. | CLI `ec-term clone`, `ec-term edit`; Abyss consent prompt | could | kitty | Good UX, kitty only. Build on the control socket, gated by consent on Abyss. |
| SHELLINTEGRATION-25 | Trigger-based integration fallback | Rules with prompt regexes stand in for scripts on hosts where nothing can be installed: report user/host, report directory, prompt detected. | rule actions `report-dir`, `report-host`, `prompt-detected` | could | iterm2 | Falls out of the rule engine at no extra mechanism. Regex-based and fragile, so low priority. |
| SHELLINTEGRATION-26 | Captured output panel | A rule action collects lines matching a regex into a panel tied to the command; click scrolls to and flashes the line. | rule action `capture-output`; `OSC 1337;ClearCapturedOutput` | could | iterm2 | Useful for compiler errors. Single source. |
| SHELLINTEGRATION-27 | Command history from blocks | Per-session (and optionally per-host) history picker built from the block store. | SHELLINTEGRATION-28 | Shell-driven completions and quick fix | Shell sends a JSON completion list (OSC 633 Completions) or an unresolved-command report (OSC 9001 CmdNotFound); terminal shows a glass suggestion popup. | `OSC 633;Completions`, `OSC 9001` | could | windows-terminal | Windows-only ecosystem for now. ## Open questions

- Do we register our own OSC for program-declared state (resurrection command, -29), or ride on user vars (-16) or termprops (-18)? Rows give no answer.
- Is OSC 9;4 (-17) also emitted by Ghostty? The row names only rio and Windows Terminal; unverified.
- Warp's "Warpify" mechanism (-22) could not be verified (docs 404); the ssh push design relies on kitty's bootstrap only.
- OSC 3008 (-19) spec status and exact field set are unverified against systemd.io.
- Is the per-cell semantic bit (-04) worth its memory cost, or can the block store plus row flags give exact input/output selection? Needs a prototype.
- How is consent for ssh terminfo push and clone/edit (-21, -22, -24) presented on non-Abyss compositors, where there is no compositor prompt?
- Should command-line capture (`cmdline=`, -05) be kept only for the live session, given the "no human input logged by content" invariant? Draft stance: in memory, never written to disk or logs.
