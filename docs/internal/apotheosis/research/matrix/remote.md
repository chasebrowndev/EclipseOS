## remote

| ID | Feature | Mechanism we adopt | Control surface | Adopt | Seen in | Rationale |
|---|---|---|---|---|---|---|
| REMOTE-01 | Selector expression language and window addressing | One boolean selector grammar (field:regex terms joined by and/or/not) over window and tab fields (id, title, pid, cwd, cmdline, env, var, state, neighbor, session, recent); negative ids count from newest; plus simple name/id/last/0 addressing for windows. Same parser used everywhere a target is needed. | `--match`, `--window`, socket `match` field, rule conditions, palette | must | kitty, windows-terminal | Reusable selector for CLI, socket, rules and palette. kitty's grammar is the richer base; wt's name/id/last forms become sugar over it. Sources: https://sw.kovidgoyal.net/kitty/remote-control/ ; wt Process Model 2.0 spec. |
| REMOTE-02 | Control socket gating by capability tiers | Unix socket mode 0600, peer credentials (SO_PEERCRED) identify the client. Per-client capability tiers (read, send-text, spawn, config, system) plus command-level allow-lists (globs) and per-pane child grants; prompt on first use of an ungranted tier via a glass dialog. No shared passwords. | `control.allow` in KDL, settings GUI, socket handshake | must | kitty | Adopts kitty's command-glob allow-lists and prompt-on-first-use, but replaces passwords with peer credentials and capabilities (matches EclipseOS no-ambient-authority). Remote-over-ssh use is by forwarding the socket, not by encryption options. |
| REMOTE-03 | Control command set coverage | Every command is a JSON schema with args and a match target. Coverage list: ls (window/tab/pane tree with cwd, pid, cmdline, env), get-text, send-text, send-key, launch, set-colors, screenshot, action (run any Action). | `apo msg <cmd>` CLI, JSON socket methods | must | kitty | kitty's remote-control list is the reference coverage; `action` ties it to the shared Action vocabulary so nothing needs a scripting language. https://sw.kovidgoyal.net/kitty/remote-control/ |
| REMOTE-04 | Control event stream with flow control and subscriptions | Line-framed JSON replies and async notifications on the socket. Per-pane output subscription, format/state subscriptions, pause-after-age with low/high watermarks so a slow client cannot stall the pane. Model: tmux control mode (%begin/%end/%error blocks, %output, pause-after, refresh-client -A/-B; watermarks 512/8192 bytes). | socket `subscribe`/`pause`/`resume`, CLI `apo events` | should | tmux-zellij | Enables third-party GUIs and tools (iTerm2 uses tmux -C this way). Source: tmux control.c (control_check_age, control_write_output, CONTROL_BUFFER_LOW/HIGH), cmd-refresh-client.c. |
| REMOTE-05 | Versioned IPC with capability announcements | Every IPC (control socket, client spawn, any mux/frame stream) opens with a protocol version and a capability set (graphics, sixel, compression, structured frames); older oldest-supported version is declared. Never assume peer capabilities. | internal; version in `apo --version` and socket hello | must | tmux-zellij | Mixed client/server versions across a persistent server are guaranteed. Source: tmux tmux-protocol.h (PROTOCOL_VERSION, MSG_VERSION), client.c identify messages; zellij client_to_server.proto. |
| REMOTE-06 | Client spawn protocol with exit-code passthrough | Thin client talks to the server over a unix socket with one packed message (flags, cwd, activation token, config overrides, argv, env); server replies with the child's exit status; SIGUSR1/2 forwarded as IPC frames. Keep -N (no detach), -E env, -o override, -D cwd, -s, --hold semantics so it works as a drop-in terminal in scripts. | `apo` / client CLI flags | must | foot | Users script footclient as a terminal replacement; exit code and flag semantics must survive. Source: foot client-protocol.h, client.c, server.c. |
| REMOTE-07 | Attach to an existing pty | Run the UI against a caller-supplied pty fd instead of spawning a child (VM and serial consoles). Cheap if the pty layer is an abstraction. | `--pty <path>` | could | foot | Niche but real foot capability. Source: foot doc/foot.1.scd. |
| REMOTE-08 | System ssh as transport with private ControlMaster | Spawn the system ssh binary (no C library in our build) with ControlMaster=auto, a pid-keyed ControlPath using %C, ControlPersist=yes, ServerAliveInterval=60, ServerAliveCountMax=5, TCPKeepAlive=no; tear down on exit. Connection sharing makes new tabs fast. | connection KDL (`connection "host"`), palette: connect | must | kitty | Satisfies the no-C rule and inherits ssh_config, agents, ProxyJump, FIDO keys. Source: kitty kittens/ssh/main.go#connection_sharing_args. |
| REMOTE-09 | Short control-socket path workaround | If the runtime dir path exceeds about 35 chars, symlink a short per-uid dir under /tmp so ssh's ControlPath (hash plus temp suffix) stays under ~104 chars. | internal | should | kitty | Avoids obscure ControlPath failures on long XDG_RUNTIME_DIR. Source: kitty kittens/ssh/main.go#connection_sharing_args. |
| REMOTE-10 | Stale ControlMaster probe | Ask the master to forward to a closed port: costs a server round trip, runs nothing remote, 5 s timeout; on failure create a new master. | internal | should | kitty | Detects dead shared connections without hanging a new tab. Source: kitty kittens/ssh/main.go#master_responds. |
| REMOTE-11 | Native askpass via SSH_ASKPASS | Set SSH_ASKPASS (and force-use) to a helper that routes password, passphrase and host-key confirmation prompts to a glass dialog (with fingerprint display) instead of the tty. | connection KDL `askpass=glass\|tty` | must | kitty | Avoids tty interference and gives a proper host-key UI. Source: kitty kittens/ssh/main.py (askpass option), askpass.go. |
| REMOTE-12 | Terminfo and shell-integration shipping on ssh | Optional wrapper copies terminfo and integration scripts to the remote and reuses the master connection; per-host config. | connection KDL `integration=...` | could | kitty | Terminfo is better solved by a widely installable terminfo; revisit later. https://sw.kovidgoyal.net/kitty/shell-integration/ (partially read, unverified detail). |
| REMOTE-13 | Remote helper install with consent | On connect, offer to install a small helper under the user's home, add it to PATH for that session only, inject env vars; fall back with an indicator on failure. Source: https://docs.waveterm.dev/connections. kitty's download-on-demand variant is rejected (REMOTE-27). |
| REMOTE-14 | Mux over ssh stdio / proxy_command | Remote persistent sessions: ssh (REMOTE-08) runs a remote proxy command that bridges the mux PDU stream on stdin/stdout; no extra listener, no new crypto. Version negotiation per REMOTE-05. | domain KDL `proxy-command`, `remote-path` | should | wezterm | One hook covers WSL, jump hosts and containers. Depends on a compatible remote binary so version negotiation matters. Source: wezterm docs/multiplexing.md; config/src/ssh.rs (override_proxy_command, remote_wezterm_path). |
| REMOTE-15 | ssh_config host import for connections | Parse ~/.ssh/config (and /etc/ssh/ssh_config) to auto-create plain and multiplexed domains per Host; hide wildcard hosts but apply them; document no Match support and agent detection order; rows overridable in KDL and listed in the palette. | palette: connect, `connections { import-ssh-config }` | should | wezterm, warp-wave | Two terminals ship it. ## Open questions

- Predictive local echo (REMOTE-16): should it ship in v1, and what reliable password-prompt guard exists (termios echo state is not visible over ssh)?
- Mux remote binary (REMOTE-14): does Apotheosis ship a headless server binary distinct from the GUI, and how is it installed remotely without the download path rejected in REMOTE-27?
- Terminfo (REMOTE-12): which terminfo name and distribution plan removes the need for ssh-time shipping?
- Frame protocol (REMOTE-18): is a separate server/client split in scope for v1, or does it start as an internal boundary only?
- Mode 2048 path (REMOTE-24): contour vt-extensions location was unverified.
- Capability tier boundaries (REMOTE-02): exact commands per tier, and how forwarded sockets over ssh are authorised.
