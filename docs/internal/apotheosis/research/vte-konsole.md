# Prior art: VTE (GNOME) and Konsole (KDE)

Researched 2026-11-12. Source read at shallow clones of VTE 0.85.0 (gitlab.gnome.org/GNOME/vte, HEAD of 2026-11-12) and Konsole (invent.kde.org/utilities/konsole, HEAD of 2026-11-13) under `/home/risk/.cache/apotheosis-prior-art/`. Nothing was built or run. Per the prior-art rule this dossier describes techniques in prose; escape sequences, OSC numbers and config key names are quoted as interface facts. Licences: VTE is LGPL-3.0+ (library), Konsole is GPL-2.0+; neither may be linked or copied into Apotheosis, which is another reason to stay at the level of technique.

## Summary

- **Accessibility is the key finding, and the prior art is thin.** VTE has the only serious terminal a11y implementation: a snapshot-and-diff text model exposed through GTK's `GtkAccessibleText` (GTK 4.14+, extents/offset from 4.16), previously ATK in GTK3. Konsole exposes a Qt `QAccessibleTextInterface` that is mostly stubbed (attributes return empty with a FIXME, offset-at-point returns 0, character count is lines x columns). Neither exposes semantic structure (prompts, command blocks, hyperlinks, tabs/splits as a tree), neither speaks to the screen reader directly, and neither handles scrollback. Apotheosis draws its own interface with wgpu, so it has no toolkit giving it a11y for free: it must implement AT-SPI itself (D-Bus, via an `atspi`/`zbus`-style Rust crate; crate choice is for the spec to verify) and has a chance to go well beyond both.
- **VTE is the technical reference for terminal correctness**: bidi per the Terminal-wg draft (implicit and explicit modes, arrow swapping, RTL cursor), OSC 8 with GC'd hyperlink table, an encrypted and LZ4-compressed on-disk scrollback, "termprops" (OSC 666) as a structured app-to-terminal property channel, sixel, kitty-style SGR extensions, and reflow with a written design doc. It is a widget, not an app: no tabs, splits, profiles, or IPC.
- **Konsole is the reference for the application layer**: profiles (`.profile` files, many properties), nested split views with drag/drop, JSON view layouts, rich D-Bus API, copy-input-to-sessions, monitor activity/silence/prompt, escape-sequence URL extraction, OSC 133 semantic hints with up/down-arrow and click-to-move-cursor, kitty keyboard protocol, badges, history to file, filters (regex, URL, file path, colour).
- **Lessons for Apotheosis**: build a11y as a first-class model (visible-grid text plus a semantic layer), borrow VTE's bidi design and termprop idea, borrow Konsole's profile/split/layout/D-Bus surface but replace D-Bus-only control with the shared Action vocabulary, and avoid both projects' CPU-painted, toolkit-bound renderers.

## Architecture (how it is built)

### VTE
- C++ library over GTK (3 and 4 builds from one tree; `vteaccess.cc` is ATK for GTK3, `vteaccess-gtk4.cc` is `GtkAccessibleText`; `drawing-cairo.cc`/`drawing-gsk.cc` are the two back-ends; `fonts-pangocairo.cc` for text). Public API is `VteTerminal` plus `VtePty`; an app (GNOME Terminal, Console/Ptyxis, Terminator) supplies tabs, splits, profiles.
- Data path: PTY fd source -> `Chunk` queue (chunks of about 8 KiB, `k_chunk_size = 0x2000 - 2*sizeof(void*)`, with 1 byte overlap so a UTF-8 sequence cut across a chunk boundary is decodable) -> parser (state machine in `parser.cc`; sequences described in `parser-seq.py`, OSC numbers in `parser-osc.hh`, DEC/xterm modes generated from `modes.py`) -> `Terminal::process_incoming()` with sub-decoders for UTF-8, PC-term, and DEC sixel -> screen. Input reads are capped per iteration (`VTE_MAX_INPUT_READ` 0x1000 bytes) and processing per tick (`VTE_MAX_PROCESS_TIME` 100 ms, a bound, not a budget), so output floods yield to the main loop.
- Screen model: a `Ring` of `VteRowData` rows; each cell is 20 bytes (`VteCell`: 4-byte vteunistr for base char plus combining chain, 16-byte `VteCellAttr` packing fg/bg/deco colours, bold/italic/underline style/strike/blink/reverse, hyperlink index of 20 bits, shell-integration mode, width). A per-row 1-byte `VteRowAttr` holds soft-wrap and bidi flags. Sources: `cell.hh` (size asserts: VteCellAttr 16, VteCell 20, VteStreamCellAttr 14), `vterowdata.hh`.
- Scrollback: the ring has a writable in-memory part and a "stream" part. Rows scrolled out far enough are serialised (text stream, attribute stream, row stream) to an unlinked temporary file through a layer called VteBoa that LZ4-compresses blocks and encrypts them with AES-256-GCM via GnuTLS (`vtestream-file.h`, `ring.cc`). Block overwrite counters give unique IVs. Result: unlimited scrollback at low RSS, and the secrets-at-rest argument (an unlinked, encrypted file).
- Rewrapping on resize is designed in `doc/rewrap.txt`: remember per row whether it ended by hard newline or by soft wrap, treat a run of soft-wrapped rows plus its final hard row as a "paragraph", and on resize re-flow paragraphs while tracking the cursor and selection; the doc enumerates the awkward cases (cursor movement making wrap state ambiguous, alternate screen not reflowed, etc.).
- Bidi (`bidi.cc`, `ringview.cc`, `bidi.hh`): a `RingView` is a window over the visible rows (plus context rows) giving per-row access to cells; `BidiRunner` runs the algorithm per paragraph (capped at `VTE_RINGVIEW_PARAGRAPH_LENGTH_MAX` 500 rows) and stores a `BidiRow` per visual row (logical-to-visual and visual-to-logical maps, per-cell RTL flag for mirroring/selection, shaped base chars, per-line paragraph direction and a "contains foreign-direction char" flag used for the cursor). Fully LTR rows are stored as width 0 (trivial map) as a fast path. FriBiDi supplies classification, embedding levels (`fribidi_get_par_embedding_levels_ex`), line reorder, mirroring; Arabic shaping currently uses presentation forms (`fribidi_shape_arabic`) with a code comment that HarfBuzz would be better. Ringview can be "paused" (frees nearly all memory) when the widget is unmapped.
- Hyperlinks (OSC 8): the `Ring` owns a table of "id;uri" strings; cells hold a 20-bit index. A bitmap-based garbage collector periodically scans visible and scrolled rows and purges unreferenced entries. Limits: URI 2083 bytes, id 250 bytes, up to about 1M distinct links. Auto-generated ids start with `:` so they cannot collide with explicit ids. Sources: `vteseq.cc#Terminal::set_current_hyperlink`, `ring.cc#Ring::hyperlink_gc`, `vtedefines.hh`.
- Termprops (OSC 666, `termpropsregistry.cc`): a typed property registry (types: valueless, bool, integers, floats, string, URI, UUID, colour, image ...) that terminal-side code and apps can query and observe. Well-known names: `vte.cwd`, `vte.cwf` (current working file), `xterm.title`, `vte.container.{name,runtime,uid}`, `vte.shell.{precmd,preexec,postexec}`, `vte.progress.{hint,value}`, `vte.icon.{color,image}`; app-defined ones must live under `vte.ext.`; a blocklist and type checks stop spoofing of well-known names. Legacy OSC 777 (`precmd`, `preexec`, `notify;Command completed`, `container;push/pop`) is accepted only if `enable_legacy_osc777` is set and maps onto termprops. OSC 9;4 (ConEmu progress) maps to progress termprops.
- Shell integration: OSC 133 (iTerm2/FinalTerm style) A/B/C are tracked as a per-cell attribute (prompt/command/normal), D is ignored, L inserts line breaks so the prompt starts on a fresh paragraph. Used for selection and for prompt-aware rewrap behaviour; exit codes are not surfaced.
- Rendering: Cairo or GSK nodes per frame; "minifont" renders box-drawing/blocks procedurally (`minifont.cc`, `box-drawing.hh`) so lines join without font gaps. Since GNOME 46 VTE paints each frame on the frame clock instead of a 40 Hz repaint timer (per the bxt.rs measurement post; the commit itself I did not locate in the shallow tree: unverified).
- Search: PCRE2 regex (`VteRegex`), `search_find_next/previous`, wrap-around; match-and-hover regexes (`vte_terminal_match_add_regex`) drive link detection with a cursor name per match.
- Other protocol coverage in `modes.py`: DECSET 2004 bracketed paste, 1006 SGR mouse, 1016 SGR-pixels, 1070 sixel private palette, 2026 batched rendering (listed; check status in source before relying), 2016/2017 kitty-style underline and extended keyboard entries (listed in the mode table), 2027 Unicode core, BDSM (SM 8), and the VTE-specific 1243/2500/2501 for bidi.

### Konsole
- C++/Qt (Qt 6 + KDE Frameworks; GPL). Layers: `Pty` (`ptyqt`, KPty) -> `Session` (one process, one emulation, D-Bus object `org.kde.konsole.Session`) -> `Vt102Emulation` (~4500 lines, big hand-written OSC/CSI switch) -> `Screen` (cell image + history) -> `ScreenWindow` (viewport) -> `TerminalDisplay` (QWidget, QPainter via `TerminalPainter`, CPU rendering) with `TerminalFonts`, `TerminalColor`, `TerminalScrollBar`, `TerminalBell`.
- App layer: `MainWindow` (KXmlGui menus/actions, shortcut editor), `ViewManager` (D-Bus `org.kde.konsole.Window`), `ViewSplitter` (a `QSplitter` tree whose leaves are terminal displays, with `TerminalHeaderBar` per pane and a `DetachableTabBar`), `SessionController` (per-view actions, search bar, filters), `ProfileManager`.
- Profiles: `*.profile` files in KConfig INI format, found through the XDG data path (`konsole/`). `Profile` is a property bag with about 110 keys (Path, Name, Command, Directory, Environment, Font, ColorScheme, HistoryMode, HistorySize, ScrollBarPosition, ReflowLines, BlinkingTextEnabled, BidiRenderingEnabled, BidiLineLTR, BidiTableDirOverride, KittyKeyboardEnabled, SemanticHints, SemanticUpDown, SemanticInputClick, UrlHintsModifiers, AllowEscapedLinks, EscapedLinksSchema, MouseWheelZoomEnabled, AllowMouseTracking, AlternateScrolling, Badge* , ErrorBars, AlternatingBars, LineNumbers, TabColor, DimWhenInactive, BorderWhenActive, FocusBorderColor, ...) plus parent/child inheritance (`ProfileGroup` for multi-selection editing) and a per-session "shouldApplyProperty" mechanism so UI tweaks made at runtime are not clobbered by profile reapplication.
- Views: arbitrary nested horizontal/vertical splits, drag-and-drop panes and tabs, detach to new window, saved/loaded as JSON layout files (`Orientation`, `Widgets[]`, leaves keyed by `SessionRestoreId`); built-ins 2x2, 2x1, 1x2 ship in `data/layouts/`. D-Bus offers `viewHierarchy`, `createSplit`, `createSplitWithExisting`, `moveView`, `moveSplitter`, `resizeSplits`, `getSplitProportions`, `setCurrentView`, `saveLayoutFile`, `loadLayout`.
- History: `HistoryTypeNone`, bounded in-memory "compact" scroll, `HistoryTypeFile` (unbounded, on a temp file). No encryption.
- Filters: a `FilterChain` over the displayed image of `RegExpFilter` (URL, e-mail), `FileFilter` (existing file paths with `path:line:col` forms, checked against the session cwd), `ColorFilter` (colour literals), `EscapeSequenceUrlFilter`; hotspots carry actions and tooltips; `EscapeSequenceUrlExtractor` records OSC 8 spans out of band.
- Bidi: optional (`BidiRenderingEnabled`), per displayed line only, using ICU `ubidi_setPara` with a default-LTR or forced-LTR paragraph level and an optional class callback to override table drawing direction; no explicit mode, no paragraph spanning wrapped rows, no arrow swapping. Source: `TerminalDisplay.cpp#bidiMap`.
- Notifications: OSC 777 `notify;title;body` is turned into a KNotification (two event classes, focused and hidden) with a default "Show session" action carrying an XDG activation token; the raw params are also emitted as a Qt signal `osc777Received` for plugins. Source: `Vt102Emulation.cpp` (Notification handling).
- Semantic prompts: OSC 133 A/N/P prompt, B input, C output, D with exit code, L; sets a per-row "REPL mode" (None/Prompt/Input/Output). Profile flags let Up/Down arrows move within the input region and clicks move the cursor in the prompt. Not surfaced to a11y.

**remote / packaging**: neither has remote control beyond D-Bus (Konsole) / PTY pass-through; Konsole is a KDE KPart (`Part.cpp`) embeddable in Dolphin/Kate; VTE is embedded by dozens of apps. Packaging is distro-library style; VTE ships a `perf/` directory of test scripts (bidi demo, hyperlink demo, 256-colour, sgr, utf8 tests).

### Accessibility in depth

**VTE GTK4 (`vteaccess-gtk4.cc`, about 1170 lines)**
- Widget role `GTK_ACCESSIBLE_ROLE_TERMINAL`. Initial properties: label "Terminal", multi-line true, has-popup true, description = window title (updated on `window-title-changed`).
- Text model is a **snapshot of the visible rows only** (`get_text_displayed_a11y` uses `scroll_delta` .. `scroll_delta + row_count`, not scrollback). A snapshot holds: the UTF-8 string; per-character byte offsets; a per-cell `VteCharAttributes` list (row, column, colours, underline, strikethrough); line-break offsets (the first character index of each visual row); caret index. Two snapshots (`contents[2]` plus a flip bit) are kept so the "removed" text of an update is still readable by the AT while the "inserted" text is announced.
- **Change notification by prefix/suffix diff**: on `contents-changed` it takes a new snapshot, finds the longest common prefix and suffix against the previous one, and emits one `GTK_ACCESSIBLE_TEXT_CONTENT_CHANGE_REMOVE` for the old middle and one `..._INSERT` for the new middle, then updates the caret if the index changed. Scrolling is handled separately (`_vte_accessible_text_scrolled`; a flag suppresses the diff for the contents-changed that scrolling also triggers). Cursor moves are de-duplicated against a cached (column, row). Selection changes update caret and selection bound.
- Interface methods: `get_contents`, `get_contents_at` (granularity char/word/sentence/line/paragraph, line granularity uses the line-break table), `get_caret_position`, `get_selection`, `get_attributes` (names `underline`, `strikethrough`, `fg-color`, `bg-color`; one range per run of equal attributes), `get_extents` (cell-based rect union; multi-row extents widen to the full line), `get_offset` (point to index via cell size and border). Gated on GTK 4.16 (`#endif // gtk 4.16`).
- A property `enable-a11y` (default true) lets embedders switch all of it off; every handler early-returns when off, which is the escape hatch for the cost of snapshotting every contents-changed.
- Costs and gaps: a full re-snapshot of the screen per update (O(rows x cols)), no throttling visible in the a11y code (the terminal's own repaint timing is the throttle), no scrollback, no semantic roles for prompt/output/links, no live-region polite/assertive distinction, no announcement of wide-char/bidi order (the AT receives logical text, which is right for bidi), blink/inverse colours reported as raw attributes only.

**VTE GTK3 (`vteaccess.cc`, ATK)**: same snapshot idea but implements the old ATK text boundary types (`ATK_TEXT_BOUNDARY_CHAR`, `WORD_START/END`, `LINE_START/END`, `SENTENCE_START/END`) by hand; role `ATK_ROLE_TERMINAL`; states VISIBLE, SHOWING, FOCUSABLE, RESIZABLE.

**Konsole (`widgets/TerminalDisplayAccessible.cpp`, 196 lines)**: `QAccessible::Terminal` role; Value text is the whole visible screen; character count is `lines * columns` (blank cells count; offsets are cell-based, not text-based, which breaks multi-byte, wide and combining characters); one selection supported; `attributes()` is a stub with a FIXME about ARIA-like CSS attributes; `offsetAtPoint` is a stub; `characterRect` is cell arithmetic. Events (`TerminalDisplay.cpp` after painting): `VisibleDataChanged`, a text-cursor event, and a text-update event covering the dirty index range with the new text and an empty old string (no true diff, so insertions and replacements are both reported as "insert new text at 0 of range"); cursor event also after a key press when not read-only. Unit test `autotests/TerminalDisplayAccessibleTest.cpp` exists.

**Takeaways**: (1) the visible-grid text model with caret, selection, extents and per-run attributes is the proven minimum; (2) event quality matters more than the interface: VTE's diff gives screen readers sane "what was typed/erased" speech, Konsole's does not; (3) nobody models structure. Orca's behaviour with terminals (flat review, speech on insertion) was not checked against Orca source: unverified.

## Control surface (config, actions, IPC)

- **VTE**: no config files; GObject properties (cursor shape/blink, text-blink-mode never/focused/unfocused, font scale, cell scale, scrollback lines (-1 unlimited), `enable-bidi`, `enable-shaping`, `enable-sixel`, `enable-a11y`, `enable-legacy-osc777`, `allow-hyperlink`, word-char exceptions, audible bell, bold-is-bright, ambiguous width, 47 `vte_terminal_set_*` setters), signals, and the API `feed`, `feed_child`, `get_text_*`, `match_*`, `search_*`, `copy/paste_clipboard`, `spawn_async`. Terminal-to-app: DECRQM, XTVERSION-style queries, OSC 666 termprop queries.
- **Konsole**: GUI with a profile dialog per page (General, Tabs, Appearance, Scrolling, Keyboard, Mouse, Advanced), `konsolerc` and `*.profile` INI, `.keytab`, `.colorscheme`, `.json` layouts; actions are KXmlGui `QAction`s bound to shortcuts, with a shortcut editor; D-Bus on the session bus (`org.kde.konsole.Session`, `.Window`, `.Application`, one object per session/window), CLI flags. D-Bus lacks structure for tree-wide queries beyond `viewHierarchy` returning strings and lacks event subscription for outputs.
- Neither has a rules engine; Konsole's profile switching on process name or "tab title format" tokens is the closest thing (title format `%n`, `%d`, `%w`, `%u`, `%h`, `%D`, `%#`; format token list not exhaustively verified).

## Performance (numbers + method)

No first-party numbers from VTE or Konsole. Third-party, with method:
- Hardware tester (light sensor on a Teensy, 120 repetitions, 144 Hz, Mutter 46.0, Mesa 24.0.4, 2560x1440) in the bxt.rs post: VTE test app on GNOME 46 is "pretty much on par with Alacritty"; GNOME 46 moved from a 40 Hz repaint timer to per-frame drawing. Exact ms only in plots: unverified. https://bxt.rs/blog/just-how-much-faster-are-the-gnome-46-terminals/
- VTE issue 334 (hardware-ish tester, 100 key presses, 144 Hz, GNOME 40 beta Wayland): VTE about 20 ms worse than non-VTE GTK3 apps and Alacritty; repeat on 60 Hz laptop similar; spread about 7 ms equals one 144 Hz frame. https://gitlab.gnome.org/GNOME/vte/-/issues/334
- 2018 typometer-based comparison (anarc.at): Konsole and Xfce terminal (VTE) about twice rxvt's latency; xterm about five times. Typometer on Wayland has caveats. https://anarc.at/blog/2018-05-04-terminal-emulators-2/
- Source-derived budgets: VTE input chunk about 8 KiB, 4096-byte read cap, 100 ms processing cap; cell 20 bytes; row attr 1 byte; scrollback compressed (LZ4) and encrypted (AES-256-GCM) per block.
- Lesson: the largest latency win in VTE came from pacing (frame clock, not timer), not from parsing speed.

## What Apotheosis should take

1. **AT-SPI as a first-class subsystem** (see rows): a11y tree with terminal role, visible-grid text, caret, selection, extents, attributes; VTE-style old/new snapshot diff generating insert/remove events; an `enable_a11y`-style kill switch plus lazy snapshotting only while an AT is connected (query the a11y bus status property `IsEnabled`; verify in the AT-SPI spec).
2. **Go beyond**: expose scrollback range (paged), semantic child objects (prompt, command, output blocks from OSC 133 with exit code), hyperlinks (AT-SPI Hyperlink/Hypertext interfaces mapping OSC 8 spans), tabs and splits as a proper tree (page-tab list, panes with labels), live-region style announcement controls (polite for output, assertive for bell/notification), and settable per-pane "speak output" behaviour. Mark attributes in ARIA-like CSS names (`fg-color`, `bg-color`, `underline`, `strikethrough`; add `weight`, `font-style`, `invalid` for error spans). All a11y settings editable in the settings GUI and KDL.
3. **Bidi per Terminal-wg**: implicit and explicit modes, BDSM, SCP, 1243 arrow swap, 2500 box mirror, 2501 autodetect; row/paragraph model with trivial-LTR fast path; RTL-aware cursor and selection; shaping through a Rust text shaper rather than presentation forms. Rust pieces to evaluate: `unicode-bidi` (MIT/Apache-2.0, verify) and `rustybuzz`/`harfrust` for shaping (verify licences).
4. **Hyperlinks (OSC 8)**: link table with index per cell and GC; limits (2083 URI, 250 id, generated ids that cannot collide); `id` grouping on hover; only click-with-modifier by default, show URI on hover, scheme allow-list, `file://` host check; surface links to the palette ("open link", "copy link", "list links") and to a11y.
5. **Termprops-like structured channel**: typed, registry-validated app-to-terminal properties with well-known names, reserved extension namespace, and no spoofing of built-ins; map onto the Action/event model so rules can react (`on cwd change`, `on progress`, `on command finished`).
6. **OSC 777 notify** plus **OSC 9;4 progress**, mapped to an event feeding rules and the Abyss notification surface; emit an unfiltered event for rules (Konsole's raw signal idea); legacy 777 `precmd/preexec` only behind a setting.
7. **Konsole layer**: profile property bag with inheritance and runtime-override protection; nested split tree with per-pane header, drag/drop, detach, JSON-like layouts (as KDL layouts); copy-input-to-panes (broadcast) with a visible indicator; monitor activity/silence/prompt/command-finished; tab colour and title format tokens; badge overlay; history save and background search task; filter chain with hotspots (URL, `path:line:col`, regex user rules).
8. **Scrollback**: unlimited, encrypted-at-rest, compressed, unlinked temp file (memfd-like), page-in on demand; Rust crates for LZ4/ChaCha20-Poly1305 (`lz4_flex`, RustCrypto) must be licence-checked.
9. **Reflow design**: paragraph model with hard/soft wrap flags; document the awkward cases and test them.
10. **Procedural box drawing/blocks** drawn in the shader so lines join at any scale (VTE minifont, Konsole `UseFontLineChararacters`).
11. **Frame-clock pacing** for rendering, not a timer; per-iteration read and processing caps.
12. **Semantic OSC 133** full set (A/B/C/D with exit code and options, L), per-row marks, jump-to-prompt, select-output, click-to-move-cursor and Up/Down in input zone behind profile flags, and expose all of it to a11y.
13. **DECRQM-complete mode table generated from one data file** so docs, queries and the control socket stay in sync.

## What it should avoid

- VTE's a11y exposing **only** visible text with a full-screen snapshot per update on the hot path; make snapshotting lazy, incremental (dirty-row ranges, not whole-screen scans) and rate-limited.
- Konsole's cell-index offsets (blank cells counted, wrong for wide, combining and bidi text) and its "insert whole dirty range at offset 0" events; stub methods (`attributes`, `offsetAtPoint`) that make ATs misbehave silently.
- Presentation-form Arabic shaping and per-line-only bidi (Konsole): breaks across soft wraps.
- Bidi mode numbers marked "temporary" in the draft (2500, 2501, 1243): follow the draft but keep them behind a mapping table so renumbering is cheap; SPD handling is undecided in the spec, so do not emit or depend on it.
- Dual toolkit back-ends (VTE's GTK3 ATK and GTK4 paths) and Qt/KDE-framework coupling (KConfig INI, KNotification, KXmlGui): not applicable to our own Wayland client.
- D-Bus-only control (Konsole): our socket is JSON plus the shared Action vocabulary; do not mirror per-object D-Bus methods.
- CPU raster of the grid (Cairo, QPainter); a 40 Hz repaint timer; GNU/GPL/LGPL code or dependencies (GnuTLS, FriBiDi LGPL, ICU is permissive but C++; none allowed by our build rules).
- Unencrypted history-to-disk (Konsole `HistoryTypeFile`) as the default.
- Auto-opening links on plain click, and allowing unprompted OSC 52 reads.
