# This list is a ratchet: entries only ever come out. Adding one needs a
# reason on the line above it, and a milestone that will remove it. A test
# that is not listed here must pass, or the gate goes red.
#
# Measured against the full suite on the headless backend (COMP-16 m9c):
# 786 pass, 307 skipped by wlcs itself, 54 excluded below. (Touch landed:
# the 170-entry touch bloc that used to head this list is gone — 168 of those
# tests pass now, and the 2 that do not are pointer bugs in touch clothing,
# rehomed next to their pointer twins.) Group 16 (input-region leave) is gone
# entirely: all 12 entries pass now that pointer focus is re-evaluated on
# commit; group numbers are otherwise left as they were. Groups 7 (interactive
# move/resize), 8 (set_parent) and 9 (window-geometry hit-test offset) are gone
# too -- see the map-time-configure and grab-reentrancy fixes in
# docs/HANDOFF.md.
#
# The 319 are not one bucket, and only 30 of them are worth chasing. wlcs
# skips a test when the integration does not advertise the extension it
# needs; ours advertises nine globals (`SUPPORTED_EXTENSIONS` in
# `crates/wlcs-abyss/src/lib.rs`). Breakdown:
#
#   244  wl_shell + zxdg_shell_v6        dead protocols; will never pass
#     5  gtk_primary_selection           superseded by zwp_primary_selection
#     4  wlcs SelfTest                   tests wlcs itself, not us
#    30  foreign-toplevel                UNIMPLEMENTED -- real gap
#    24  touch                           wl_shell/zxdg_shell_v6 variants
#
# zwlr_virtual_pointer_v1 used to sit in that list with 12 skipped tests. It
# is implemented now (`protocols/standard/virtual_pointer.rs`), advertised in
# `SUPPORTED_EXTENSIONS`, and all 12 pass.
#
# 120 of the 244 are the numerically-named `*InputCombinations` cases, which
# `Combine(edges, all_surface_types, all_input_types)` in wlcs's
# `tests/surface_input_regions.cpp` flattens to a bare integer -- the name
# gives no hint what a case covers. Decode with `(index / 2) % 6` against
# `SurfaceBuilder::all_surface_types()`; all 120 land on index 0 or 1
# (WlShellSurfaceBuilder, XdgV6SurfaceBuilder). They are not an input-region
# gap, despite what the suite names suggest.
#
# Note foreign-toplevel hands any client the full window list, so it wants a
# policy check rather than a straight implementation (COMP-08/COMP-11), not a
# free 30 tests.
#
# One gtest name per line ("Suite.Test" or "Suite.*"); blank lines and
# lines starting with '#' are ignored.

# 2. text-input-v3 / input-method-v2: smithay request-discard behaviour.
#
# Both globals ARE implemented and advertised (state.rs, and the wlcs
# integration's SUPPORTED_EXTENSIONS). The tests still fail for a reason
# outside our code.
#
# wlcs's fixture uses two clients: app_client holds the zwp_text_input_v3,
# input_client holds the zwp_input_method_v2. Neither the fixture's
# `bind_if_supported` nor `get_input_method` flushes input_client's
# connection, so the compositor does not receive the input-method bind until
# a test calls `input_client.roundtrip()` -- which happens *after* the
# app_client has already sent enable/commit. Verified with WAYLAND_DEBUG=server:
# the bind arrives 17ms after `zwp_text_input_v3#9.commit()`.
#
# smithay 0.7.0 discards every text-input request while no input-method
# instance exists (text_input_handle.rs: "discarding text-input request
# without IME running") and gates `text_input.enter()` on
# `input_method.has_instance()` (seat/keyboard.rs). It never replays the
# pending enable/commit when the IME appears late, so `activate`/`done`
# never fire. Mir, which these tests were written against, replays.
#
# Passing them requires either patching the pinned smithay=0.7.0 or replacing
# its text_input/input_method modules with a hand-rolled implementation
# (archived on branch comp16-ime-v3, commit 4abd048). Neither is in scope here.
#
# Removed by: no milestone assigned yet -- COMP-06 text-input-v3.

# 10. `defaults` wants an unconstrained window.
#
# `defaults` requires the last configure of a freshly mapped toplevel to carry
# width 0, height 0, i.e. "pick your own size". abyss tiles by default
# (`Placement::float` is false in `shell/rules.rs`), so `arrange` computes a
# real rectangle and `shell::configure` sends it. Reporting 0x0 would be a
# lie about a tiled window. Deliberate divergence pending a decision on
# whether an unconstrained-size path is wanted at all.
#
# `window_can_fullscreen_itself` / `window_can_unfullscreen_itself` came out
# here when COMP-05 §4 fullscreen landed.
#
# Removed by: no milestone assigned yet -- the tiling-default decision.
XdgToplevelStableConfigurationTest.defaults

# 11. Zero-size xdg_positioner anchor rectangle.
#
# UPSTREAM BLOCKER, not an abyss bug: the xdg_positioner global is delegated
# wholly to smithay, and smithay 0.7.0's `set_anchor_rect` handler posts
# `xdg_positioner::Error::InvalidInput` for any width or height < 1, while
# xdg-shell only mandates an error for *negative* values. wlcs maps a popup
# with a 0x0 anchor rect, so the client is killed before abyss ever places it.
# abyss's own placement math is correct for this case -- it yields the expected
# (170, 230). Fixing it needs a smithay change (or taking over the positioner
# handler), and the pin is `=0.7.0` (root CLAUDE.md: a bump is its own PR).
#
# Removed by: a smithay bump that relaxes the anchor-rect validation.
XdgPopupTest.zero_size_anchor_rect_stable
